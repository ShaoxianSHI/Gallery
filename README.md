# Gallery

一个基于 Python 的本地相册软件：**照片留在你自己的文件夹里，软件只是它的一个视图。**

Gallery 像 Obsidian 那样工作 —— 你指定一个本地文件夹作为「库」，软件读取它、而不接管它。照片始终是普通文件，用访达、Photoshop 或任何别的工具都能打开；即使卸载 Gallery，你的照片和元数据依然完整可读。第一个版本面向 macOS，核心目标是两件事：

1. **实时查看**：打开文件夹即可浏览，磁盘上的变化立刻反映到界面。
2. **元数据的查看与修改**：读取并写回 EXIF / IPTC / XMP，改动直接落在照片文件上。

---

## 设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | **本地文件夹即数据库** | 没有「导入」这一步。库就是一个普通目录，不存在只有 Gallery 才能打开的私有格式。 |
| 2 | **照片是唯一事实来源** | 元数据写回原文件（经 exiftool），不用 Gallery 也能看到修改结果。 |
| 3 | **缓存可丢，数据不可丢** | `.gallery/` 下除 `config.toml` 外的一切都可以随时删除并重建。 |
| 4 | **默认只读，写入显式** | 浏览、检索、缩放永不写盘；任何改动原文件的操作都必须由用户主动触发，并留可回滚记录。 |
| 5 | **Mac 优先，但不锁死** | v1 只为 macOS 打磨（文件监听、HEIC/RAW 支持、原生观感），核心逻辑保持平台无关，为将来的 Windows / Linux 留出空间。 |
| 6 | **一整块底色** | 标题栏、相册路径条、网格、大图、元数据面板与**弹出的菜单**共用同一块底色，并跟随系统的浅色 / 深色主题；界面里不再有「一层深一层浅」的接缝。标题栏那一行的文字也由 Gallery 自己画（网格页是相册名，大图页是照片文件名），于是它同时就是大图页的改名字段。 |

## 名词约定

| 术语 | 含义 |
|------|------|
| **库 / Library** | 你交给 Gallery 的那个根文件夹。一个库对应一个根目录。 |
| **根目录 / Root** | 库的顶层文件夹路径，所有扫描与监听都从它开始。 |
| **`.gallery/`** | 库内的隐藏配置目录，存放配置、索引与缓存。见下节。 |
| **索引 / Index** | 由扫描生成的照片清单与元数据快照，存放在 `.gallery/index.db`。 |
| **旁车文件 / Sidecar** | 与原图同名、放在旁边的附属文件（如 `IMG_0001.xmp`）。v1 不作为主存储。 |
| **写回 / Write-back** | 把界面上的元数据修改真正写进照片文件的操作。 |

## `.gallery/` 目录约定

配置目录固定为 `.gallery/`（**不是** `.galley/`），位于库根目录下：

```
<库根目录>/
├── 2024-京都/                 # 你自己的照片文件夹，Gallery 不做任何整理
│   ├── IMG_0001.HEIC
│   └── IMG_0002.JPG
└── .gallery/                  # Gallery 的运行时数据
    ├── config.toml            # 库级配置（含**每个相册的封面**是哪一张照片）
    ├── index.db               # SQLite 索引缓存，删除后可重建
    ├── cache/thumbs/          # 缩略图缓存，可随时清空
    └── journal/               # 写操作日志（改名、移到废纸篓、粘贴、移动到相册、新建相册），用于回溯与回滚
```

`config.toml` 里的字段：`recursive`（是否递归扫描子文件夹）、`thumbnail_max_edge`、
`max_cache_bytes`，以及 `[album_covers]` —— **相册封面**，键是相册相对库根的路径、值是封面照片
相对库根的路径（没写的相册用「里面第一张照片」当封面）。这个文件是可以手改的：改坏了不会
损坏照片，删掉它会恢复默认值。

**硬性约定**：除 `config.toml` 外，`.gallery/` 中的任何内容都不得成为唯一数据副本。删掉整个 `.gallery/`，软件必须能通过重新扫描恢复到等价状态。`journal/` 是个例外也要说明白：它记录的是**已经发生在硬盘上**的改动的历史，删掉它只是丢了回溯与 ⌘Z 撤销的能力，照片本身不受影响。

> 首次打开一个还没有 `.gallery/` 的文件夹时，Gallery 会先询问你：在库中创建缓存目录，还是把缓存放到系统目录
> （`~/Library/Application Support/Gallery/`）而让你的照片文件夹保持零写入。两种方式都不会修改原图；
> 会动文件的只有你亲手触发的五件事 —— 重命名（`⌘R`）、移到废纸篓（`⌘⌫`）、粘贴（`⌘V`，
> 把剪贴板里的文件**复制**进当前这一层，源文件原地不动）、右键菜单里的**移动到相册**，
> 以及网格空白处右键的**新建相册**（`⇧⌘N`，建一个空文件夹出来）。
> 移动、删除、改名都能 `⌘Z` 撤销（撤销一次移动是把它挪回原来的相册，不是删除）；粘贴与新建相册
> 只增不改、不覆盖同名，因此不提供撤销（想撤就在访达里删掉，或选中它按 `⌘⌫`）。
> 另外「设为相册封面」会往这个目录里的 `config.toml` 写一行 —— 那是 Gallery 自己的配置文件，
> 你的照片一个字节都不动（上面那五件事仍然一件没少）。

## 安装与运行

需要 macOS，以及两个前置工具：

```bash
brew install uv exiftool
```

然后从源码运行：

```bash
git clone https://github.com/ShaoxianSHI/Gallery.git
cd Gallery
uv sync                       # 创建虚拟环境并装好依赖（含 Python 3.12 本身，无需自行安装）
uv run gallery                # 启动
```

`uv run gallery ~/照片` 可以直接打开指定文件夹；`uv run gallery --version` 打印版本号与所用的 Python 版本。

> exiftool 是运行时依赖，分组 / 排序用的元数据（拍摄时间、相机、地点、关键词）需要它。缺少时 Gallery 会退回 Pillow 读基础 EXIF，而不是报错崩溃。

### 打包成应用

窗口标题栏左侧那一枚图标由 `src/gallery/resources/` 提供，不需要额外操作。

Dock、访达、`⌘Tab` 里显示的图标来自 `.app` 包，所以想让它们也变成 Gallery 的图标，
需要先把 Gallery 打包成一个应用包。有两种，产物都在 `dist/Gallery.app`：

```bash
# 自包含版：解释器、Python 依赖与 Qt 插件全部编译进包里，拷到别的 Mac 上也能直接跑
uv sync --group build
uv run --group build python scripts/build_app.py

# 开发版：一秒生成，不编译；启动器指向本仓库的 .venv
uv run python -m gallery.macos_app
```

自包含版约 110 MiB，编几分钟（首次还要下载编译缓存）。它需要 macOS 13 或更高版本，
没装 exiftool 也不影响启动 —— 缺 exiftool 只是退回只读模式。

```bash
uv run --group build python scripts/build_app.py ~/Applications   # 直接放到「应用程序」
uv run --group build python scripts/build_app.py --dry-run        # 只看将要执行的命令
```

两种包都能双击启动，Dock、访达、窗口标题栏里都是同一枚图标。想换图标，见
`src/gallery/resources/README.md`。

从访达 / Dock 启动的进程默认只看得到系统那几个目录，Homebrew 装的 exiftool 不在其中
（终端里有，因为 shell 会读你的配置文件）。Gallery 因此会在启动时把常见的安装目录补回
`PATH`，从 `.app` 启动时元数据依然是完整的。

> 自包含版是 ad-hoc 签名的，只在这台机器上直接双击可用。要分发给别人，需要换成自己的
> 开发者证书签名并做公证（`--macos-sign-identity`）。

| 操作 | 快捷键 |
|------|--------|
| 打开文件夹作为库 | `⌘O` |
| 打开大图 / 返回网格 | 双击、`回车` / `Esc`、`回车` |
| 回到上一层（相册模式下） | 网格下 `Esc`，或**双击没有照片的空白处** |
| 上一张 / 下一张 | `←` / `→`（大图下 `空格` 也是下一张）。**焦点停在元数据面板里也一样能翻** —— 点过「复制全部」或「显示全部字段」之后不必先点回照片 |
| 适应窗口 / 实际大小 | `⌘0` / `⌘1` |
| 回到默认视图（适应窗口并居中） | 大图下**双击图片**（平滑过渡，不瞬跳） |
| 放大 / 缩小 | `⌘+` / `⌘-`，或 `⌘`+滚轮、触控板捏合 |
| 缩略图大小（小 / 中 / 大） | 网格下 `⇧⌘↑` / `⇧⌘↓` 一档一档挪，或触控板捏合、`⌘`+滚轮；也可用「视图 → 缩略图大小」 |
| 重命名（照片或相册） | 网格下**再次点击**已选中的缩略图；也可用 `⌘R`。<br>**大图页改的就是窗口标题栏那一行**：`⌘R` 把标题栏换成输入框（回车确认、`Esc` 取消、点到别处也确认），标题栏同时显示正在看的那张照片的文件名 |
| 在当前这一层新建相册（建完立刻行内重命名） | 网格**空白处右键 → 新建相册**，或 `⇧⌘N`（「文件 → 新建相册」）；分组视图里没有这一条 |
| 移到废纸篓（可多选） | 网格下 `⌘⌫`；大图下 `⌘⌫` 删掉正在看的那张，**接着看下一张**，`⌘Z` 再跳回刚删掉的那一张 |
| 撤销上一次写操作（重命名 / 移入废纸篓 / 移动到相册 / 编辑元数据） | `⌘Z`（只认 Gallery 自己做过的操作，「编辑 → 撤销」；**粘贴与新建相册除外**，撤销它们等于删文件） |
| 全选当前这一层 | `⌘A`（「编辑 → 全选」） |
| 拷贝文件（可多选，粘到访达里是一份拷贝） | `⌘C`（「编辑 → 拷贝」） |
| 拷贝路径（可多选，一行一个） | `⇧⌘C`（「编辑 → 拷贝路径」） |
| 粘贴：把剪贴板里的文件复制进**当前这一层**的文件夹 | `⌘V`（「编辑 → 粘贴」；右键菜单里**粘进某个相册**是另一条，见上面「右键菜单」那张表） |
| 复制 / 移动选中的照片到另一个相册 | **右键 → 复制到相册 / 移动到相册 → 挑一个相册**（网格与大图上都可用，不设快捷键；库里没有别的相册时这两条不出现） |
| 把这张照片设成所在相册的封面 | **右键照片 → 设为相册封面**（网格与大图上都可用，不设快捷键；改回来是**右键相册 → 取消相册封面**） |
| **编辑元数据**（拍摄时间 / 时区，与国家 / 省州 / 城市 及经纬度，写回这张照片） | **⇧⌘I**，或**右键照片 → 编辑元数据…**，或元数据面板**底部那一行**的「编辑元数据」（照片**本来就没有位置和时间**时也在那儿）；`⌘W` 关掉它，`⌘Z` 撤销写入 |
| 在访达中显示（可多选，把选中的挑出来） | 网格下 `⌘⏎`（右键菜单里也有这一条；大图下同样可用，作用于正在看的那张） |
| 在**默认应用**里打开当前这张（预览、PS…） | 网格下 `⇧⏎`（照片右键菜单里也有这一条；`⏎` 仍是在 Gallery 里打开大图） |
| 常用操作（打开 / 访达 / 新建相册 / 改名 / 删除 / 排序 / 上一级…） | **右键**：网格上照片、相册、分组卡片各有各的一份，空白处那一份以「新建相册」开头；大图上是照片那份换个头（第一行是「退出 `⎋`」） |
| 按元数据分组 / 排序 | 「视图 → 分组」、「视图 → 排序」 |
| 日历：切到年 / 月 / 周 | 日历下 `Y` / `M` / `W`，或工具条右边的分段选择器 |
| 日历：往前 / 往后翻一个月（一周、一天、一年） | 日历下 `←` / `→`；回到今天是 `T` |
| 进入 / 退出一个分组 | 双击组卡片 / 网格下 `Esc` 或**双击空白处** |
| 搜索照片（文件名 / 相册 / 元数据） | `⌘F`，在窗口标题栏右上角那个胶囊里输入，回车确认（详见下面「搜索」） |
| 显示 / 隐藏元数据信息 | 大图下 `⌘I`；也可用「视图 → 显示元数据信息」 |
| 拖动画面 | 直接拖拽（大图下） |

**三种浏览方式**，菜单「视图 → 浏览方式」切换，选择会记住：

- **全部照片**（默认）：把整个库（含所有子文件夹）的照片平铺在一起。
- **相册**：一个子文件夹就是一个相册，双击进入；每层只列当前目录的内容，同一层里**相册排在照片前面**，空相册画文件夹图标。用顶部面包屑、`Esc` 或**双击空白处**回上层（这一层空着时也一样管用）。退上去之后网格上**仍然选中刚离开的那个相册**；再进同一个相册，仍然停在刚才看的那张照片上。
- **日历**：按拍摄时间浏览，分**年 / 月 / 周**三层（详见下面「日历」）。

**分组与排序**，「视图 → 分组」「视图 → 排序」两个子菜单，选择会被记住：

- **分组**：网格里的照片变成一张张**组卡片**（和相册卡片同形：封面 + 组名 + 张数），双击进入，
  这一组的照片铺满网格，`Esc`、面包屑或**双击空白处**退回（退回来选中的是刚才那张组卡片）。
  相册卡片始终排在组卡片前面。
  可选的字段：拍摄年份 / 月份 / 日期、相机、镜头、国家、省州、城市、关键词、所在文件夹、文件格式。
  时间类分组新 → 旧，其余按名称升序；没写该字段的照片归到一个「时间未知」之类的组，排在最后。
- **排序**：在组内（未分组时是整层）按修改时间、拍摄时间、文件名、文件大小、所在文件夹、
  文件格式、相机、光圈、快门、ISO、焦距、像素尺寸排序，并可切成逆序。
  **默认就是按修改时间**（没打开过这个菜单也按时间看照片），网格永远按其中一个字段排。
  默认这一档**只看文件本身**：打开库就能排好，不必等 exiftool。**没值的一律排在最后**，
  正序逆序都一样。
- 每一层的网格都不会先铺一屏再换：**照片先攒着，顺序定下来一次到位**，
  中间只有横幅报进度（没装 exiftool 时那几项直接置灰，连这段等待都不会有）；
  索引里已经有的照片直接读缓存，这时连横幅都不出现。
- 分组与排序需要读照片的元数据。Gallery 会**一次 exiftool 子进程读一批**（不是每张一次），
  结果按「路径 + 大小 + 修改时间」缓存进 `.gallery/index.db`：第一次几秒，之后换库再回来立刻生效；
  删掉索引只是下次重读一遍。照片改过（写回元数据、被其它工具动过）会自动重读。
- **地点分组靠坐标反查**：相机原图几乎不写 IPTC / XMP 地点，只写 GPS，Gallery 会按
  坐标**离线反查**出城市 / 省州 / 国家（与元数据面板共用同一份随包分发的城市库，
  同样不上传坐标，也不需要下载）。文件里本来就写了地点的以文件为准；
  没有坐标也没有文件地点的归到「国家未知」。
- **地点在打开这个库时就解析好**：第一次打开一个文件夹，Gallery 会在后台把整库的
  坐标过一遍，反查结果连同拍摄时间、相机那些字段一起存进索引（横幅报进度，可以随时切走）。
  之后按国家 / 省州 / 城市分组与元数据面板里的地点都**直接读这份结果**，不必当场再算 ——
  两处显示的永远是同一个说法。关掉软件再打开同样不会重来一遍。
- 没装 [exiftool](https://exiftool.org/) 时，依赖 IPTC / XMP 的字段（国家、省州、城市、关键词）
  在菜单里**置灰并写明原因**，其余字段照常可用（走 Pillow 读基础 EXIF）。
- 组卡片本身不是磁盘上的东西：**改不了名**（右键菜单里干脆不出现这一项）。但它代表的
  那批照片是实实在在躺在磁盘上的，所以右键菜单里**拷、搬、删都是按组内这批照片来做**
  （与「双击进去、全选、再操作」得到的是同一件事，只是少了一趟）。删完组里一张不剩，
  那张卡片也就没有了。
- 按「关键词」分组时一张照片可以属于多个组（像标签一样），因此各组张数之和可能大于照片总数。

**搜索**，窗口标题栏右上角那个胶囊（`⌘F`）：

- **直接敲就是搜文件名**（按名字包含的那一段匹配，大小写无所谓）。
- 敲 `#` 会列出可以搜的字段：文件名、相册、文件格式、文件大小、拍摄时间、相机、镜头、
  国家、省/州、城市、关键词、光圈、快门、ISO、焦距、像素尺寸、修改时间。
  字段名**中文英文都认**（`#相机` 与 `#camera` 等价），选完补全成 `#相机 `，接着敲值。
- 写法：`#相机 Canon`、`#相册 旅行`（含子相册）、`#ISO 800` 或 `#ISO >1600`、
  `#文件大小 5MB`、`#拍摄时间 2024-05`、`#修改时间 2024`。认不出来的字段名会当成文件名搜
  （`#海边` 找的是名字里带「海边」的照片）。
- **时间可以写一段区间**：`#拍摄时间 2023～2024` 是「2023 与 2024 两年」，
  `#拍摄时间 2023-06 ～ 2023-08` 是那三个月（`～` 前后有没有空格都一样，
  半角的 `~`（`2023~2024`）一样认）。
  **两端各含自己那一整段** —— 写 `2024` 就是从元旦到 12 月 31 日那一整年。
  `#修改时间` 同样可以写区间；只要单边（某年之前、某年之后）就用 `>`、`<`。
  起始写在后面、或者只写了一端，横幅上会说明白，不会变成一条悄悄查不到的条件。
- **回车确认后输入框清空，这条条件出现在面包屑那一行的最右侧**；可以接着敲下一条，
  几条**全部满足**，一条一条收窄。
- **点面包屑上任意一条胶囊**（点文字）：把它放回右上角那个输入框接着改，回车**就地替换**
  那一条（位置不变），改到一半按 `Esc` 放弃这次改动。
- **点胶囊右端的 `✕`**（或在输入框里把它清空后回车）才是撤掉那一条；
  `Esc` 从最后一条开始逐条撤销，全撤光才回到上一层（「文件 → 清除搜索条件」一次清完）。
- 检索**横跨整个库**（不限于当前所在的文件夹；在 `旅行/2024` 里搜，命中的大半在别处）。
  结果就是一层，排序与分组照旧按「视图」里的选择来，面包屑上写着「搜索结果（命中数）」
  —— 那一行**不写当前文件夹、也不写当前那一组**，免得读成「在这个文件夹 / 这一组里搜到的」；
  撤光条件后会回到原来那一层、那一组。要限定范围自己加一条
  「#相册 …」（`#相册 旅行` 含其子目录，`#相册 旅行/2024` 精确到那一层，路径是精确匹配）。
- 结果里的照片**可以照常双击开大图、拷贝、移到废纸篓**（这些动作作用于选中的那几张，
  与浏览时完全一样）。
- 第一次搜索时如果索引还没建好，Gallery 会**先在后台建一遍**再把这次检索补上 ——
  不会给你一个「什么都没找到」的假答案。
- 国家 / 省州 / 城市 / 关键词这几个字段靠 IPTC / XMP，没装 exiftool 时读不出来；
  此时提交这样的条件会**明说**这一点，文件名、相册、格式、大小不受影响。

**右键菜单**（网格与大图上，⌘ 与访达一致的三条规则）：

| 落点 | 菜单里有什么（`│` 是分隔线） |
|------|--------------|
| 照片 | 打开 · 在默认应用中打开 · 在访达中显示 · **设为相册封面** │ 拷贝 · 拷贝路径 · 复制到相册 · 移动到相册 │ 重命名… · **编辑元数据…** · 移到废纸篓 │ 显示元数据信息 · 复制元数据 —— **没有「粘贴」**（`⌘V` 照旧能用）；「设为相册封面」只在选中的是相册里的照片时出现（多选、库根下的照片、分组卡片都没有） |
| 相册 | 打开 · 在访达中显示 · **取消相册封面**（设过才有）│ 拷贝 · 拷贝路径 · **粘贴**（`⌘V`）│ 重命名… · 移到废纸篓 —— 这一条的「粘贴」**粘进这个相册内部**，不是粘到它所在的这一层（与访达的「粘贴项目」一样）；少了元数据那两条、「在默认应用中打开」，也没有「复制到相册 / 移动到相册」（搬相册会动到整棵子树，请去访达做） |
| 分组卡片 | 打开 · 在访达中显示 │ 拷贝 · 拷贝路径 · 复制到相册 · 移动到相册 │ 移到废纸篓 │ 复制分组条件（形如「按「相机」分组：Canon EOS R5 · 128 张」）—— 中间那几条**逐字就是多选照片时的那几条**，作用的是组内这批照片；没有「重命名…」（卡片没有名字可改），也没有「粘贴」（卡片不是文件夹，粘到哪儿说不清） |
| 空白处 | **新建相册** · **粘贴** │ 全选 │ 分组 ・ 排序 ・ 缩略图大小 │ 回到上一层 —— 最上面那两条是仅有的会动磁盘的两条，都只增不改 |
| 大图（在照片上） | 与上面「照片」那一行几乎一样，只把最上面的「打开」换成「退出」（`⎋`）；同样没有「粘贴」。「重命名…」改的是**窗口标题栏那一行**（`⌘R`） |

- **「粘到哪里」看的是选中没选中相册**（`⌘V` 与菜单里那一条都按这一条走）：

  | 选区 | 粘到哪里 |
  |---|---|
  | **恰好选中一个相册** | **那个相册内部**（不是它的上一层，与访达的「粘贴项目」一样） |
  | 没选中、选中的是照片或分组卡片、选了不止一个 | 当前这一层 |

  也就是说：点中一个相册再按 `⌘V`，照片就落进那个相册里 —— 与访达一致。多选时粘进哪一个
  说不清，仍旧粘进当前这一层。**点一下空白取消选中之后，⌘V 立刻回到当前这一层** —— 判据看
  的是真正选中的那一格，不会把刚才选过的相册记着。
- 右键菜单里**空白处**与**单个相册**那两份有这一条，**照片**（单选、多选）与**分组卡片**、
  **多个相册**、**大图**那几份没有 —— 按在一张照片上时「粘到哪」说不清。相册那一份里的
  「粘贴」**就是 `⌘V` 本身**，所以那一行写着 `⌘V`：菜单开着时按 `⌘V` 与点它是同一件事。

- 五张菜单都按**同样四段**分组：**看一眼**（打开 / 在默认应用中打开 / 在访达中显示 / 设为相册封面 / 取消相册封面）、
  **拿进拿出**（拷贝 / 拷贝路径 / 复制到相册 / 移动到相册 / 粘贴）、**会动文件**
  （重命名… / 编辑元数据… / 移到废纸篓）、**它是什么**（显示元数据信息 / 复制元数据；分组卡片上则是
  复制分组条件）。分组看的是「这道命令到底动什么」，所以换一张菜单、换一种选区，段的
  位置不跳：某个落点缺某一段时那一段连同分隔线一起不出现，**一段里少几行时分隔线照旧**
  （例如按在照片上时整段没有「粘贴」，其余几行与那道线都还在）。菜单栏里那几条命令永远
  摆在同一张表的同一段里。
- 右键点**没选中**的那一格会先把它选中；点在**已经选中**的那一格上则**保持整个多选**，
  菜单里的命令作用于全部选中项（多选时「打开」「重命名…」这类只对单个的条目不会出现）。
  多选照片时**最后一整段也不出现**：「显示元数据信息」与「复制元数据」讲的都是**这一张**
  照片 —— 面板显示的是光标那一格，选区里另外那十几张并没有理由被指定（`⌘I` 照旧能用）。
- **大图上右键，命令作用的是「正在看的那一张」** —— 不是网格里还选中的那一格（翻过图之后
  两者早就不是同一张了）。在大图里 `⌘⌫` 删掉正在看的那张，**接着看下一张**；没有下一张就看
  上一张，整层一张都不剩了才退回网格（同样记账、同样 `⌘Z` 可撤销）。
  **`⌘Z` 会带你回到刚删掉的那一张** —— 撤销会让整层重排，不跳回去的话那张照片既不在大图里，
  网格上那一格也可能落在视野之外。整层删空而退回网格的那一次，撤销会把大图重新打开。
- 三个「打开」是同一族：`⏎` 在 **Gallery 里**开大图，`⇧⏎` 交给**系统为这类文件设定的默认
  应用**（预览、PS…），`⌘⏎` 把它在**访达里挑出来**。Gallery 自己只读不写 —— 打开成什么样
  是那个程序自己的事。分组卡片上 `⇧⏎` 不可用（组里哪一张都没有理由被指定，按下去什么也
  不发生，不会偷偷退回成「在 Gallery 里打开」），`⌘⏎` 则把那批照片在访达里一起挑出来。
- 选中的**分组卡片**按它代表的那批照片来算：`⌘C` / `⇧⌘C` / `⌘⏎` / `⌘⌫` 与右键菜单里的
  那几条作用在同一批照片上（菜单里亮着的，快捷键也就按得出来）。卡片与照片一起选中时
  同一张只算一次。
- 网格上会动用户文件的入口有五条：**重命名**、**移到废纸篓**、**粘贴**、**移动到相册**、
  **新建相册**。前两条与 `⌘R` / `⌘⌫` 走的是同一条路：同样记账、同样 `⌘Z` 可撤销。
  **移动到相册**同样能 `⌘Z` 撤销（撤的是「挪回原来的相册」）；**粘贴与新建相册不一样**，
  见下面那两条。
- 另有**「设为相册封面」/「取消相册封面」**：它们写的是 `.gallery/config.toml`，
  也就是 Gallery 自己的配置文件 —— **你的照片一个字节都不动**，因此不在上面那五条里，
  也不进 `⌘Z` 那一摞栈（那一摞装的是「动了用户文件」的那些操作）。
- 「拷贝」⌘C 往剪贴板里放的是**文件本身**（访达里 `⌘V` 得到一份拷贝，粘到邮件里是附件），
  「拷贝路径」`⇧⌘C` 放的才是路径文字。两条都只往剪贴板里写一个路径引用，**不读像素、
  不写文件** —— 粘出来的那一份是访达写的，不在 Gallery 的地盘上。
- **「粘贴」⌘V** 把剪贴板里的文件**复制**进**当前这一层**的文件夹（源文件原地不动）：
  - 粘到哪里一律**按磁盘上的真实位置**算 —— 相册模式是当前这一层，「全部照片」是库根，
    分组里则是「这一组照片本来就在同一个相册」时的那个相册（散在几个相册里的一组 `⌘V` 置灰）。
    同一个相册的两个不同分组认成同一个目录。
  - **选中了一个相册就粘进那个相册**，不是粘到它所在的这一层（见上面那张选区的表）。
    右键某个相册时菜单里那一条也是同一个 `⌘V`：右键会先把那一格选中，于是点它与按 `⌘V`
    落在同一个目录上。按在照片上（单选、多选都是）**不出现**这一条 —— 那一格未必属于当前
    这一层，粘到哪儿说不清；`⌘V` 一直都在，不必靠菜单。详见上面「右键菜单」那张表。
  - **已经在那个文件夹里的原样跳过**：同一个相册里 `⌘C` 再 `⌘V` 什么也不会多出来。
  - **绝不覆盖**：目标已有同名就按访达的办法改叫「一张 2.jpg」「一张 3.jpg」，横幅会告诉你新名字。
  - **源可以来自库外**（在访达里 `⌘C` 的东西照粘）。
  - 粘进来的新照片不用刷新，网格自己会长出来。
  - **不能 `⌘Z` 撤销**：撤销粘贴就是删文件，而删除只由用户在界面上亲手触发（`⌘⌫` 走的是
    有日志、可再撤销的那条路）。粘贴仍然会记进 `.gallery/journal/`。
- **「新建相册」`⇧⌘N`** 在网格空白处菜单的**第一条**（「文件 → 新建相册」也有），
  与访达的「新建文件夹」同一个键、同一个手感：
  - **建在当前这一层**：相册模式是正在浏览的那个文件夹（顶层就是库根），「全部照片」是库根；
    **分组视图里没有这一条** —— 分组不是文件夹，而且那一层网格上摆的全是照片。
  - 建出来的是一个**普通的空文件夹**，照片怎么进去、怎么整理，Gallery 一概不管（不替你
    建目录结构、不替你搬照片）。
  - **建完立刻进入行内重命名**：光标已经在那一行上等着，直接打字就是改名字，回车确认。
    这一步是一次普通改名，`⌘Z` **能撤**；撤不掉的是那个空文件夹本身 —— 要删就选中它按 `⌘⌫`。
  - **绝不覆盖**：已经有一个叫「新建相册」时就叫「新建相册 2」，与粘贴同一套规矩。
  - **不能 `⌘Z` 撤销**（撤销就是删文件夹，删除只由用户亲手触发），但同样记进
    `.gallery/journal/`。
- **「设为相册封面」** 在照片与大图的右键菜单里，摆在「看一眼」那一段的末尾：
  - **相册是这张照片的父目录**，不是「现在站在哪一层」—— 在「全部照片」那一屏里选到一张，
    说的也是它自己那个相册。
  - 只记**一个路径**，写在 `.gallery/config.toml` 里（`[album_covers]` 那张表，两列都是相对
    库根的路径）：`"京都" = "京都/DSC_0001.JPG"`。删掉那一行就回到默认，**手改这个文件也有效**。
  - **默认是「里面第一张照片」**，没指定封面与指定了但那张照片已经不在了，都是这个结果。
    那一行配置会留着：照片挪回来时它又算数。
  - 写的是 `.gallery/config.toml`，**不是你的照片**：不改一个字节、不记 `journal/`、
    不能 `⌘Z` 撤销（改回来是**右键相册 → 取消相册封面**）。
  - 开场时选了「缓存到系统目录」的库**设不了**：那个承诺是照片文件夹一个字节都不写入，
    而封面只能存在库里的配置文件里 —— 此时这一条会明说，不会偷偷建出目录来。
- **「复制到相册」「移动到相册」** 在照片与分组卡片的右键菜单里，摆在「拷贝路径」正下方，
  两条都是子菜单（要挑一个目标相册）：
  - 清单里列的是**整个库的全部相册**，标签是**相对路径**（`2025/苏州`）—— 两个年份下面
    各有一个「苏州」，只写名字分不清要挪到哪去。清单每次弹出时现列，在访达里新建的相册
    下一次右键就能选到。
  - **复制**与「粘贴」是同一个动作：源文件原地不动，目标里多一份。
  - **移动**把照片**挪**进那个相册 —— 原处不再有它。像素与修改时间一个字节都不改
    （同一个磁盘上就是一次改名，不产生第二份数据）。
  - **绝不覆盖**：目标已有同名就按访达的办法改叫「一张 2.jpg」，横幅会告诉你新名字。
  - **本来就在那个相册里的原样跳过**，横幅会说明为什么什么也没发生。
  - **移动可以 `⌘Z` 撤销**，照片挪回原来的相册（撤销一次移动仍然是一次移动，不是删除）。
    一次移动十张就是一次 `⌘Z` 全撤回来；原位置这期间被别的文件占了就撤不回来，
    横幅会如实说 —— Gallery 不会替你腾位置。
  - 移走的东西网格会自己更新（靠文件监听），**不会**重扫当前这一层，所以选中与滚动位置不丢。
  - **相册菜单里没有这两条**：搬相册会动到整棵子树，那请去访达做。
- 「复制元数据」在面板没展开、缓存里没有时会现读一次（约 50ms，后台线程，完成后横幅告知）。

其它行为：

- **提示横幅浮在内容上面**：做完一件事的那句话出现在照片区的**顶部中央**（面包屑
  那一行），**盖在上面、不占一行** —— 网格不会被它往下挤，滚动位置也不会因为一句话跳一下。
  网格页与大图页看到的是同一条（在大图上做的 `⌘Z`、`⌘C`、`⌘⌫` 也当场看得见反馈，
  不必退回网格）。**做完一件事的确认过几秒会自己收起来**（约 4 秒）；出错、没能做成、
  「这里是空的」这类要你动手处理的话会一直留着，直到被下一条替换。
- 打开库时递归扫描全部子文件夹；扫描、缩略图解码与排序都在后台线程，界面不会卡住。
  这一层的照片扫完之后一次到位（顺序一次到位，不先铺一屏按文件名排再换），滚到哪儿，
  哪儿的缩略图先出。默认排序只看文件，因此打开库**不必等 exiftool**：整库的地点解析
  在后台慢慢做，不挡着网格。
- 缩略图有小 / 中 / 大三档，档位是目标密度：每一行都按窗口宽度铺满、右侧不留空白，所以实际边长
  会随窗口小幅浮动（状态栏会报出实际值）。切换档位或改变窗口大小时，已经显示的缩略图会保留并就地
  缩放，不会先空一块再一张张弹出来。
- 切图时**上一张会留在屏幕上**，只在右上角提示「正在载入…」（加载快时不显示提示）。打开损坏文件
  同样不清屏，改用右上角的红色提示说明原因。
- 读不了的文件（损坏、没有权限）不会让整个库打不开：界面上给出中文提示，其余照片照常浏览。
- **重命名**：网格里选中一个缩略图后**再点一次**，名字那一行会变成可直接编辑的输入框；
  在大图页里，窗口标题栏那一行就是输入框（`⌘R`），标题栏平时显示正在看的那张照片的文件名。
  两处都是回车确认、`Esc` 取消、点到别处也确认。改的是硬盘上真实的文件名 / 文件夹名，
  所以访达、iCloud、Photos 里看到的也是新名字。照片只选中「主干」，扩展名不会被误删；
  扩展名本身不能改（改了就不是 Gallery 认得的照片了），名字也不能以 `.` 开头
  （以点开头的文件不会出现在 Gallery 里）。相册改名等于改文件夹名，里面的照片路径会跟着变。
  每次改名都会记进 `.gallery/journal/`，`⌘Z` 可以撤销最近一次；被访达或其它程序改过的
  名字 Gallery 不会去撤销。同名文件已存在时直接拒绝，绝不覆盖。
- **移到废纸篓**：网格里选中若干项（`⌘` 点、`Shift` 连选）后按 `⌘⌫`，它们会被**移进系统
  废纸篓**（和访达的「移到废纸篓」是同一个地方），不是被删掉 —— 照片一个字节都没少，
  在访达的废纸篓里也照样能还原。删相册时里面的一切一起进废纸篓。不弹确认框，界面用一行
  横幅立刻告诉你移走了多少、能不能撤销。每次操作都记进 `.gallery/journal/`，`⌘Z` 把它们
  原样取回网格。选中一张**分组卡片**时，删的是它代表的那批照片（组里一张不剩，那张卡片
  就没有了）。**Gallery 没有任何会销毁文件的操作**。
- **实时反映磁盘上的变化**：打开库之后就不用再重开它了。从访达拖一批照片进来、
  删掉一张、在访达里改个名、用别的工具改完 EXIF 再切回来 —— 网格都会立刻跟上：
  新照片插在该在的位置，删掉的格子就地消失，改名的原地换掉（选中还在），
  内容变了的会重新取缩略图与元数据。拷贝一批照片只会引起一次网格改动，
  不会一张张地闪。Gallery 自己在窗口里做的改名 / 删除也会被听见，但不会被重复执行一遍。
- 下次启动会自动回到上次打开的库，窗口位置、大小与缩略图档位都会记住。
- 菜单「文件 → 清空缩略图缓存」只删缓存、不碰照片。
- 大图下按 `⌘I` 在右侧展开**元数据面板**（图片区域会自动缩小重新适配，不会遮住照片）：
  分组展示拍摄参数、位置、图像、内容与文件信息；长值自动换行、可选中复制，底部「复制全部」
  一次拷成文本，勾选「显示全部字段」可以看到来源返回的原始键值（制造商注释、ICC 配置等）。
- 元数据优先由 [exiftool](https://exiftool.org/) 读取（`brew install exiftool`），
  它同时覆盖 EXIF / IPTC / XMP。**没装也能用**：Gallery 会退回 Pillow 读取基础 EXIF，
  并在面板顶部说明少了什么 —— 只是读不到 IPTC / XMP 与制造商注释。
- 照片带 GPS 坐标时，会**按坐标推断地点**显示在「位置」里，例如
  「Bordeaux · Gironde · France（按坐标推断）」。这是**完全离线**的反查：
  用的城市库（约 380 KB）随应用一起分发，**不联网、不下载、不缓存**，
  **你的坐标不会发送到任何服务器**。文件里本来就写了地点（Lightroom 等导出的
  `City` / `Country`）时以文件为准，不再推断。推断结果一律标注「按坐标推断」，
  它与照片自带的元数据不是一个可信级别。
- 地点名**一律用当地语言**：国内显示成中文，境外保持当地写法（上面那个 Bordeaux
  就是例子）—— 用户在自己的照片上认得出自己拍过的地方，比认一份我们替他翻的清单更有用。
  直辖市、香港、澳门不设「省」那层（「中国 · 上海」），台湾显示成「中国 · 台湾 · 高雄」。
  文件里自带的地点名同样原样显示，一个字都不改。
- **区不会被当成城市**：深圳宝安区的松岗街道会显示成「中国 · 广东省 · 深圳」——
  照片归属到它所属的市，而不是就近那个区的名字。
- 面板里的地点与地点分组**读的是同一份结果**（打开这个库时算好，存在 `.gallery/index.db`），
  所以两处显示的说法一定一致，不会一个写杭州、一个写 Bordeaux。

### 编辑元数据

**能改的只有两类**：**拍摄时间**（含时区）与**位置**（坐标 GPS 与城市 / 省州 / 国家这三层地名）。
它们通过 [exiftool](https://exiftool.org/)
**写回这张照片本身**，所以别的软件（Lightroom、Photoshop、访达的「简介」）看到的也是你改过的值；
Gallery 不维护另一份「自己的元数据」，索引里那几列永远是从照片里读出来的投影。

**其余的元数据一律只读**：相机、镜头、光圈 / 快门 / ISO / 焦距这些是**拍摄事实**。
它们由相机机身测出并写下，是这份照片的证据；替用户改掉它们等于伪造证据，还会让「同一台机器拍的照片」
这类去重悄悄失效。

**拍摄时间为什么可以改**：它不是测出来的量，而是**机内时钟的一次读数** —— 对不对取决于
你有没有把时区设对、有没有换过电池、GPS 有没有对过时。相机带着没电的电池出去、在日本忘了调时区、
扫描件没时间、胶卷靠张数推断…… 这几类照片的时间是**确定错了**的，而它们的错恰恰不该被当成
证据保护起来。相机与曝光三件套仍然不开放，那一条线一个字没动。

| 你改了什么 | 顺带发生什么 |
|---|---|
| **拍摄时间 / 时区** | 两个框各写各的。EXIF 的 `DateTimeOriginal` 记的是**墙上时间**（拍照当地那个钟面上的几点几分，**既不是 UTC 也没有换算**），时区在单独的可选字段 `OffsetTimeOriginal` 里，相机十有八九不写它 —— 所以那一栏照片没记时区时就是**空的**，Gallery **绝不按本机时区替你补一个**（猜错的后果是排序整体偏几个小时） |
| **坐标** | 地点按新坐标**重新推断**（离线，最近的城市，超过 300 公里就不给结论）；原来的**海拔与定位时间会一并清掉** —— 留着就是一条自相矛盾的 GPS 记录 |
| **城市 / 省州 / 国家** | 城市库里有这个名字时，**坐标也会自动更新成这座城市的位置**。⚠️ 那是**市级精度**：照片从「西湖边」变成「杭州市中心」，几十米变成几公里 |
| **两样都改** | 都按你填的来，Gallery 不替你调整它们之间的对应关系 |
| **只敲城市** | 城市一敲定，上面两栏（国家、省州）自动补上 —— 也照常从上往下填 |
| **全清空** | 坐标与三层地名一起删掉（不需要单独的勾选框） |

写进去之后，元数据面板的「位置」里是**一行** `中国 · 浙江省 · 杭州`，不是三行 ——
它们说的是同一个地方。

**改时间不会改文件名**：`IMG_20240705_143022.jpg` 这类文件名里编码的时间不会跟着变 ——
改名是另一条独立的、必须你亲手触发的命令，不会在保存元数据时顺手搭便车。

**编辑器长这样**：`⇧⌘I`、`⌘W` 关掉（窗口不能拖大拖小）。最上面是**拍摄时间**与**时区**两个框，
下面才是位置。三个地名框都是**普通的输入框**
（不是下拉 —— 城市库里没有的门牌、景区也得能填进去），按 **国家 → 省 / 州 → 城市**
由大到小排，而真正用来查的是**城市**：

- **只敲城市就行** —— 城市一敲定，上面两栏自动补上（用的是库里那一带的准确写法），
  换城市时也不会被上一座城市的省与国家挡住；
- **敲地点，下面两个坐标框立刻更新**；**敲坐标，上面三个地名框立刻更新**（离线，最近的城市）；
- 查不到就一个字都不填，也不会编一个出来 —— 「西湖·断桥」这种没有记录的名字，
  以及境外的当地写法（库里写的是 `Kyoto`，不是「京都」）；
- 底下是 **3×3 九个按钮**：

  ```
  复制        复制时间      复制位置
  粘贴        粘贴时间      粘贴位置
  清空位置    取消          保存
  ```

  **「清空位置」只清位置那五栏** —— 删掉一张照片的拍摄时间是另一件更大的事；想清掉拍摄时间，
  把上面那两个框清空就行（与位置同一套语义：空 = 照片里不记这一项）。
- **复制 / 粘贴**把一个地点从一张照片搬到另一张，而「复制时间 / 粘贴时间」只搬上面那一段。
  复制出来的是

  ```
  2024-05-16 20:52:02 +08:00
  31.311100, 120.621300
  苏州, 江苏省, 中国
  ```

  —— 人也能读（要粘进别的地图软件时直接用第二行），**没填的那一段就不写那一行**。
  粘贴时**按每一行的形状认**，不按行号认：像坐标的按坐标认（半球标记、`°`、空格或逗号分隔、
  经度在前都认，度分秒不认 —— 猜错的坐标会被原样写进照片，比看不懂糟糕得多），像地名的按三层地名认，
  像时间的按时间认。于是只复制了时间、只复制了位置都照样粘得回去。
  坐标与地名**两边都粘到就都别动**，那张照片米级的精度不该被市级坐标盖掉。

其余几件同样重要的事：

- 每一次写入都**记账、都能 `⌘Z` 撤销**，撤销按的是**字段**的原值 —— 在别的工具里改过的那些字段
  不会被覆盖，横幅会告诉你哪几个没撤成。**时间与位置是一次写入、一条记录、一下 `⌘Z`**，
  不是两次。
- 写进去之前会**读回来核对一次**：值对不上就按原值恢复并如实报错，不留半成品。
- 照片旁边**不会多出任何文件**（exiftool 默认会留一个 `xxx.jpg_original` 备份，已强制关掉）。
- 没装 exiftool 时「编辑元数据」这一条**不出现**，面板上那个位置会写明原因。

**已知限制**：RAW（CR2/CR3/NEF/ARW/DNG）尚不支持；GIF 只显示第一帧。
正处在「按元数据分组」的某个分组里时，刚进来的新照片会让整个库重新分组一次
（组的成员是上一次分组算出来的快照），因此那一次可能比平常慢一点点。

## 日历

「视图 → 浏览方式 → 日历」。一层是**一段日子**，照片按拍摄时间落在对应的格子里；
样式参照 Google Calendar 的桌面版，配色跟着系统的浅色 / 深色走（本软件自己的主题）。

三层用 `Y` / `M` / `W` 切，`←` / `→` 翻页，`T` 回今天，`Esc` 退出日历这种浏览方式：

- **年**：4 × 3 张小月（**一周从周日开始**，表头是「日 一 二 三 四 五 六」）。有照片的那天
  铺当天的一张封面，上面压一枚日期；每张小月右上角是这一个月的张数。
- **月**：7 列 × 6 行（首列是周日，周日与周六两列淡底）。每格左上角是日期，下面铺**当天的一张照片**铺满整格
  （不止一张时右下角写「N 张」）；照片按**自己的**比例缩放后居中，竖幅照片上下留边。
- **周**：7 列按小时铺开，首列是周日。每一小时一格，**一格一张照片**，格子是 3:2，
  照片按**自己的**比例缩放后居中放进去。那一小时超过一张时，右下角写「还有 N 张」。
  打开就停在第一张照片所在的那个小时上。标题上的「第 N 周」是按这一周数出来的
  （含 1 月 1 日的那一周是第 1 周），不是 ISO 周号。

**点开与退回去**：日历上点有照片的**任何一格**（年 / 月里的一天，或周里的一个小时），
就那一格的照片会摊在网格页里 —— 就一张时直接进大图页。`Esc` 一路退回**日历原来那一段**
（停在哪一周、滚到哪个小时都还在），再 `Esc` 才退出日历这种浏览方式。

几点约定：

- **按小时分组**，分钟与秒不参与 —— 一次连拍 48 张常常全在 19:44:02，
  按小时归一之后它们落在同一格，而不是四十几个高度为零的点。
- **不换算时区**：一律用照片里记着的那只钟点（「相机所在地几点几分」是用户唯一
  认得的那个时间）。索引里为此多存了墙上钟点两栏，老库第一次打开会重读一次 EXIF。
- **没有拍摄时间的照片不进日历**（没有日期，本来就放不下）。它们在「全部照片」
  与相册视图里都还在。

## 支持的照片格式

- **完整支持（读 + 写元数据）**：JPEG、HEIC/HEIF、TIFF、PNG
- **仅预览**：GIF、WebP、BMP
- **尚未支持**：常见 RAW —— CR2/CR3、NEF、ARW、DNG
