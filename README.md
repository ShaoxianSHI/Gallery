# Gallery

一个基于 Python 的本地相册软件：**照片留在你自己的文件夹里，软件只是它的一个视图。**

Gallery 像 Obsidian 那样工作——你指定一个本地文件夹作为「库」，软件读取它、而不接管它。照片始终是普通文件，用 Finder、访达、Photoshop 或任何别的工具都能打开；即使卸载 Gallery，你的照片和元数据依然完整可读。第一个版本面向 macOS，核心目标是两件事：

1. **实时查看**：打开文件夹即可浏览，磁盘上的变化立刻反映到界面。
2. **元数据的查看与修改**：读取并写回 EXIF / IPTC / XMP，改动直接落在照片文件上。

---

## 设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | **本地文件夹即数据库** | 没有「导入」这一步。库就是一个普通目录，不存在只有 Gallery 才能打开的私有格式。 |
| 2 | **照片是唯一事实来源** | 元数据写回原文件（经 exiftool），不用 Gallery 也能看到修改结果。 |
| 3 | **缓存可丢，数据不可丢** | `.gallery/` 下除 `config.toml` 外的一切都可以随时删除并重建。 |
| 4 | **默认只读，写入显式** | 浏览、检索、缩放永不写盘；任何改动原文件的操作都必须由用户主动触发，并留可回滚记录。 |
| 5 | **Mac 优先，但不锁死** | v1 只为 macOS 打磨（文件监听、HEIC/RAW 支持、原生观感），核心逻辑保持平台无关，为将来的 Windows / Linux 留出空间。 |

## 名词约定

| 术语 | 含义 |
|------|------|
| **库 / Library** | 用户用 Gallery 打开的那个根文件夹。一个库对应一个根目录。 |
| **根目录 / Root** | 库的顶层文件夹路径，所有扫描与监听都从它开始。 |
| **`.gallery/`** | 库内的隐藏配置目录，存放配置、索引与缓存。见下节。 |
| **索引 / Index** | 由扫描生成的照片清单与元数据快照，存放在 `.gallery/index.db`。 |
| **旁车文件 / Sidecar** | 与原图同名、放在旁边的附属文件（如 `IMG_0001.xmp`）。v1 不作为主存储。 |
| **写回 / Write-back** | 把用户在界面上的元数据修改真正写进照片文件的操作。 |

---

## `.gallery/` 目录约定

配置目录固定为 `.gallery/`（**不是** `.galley/`），位于库根目录下：

```
<库根目录>/
├── 2024-京都/                 # 用户自己的照片文件夹，Gallery 不做任何整理
│   ├── IMG_0001.HEIC
│   └── IMG_0002.JPG
└── .gallery/                  # Gallery 的运行时数据
    ├── config.toml            # 库级配置（唯一建议纳入版本控制的文件）
    ├── index.db               # SQLite 索引缓存，删除后可重建
    ├── cache/thumbs/          # 缩略图缓存，可随时清空
    └── journal/               # 元数据写回日志，用于回溯与回滚
```

**硬性约定**：除 `config.toml` 外，`.gallery/` 中的任何内容都不得成为唯一数据副本。删掉整个 `.gallery/`，软件必须能通过重新扫描恢复到等价状态。

## 技术选型

| 方面 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3.12（uv 托管，`.python-version` 锁定） | 不依赖系统 Python；类型标注完善、`tomllib` 内置、第三方 wheel 覆盖最稳 |
| 环境与依赖管理 | [uv](https://docs.astral.sh/uv/) | 速度快、锁定可靠；本机已安装 |
| 界面 | PySide6 / Qt Widgets | 大图缩放与缩略图网格性能好，Mac 观感原生 |
| 图像解码 | Pillow + pillow-heif | 覆盖 JPEG/PNG/TIFF 与 HEIC/HEIF |
| 元数据读写 | exiftool（子进程调用） | 格式覆盖最广、写入最可靠，避免自己重造 EXIF 写入器 |
| 文件监听 | watchdog | 跨平台的文件系统事件，驱动实时刷新 |
| 索引缓存 | SQLite（标准库 `sqlite3`） | 零额外依赖，单文件、可重建 |

> 开发前置依赖：`brew install exiftool`。exiftool 缺失时，软件应降级为「只读模式」而不是崩溃。

## 目录结构（规划）

```
Gallery/
├── README.md            # 面向人的项目概述（本文件）
├── AGENTS.md            # 面向 AI/协作者的工程规范
├── pyproject.toml       # 项目元数据与依赖声明
├── .python-version      # 锁定的解释器版本（3.12），由 uv 读取
├── uv.lock              # 依赖锁定文件，纳入版本控制
├── .venv/               # 虚拟环境，本地生成、不入版本控制
├── src/gallery/
│   ├── core/            # 无界面依赖：扫描、解码、缓存、索引、元数据、写回与日志
│   │   ├── constants.py     # 配置目录名等常量（唯一来源）
│   │   ├── errors.py        # 领域异常，带可行动的中文提示
│   │   ├── paths.py         # 由库根推导 .gallery/ 下各路径
│   │   ├── config.py        # 库级 config.toml 的读写
│   │   ├── photos.py        # PhotoRef 与格式判定
│   │   ├── scanner.py       # 目录遍历（可取消、可流式消费）
│   │   ├── images.py        # Pillow 解码，产出裸 RGBA 像素
│   │   ├── thumbs.py        # 缩略图磁盘缓存与 LRU 清理
│   │   ├── library.py       # Library 门面：打开库、扫描、取缩略图/预览
│   │   └── session.py       # app 级会话状态（最近打开的库、窗口几何）
│   ├── ui/              # PySide6 界面层
│   └── cli.py           # 命令行入口（启动界面；后续承载批量扫描/导出）
├── tests/               # 与 src/gallery/ 层级对应
└── docs/adr/            # 设计决策记录
```

**分层规则**：`core/` 不得导入任何 Qt 模块；`ui/` 只能通过 `core/` 暴露的接口访问文件系统。这条规则由测试强制执行——它是「核心逻辑平台无关」这一承诺的技术保障。

## 支持的照片格式（v1 目标）

- **完整支持（读 + 写元数据）**：JPEG、HEIC/HEIF、TIFF、PNG
- **只读优先（写回需显式警告）**：常见 RAW —— CR2/CR3、NEF、ARW、DNG（**M1 尚未支持**，见 ADR 0001）
- **仅预览**：GIF、WebP、BMP

## 查看器（M1）

```bash
uv run gallery            # 启动界面（自动回到上次打开的库）
uv run gallery ~/照片     # 直接打开指定文件夹
uv run gallery --version  # 只打印版本，不加载界面
```

| 操作 | 快捷键 |
|------|--------|
| 打开文件夹作为库 | `⌘O` |
| 打开大图 / 返回网格 | 双击、`回车` / `Esc`、`回车` |
| 上一张 / 下一张 | `←` / `→`（大图下 `空格` 也是下一张） |
| 适应窗口 / 实际大小 | `⌘0` / `⌘1` |
| 放大 / 缩小 | `⌘+` / `⌘-`，或 `⌘`+滚轮、触控板捏合 |
| 缩略图大小（小 / 中 / 大） | 网格下触控板捏合，或 `⌘`+滚轮；也可用「视图 → 缩略图大小」 |
| 拖动画面 | 直接拖拽（大图下） |

- 打开库时递归扫描全部子文件夹；扫描与缩略图解码都在后台线程，界面不会卡住，
  照片会边扫边出现。滚到哪儿，哪儿的缩略图先出。
- **首次打开一个还没有 `.gallery/` 的文件夹时会先询问**：在库中创建缓存目录，或把缓存放到系统目录
  （`~/Library/Application Support/Gallery/`）而让照片文件夹保持零写入。任何情况下都不会修改原图。
- 读不了的文件（损坏、没有权限）不会让整个库打不开：界面上给出中文提示，其余照片照常浏览。
- 切图时**上一张会留在屏幕上**，只在右上角提示「正在载入…」；加载快时不显示提示。
  打开损坏文件同样不清屏，改用右上角的红色提示说明原因 —— 闪一下黑屏比多等一会儿刺眼得多。
- 缩略图有**小 / 中 / 大**三档。档位是目标密度：每一行都会按窗口宽度铺满，右侧不留空白，
  所以实际边长随窗口宽度小幅浮动（状态栏会报出实际值）。再次切换窗口大小或档位时只会重读
  缩略图缓存，不会重新解码原图；选择会记住，下次启动沿用。
- 下次启动会自动回到上次打开的库；窗口位置与大小也会记住。
- 菜单「文件 → 清空缩略图缓存」可以只删缓存、不碰照片（缓存本来就可以随时删）。

**已知限制**：RAW（CR2/CR3/NEF/ARW/DNG）尚不支持；GIF 只显示第一帧；
文件夹的增删改需要重新打开库才能反映（实时监听属于 M4）。

## 路线图（v0.1）

| 阶段 | 内容 | 状态 |
|------|------|------|
| M1 | 查看器：选库、缩略图网格、大图缩放与平移浏览 | 进行中 |

## v1 非目标

明确不做，避免范围蔓延：

- 导入式图库管理（把照片复制进私有存储）
- 云同步、账号体系、分享链接
- 像素级修图（裁剪、调色、滤镜）
- 人脸识别、场景分类等自动标注
- Windows / Linux 的打包与适配

## 开发环境

前置条件只有两个：

1. 安装 [uv](https://docs.astral.sh/uv/)（本机已装；`brew install uv` 亦可）。
2. 安装 exiftool：`brew install exiftool`。**Python 无需自行安装** —— `uv sync` 会按 `.python-version` 自动下载 uv 托管的 3.12 解释器。

```bash
uv sync                 # 创建 .venv 并安装全部依赖（含 uv 托管的 Python 3.12）
uv run pytest           # 运行测试
uv run ruff check .     # lint
uv run ruff format .    # 格式化
uv run mypy             # 类型检查（仅 core/）
uv run gallery          # 启动应用
```

`.python-version` 与 `uv.lock` 都纳入版本控制：前者锁定解释器版本，后者锁定依赖解析结果，两者共同保证任何机器上 `uv sync` 得到一致环境。

工程规范、代码约定与协作规则见 [AGENTS.md](AGENTS.md)。
