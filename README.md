# Gallery

一个本地优先的 macOS 相册软件：**照片留在你自己的文件夹里，软件只是它的一个视图。**

指定一个本地文件夹作为「库」，Gallery 读取它、而不接管它。照片始终是普通文件，用访达、
Photoshop 或任何别的工具都能打开；即使卸载 Gallery，照片与元数据依然完整可读。

- **实时浏览**：打开文件夹即可看，磁盘上的增删改立刻反映到界面。
- **元数据**：读取 EXIF / IPTC / XMP；拍摄时间与位置可以改并写回照片文件本身。
- **事件**：给照片标上「这是哪次旅行 / 那场演出 / 哪部影片」，再按事件挑照片、筛选、排序；一个事件
  可以指定一张封面，照片改名或移动时封面跟着走。事件记在 Gallery 自己的库里，**不写进照片文件**。
  「演迹」导出的演出列表可直接导入；影片还能**按番号或链接（JavDB、YouTube、B 站）抓取封面与
  资料**，按住 `⌥` 点封面即可打开影片网站。
- **不碰你的照片**：扫描、索引、预览一律只读。会动文件的只有你亲手触发的几条命令，
  每一次都记账、都能 `⌘Z` 撤销。

## 环境要求

- macOS 13 或更高版本
- [uv](https://docs.astral.sh/uv/) —— 负责 Python 版本与依赖，不必自己装 Python
- [exiftool](https://exiftool.org/) —— 可选；读 IPTC / XMP 与写回元数据时需要它

```bash
brew install uv exiftool
```

## 从源码运行

```bash
git clone https://github.com/ShaoxianSHI/Gallery.git
cd Gallery
uv sync                     # 创建虚拟环境并装好依赖（含 Python 3.12 本身）
uv run gallery              # 启动
```

也可以直接打开指定的文件夹，或者只看版本号：

```bash
uv run gallery ~/照片
uv run gallery --version
```

## 打包成 .app

```bash
uv sync --group build
uv run --group build python scripts/build_app.py                    # 产物在 dist/Gallery.app
uv run --group build python scripts/build_app.py ~/Applications     # 直接放进「应用程序」
uv run --group build python scripts/build_app.py --dry-run          # 只看将要执行的命令
```

自包含版把解释器、Python 依赖与 Qt 插件一起编译进包里（约 104 MiB，首次编译要几分钟），
拷到别的 Mac 上双击即可运行。另有开发版，一秒生成、启动器指向本仓库的 `.venv`：

```bash
uv run python -m gallery.macos_app
```

## 基本用法

启动后用 `⌘O` 选一个文件夹当库。常用操作：

| 操作 | 快捷键 |
|------|--------|
| 打开大图 / 上一级（大图页上就是退回网格；已在最外层时取消选中） | 双击、`回车` / `Esc` |
| 上一张 / 下一张 | `←` / `→` |
| 适应窗口 / 实际大小 / 缩放 | `⌘0` / `⌘1` / `⌘+`、`⌘-` |
| 搜索（文件名、相册、元数据） | `⌘F` |
| 在搜索与「筛选当前视图」之间切换 | 点搜索框右边那枚双向箭头按钮（每按一次掉个头） |
| 撤掉最后一条筛选条件 | `⇧Esc` |
| 重命名（照片或相册） | 网格下再点一次已选中的缩略图，或 `⌘R` |
| 移到废纸篓 | `⌘⌫` |
| 编辑拍摄时间与位置 | `⇧⌘I` |
| 撤销上一次写操作 | `⌘Z` |
| 在默认应用里打开 / 在访达中显示 | `⇧⏎` / `⌘⏎` |
| 打开照片所属影片的网站 | 按住 `⌥` 点那张照片（网格或大图页） |
| 拷贝 / 拷贝路径 / 粘贴 / 全选 | `⌘C` / `⇧⌘C` / `⌘V` / `⌘A` |
| 在原位置造一份副本 | `⌘D` |
| 新建相册 | `⇧⌘N` |
| 显示元数据面板 | `⌘I` |
| 铺满窗口（菜单栏与 Dock 都留着） | 双击标题栏，或 `⌃⌘F` |
| 关闭窗口（应用还在）/ 退出 | `⌘W` / `⌘Q` |

- **三种浏览方式**（「视图 → 浏览方式」）：**全部照片**把整库平铺在一起；**相册**是一个子文件夹
  一个相册，双击进入；**日历**按拍摄时间分年 / 月 / 周三层（`Y` / `M` / `W` 切层，`←` / `→`
  翻页，`T` 回到今天）。
- **搜索与筛选**用的是同一套条件语法（`#相机 Canon`、`#ISO >800`、`#拍摄时间 2024-05`，
  不带 `#` 就是按文件名），区别只在**管到哪儿**：**搜索**横跨整个库，一提交整层就被结果接管；
  **筛选**（点搜索框右边那枚双向箭头按钮切过去）只收窄**当前这一层**，视图本身不动，条件一路
  跟着你换层走。条件会作为胶囊摆在面包屑那一行的右端，点文字是改、点 `✕` 是撤掉。
- **分组与排序**在「视图」菜单里：可按拍摄时间、相机、镜头、国家 / 城市、关键词、文件格式等
  字段把照片分成组卡片，也可按这些字段排序。
- **放映**：点右上角那颗三角按钮（在「用外部应用打开」左边），按网格里的顺序自动播放当前
  这一层的照片，每 3 秒一张、切换时先淡出再淡入。放映中 `←` / `→` 可手动翻，`空格` 暂停 / 继续，
  `Esc` 回到网格。已经在大图页时，从正在看的那一张开始；当前层没有照片会直接说明。
- **会动文件的命令**只有右键菜单里的几条，全部只在你亲手触发时执行，每一次都记账、都能 `⌘Z`
  撤销（粘贴与新建相册只记账、不进撤销栈）。
- **导入**（「文件」菜单里，「最近打开」下面）：
  - **导入影片**：分 **Bilibili**、**YouTube**、**JavDB** 三个入口，打开的是同一张面板，
    提示与例子跟着来源走。每行一个编号或链接，一次可以贴一批（换行、逗号、空格分开都行）；
    三个来源混着贴也认：**番号**（JavDB）、**YouTube 的地址或 videoId**、**B 站的地址或 `BV` 号**。
    Gallery 会拿这些资料（标题、发行日期、作者、类别……）建成影片，并把封面**作为一个新文件**
    存进当前这个文件夹（不会覆盖已有的同名文件）。之后按住 `⌥` 点那张封面就会在浏览器里打开
    对应的影片网站。番号那一栏打开用的网站前缀可以在 `config.toml` 的 `movie_site` 里改
    （默认 `https://jable.tv/videos/`）。
  - **导入演出 → 从「演迹」导入…**：把「演迹」导出的 `.xlsx` 演出列表建成事件。这一层现在
    只有一个来源，单独留着是为了以后能加别的来源。
  - 两件都只写 Gallery 自己的库与那几个封面文件、不碰你已有的照片；重复导入同一部影片 / 同一场
    演出会先问你跳过还是全导。
- 磁盘上的变化会实时反映到网格：在访达里拖进一批照片、改名、删除，界面自己跟上。
- 用 `.app` 跑的时候，**在 Dock 图标上右键**也能看到最近打开过的库（「文件 → 最近打开」那一份
  交给系统记了一份，应用没运行时也在）。它跟着系统设置里的「最近使用的项目」走
  （设成「无」就什么都没有）。
- **「最近打开」这份名单归你管**：菜单底部的「清除最近打开」一次清空。**当前正开着的那个库会
  留下**（它此刻就开着，本来就该在名单里），两处一起变 —— Dock 里那份也跟着。动的只是我们记着
  的那几行，文件夹本身一个字节都不碰。

## `.gallery/` 目录

首次打开一个文件夹时，Gallery 会在库根目录下建一个 `.gallery/`，存放自己的运行时数据：

```
<库根目录>/
├── 你的照片文件夹/          # Gallery 不做任何整理
└── .gallery/
    ├── config.toml         # 库级配置（相册封面、界面偏好、影片网站前缀）
    ├── index.db            # 索引缓存，删掉可重建
    ├── events.db           # 事件（旅行、演出、影片……）、它们的封面与照片的关联，删掉就没了
    └── journal/            # 写操作日志，用于回溯与撤销
```

`index.db` 与 `journal/` 都是缓存：整个删掉，重新扫描就能恢复等价状态。`config.toml` 建议自己留个
副本（相册封面、界面偏好）。

**`events.db` 不是缓存**：事件是你自己填的，删掉之后没有任何办法能重建回来 —— 所以清缓存与
重建索引都不会碰它，Gallery 升级时也只往上加列、绝不重建它那张表。备份它请连 `events.db`
一起带上。

## 日志

Gallery 自己的经过（含出错时的完整调用栈）写在一份日志里，**它不在库里**，在应用数据目录下：

```
~/Library/Application Support/Gallery/logs/gallery.log          # macOS
$XDG_DATA_HOME/Gallery/logs/gallery.log（默认 ~/.local/share）   # Linux
```

带轮转：单份超过 1 MiB 就换一份，最多留三份。界面说「详情写进了日志文件」时指的就是它 ——
报告问题时把它带上，比自己复述一遍有用。

## 支持的照片格式

| | 格式 |
|---|---|
| 元数据**读 + 写**（EXIF / IPTC / XMP 都存得下） | JPEG、PNG、TIFF |
| 元数据能写，但容器存不下 IPTC 那一组地名（只落 XMP） | HEIC / HEIF、WebP |
| 只能写 XMP 里的三层地名（EXIF 与 IPTC 都放不下） | GIF |
| 只能看，改不动 | BMP |
| **尚不支持** | 常见 RAW（CR2/CR3、NEF、ARW、DNG）与视频 |

## 已知限制

- 只有**拍摄时间**（含时区）与**位置**（坐标、城市 / 省州 / 国家）可以写回；相机、镜头、
  光圈 / 快门 / ISO 这些拍摄事实一律只读。
- 没装 exiftool 时退回 Pillow 读基础 EXIF，IPTC / XMP 相关的字段不可用，「编辑元数据」也不出现。
- 地点按坐标反查用的是随包分发的离线城市库（约 380 KB），**不联网、不上传坐标**。
