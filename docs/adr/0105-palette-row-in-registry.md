# ADR 0105：配色的那一行进清单 —— 改过的、删掉的、「+」新增的都记住

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0098（背景图与遮罩）、0100（文案口径）、0103（配色是一个对象）、
  0104（配色的删除出口）
- 相关代码：`src/gallery/core/backdrops/store.py`、`src/gallery/core/backdrops/recipe.py`、
  `src/gallery/ui/dialogs/backdrop.py`、`src/gallery/ui/window/settings_flow.py`

## 背景

0103 / 0104 之后，那一行色板只在对话框里活着：新增的、改过的、删掉的都随对话框一起消失，
重开又是八套预设原样。而颜色是用户在对话框里一个个挑出来的，**重建不出来** —— 按 0098 的
判据（名字是用户填的，重扫重建不出来）它该进 `<app data>` 的清单，现在却连缓存都没进。

## 决策

### 1. `backdrops.json` 里多一份 `palettes`：它就是这一行

每一项是一个格子，次序就是那一行的次序：

```json
{"kind": "preset", "key": "ink-01-mist", "title": "雾蓝 · 藕紫", "colors": ["#fbfbf9", "..."]}
{"kind": "custom", "key": "palette-3f2a9c1b7d4e", "title": "自定义", "colors": ["#336699", "#b06a3b"]}
```

`kind=preset` 的 `key` 是预设名，`kind=custom` 的是「+」新增那一套的 id。**整行替换**写入：
加、改、删都是一次提交，不做增量。

### 2. 没动过的预设按常量取回

读一条 `kind=preset` 时，若它的 `colors` 与 `PALETTES_BY_NAME[key]` 逐项相同，就**返回那个
常量**，不拿颜色重算：预设的停点并不均匀（`0, .30, .52, .74, .88, 1`），形状参数也各不相同，
重算会把「打开一次再关掉」变成一次静默的改动（与 0103 决策 4 同一条理由）。

### 3. 版本 2，v1 照样读

只认 `REGISTRY_VERSION` 会把老文件整份读成空 —— 那等于把用户存过的背景（名字与配方）全丢掉。
`READABLE_VERSIONS = (1, 2)`；v1 里没有 `palettes`，读出来就是「没动过」，界面用八套预设。
逐条校验：一条坏配色只丢它自己，与背景那几条同一套待遇。

### 4. 关掉生成对话框就写，不必先存背景图

配色不是「这一张图的附件」。调好一套之后用户可能只是关掉对话框，那一行也该留住。写失败照旧
报错（横幅），不静默吞。

### 5. 上限按「+」新增的几套算，删预设不腾位置

那一行最多八格预设 + 三格自己的配色。删掉一套预设**不**让「+」变得可点：那样能加到十二格，
而「恢复预设配色」要把八套放回去时就放不下了。

### 6. 「恢复预设配色」

八套预设回到代码里的样子（改过的颜色与删掉的格子都回来），`kind=custom` 的那几套不动。预设
都还原样时这个入口收起 —— 没有可恢复的东西，就不该有一个按了没反应的按钮。

一行与 `default_palette_row()` 逐项相同时**不写 `palettes`**：用户没动过，清单里就不该留一份
会过时的副本 —— 以后版本新增的预设才出得来。

### 7. 删除不弹确认

按钮已经点名了「这一套配色」（0100），删除只写清单；已保存的背景图不受影响（配方里整份写着
颜色）。与 0104 一致：可重来的编辑不该多一步确认。

## 后果

- 改过一次预设，它以后就是改过的样子 —— 那是用户状态，不是缓存。想回到原样走「恢复预设配色」。
- `Palette` 仍是「配方要的那一套颜色 + 形状」；`PaletteEntry` 是清单里的一个格子。两者的换算
  只在 `PaletteEntry.palette()` 与对话框那一侧的两个入口上。
- 「+」新增那一套的 id **不能由内容算**（改名、改色之后还得是同一格），所以由 `palette_id()`
  现生成。
- 重开对话框时选中的是第一格，与 0103 一致。
- 数据安全边界没变：只写应用数据目录里的清单，用户的照片一个字节都不碰。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 只存「+」新增的，预设永远原样 | 用户改了预设、关掉、再打开又变回原样 —— 他挑的颜色就这么没了；要留住只能改用「+」重调一遍 |
| 清单版本号不动，`palettes` 当可选键 | 文件结构确实变了，版本号是「读不懂就回空」唯一能生效的地方 |
| 版本升到 2 就只认 2 | 老文件的背景会整份消失（名字与配方），那是数据丢失，不是兼容 |
| 配色单独一个 `palettes.json` | 它和背景清单是同一份用户数据、同一处读写、同一次提交；拆开就有两份要一起改的东西 |
| 每条配色增量 add / update / remove | 这一行本来就整体有意义（次序、哪几格在）；整行替换只有一处写，少一类「忘了同步」的缺陷 |
