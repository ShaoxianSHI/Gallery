# ADR 0099：「设置」菜单按话题分三段，主题与背景拆开

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0073（顶层「设置」菜单）、0097（两档自定义背景色）、0098（两档背景图）
- 相关代码：`src/gallery/ui/window/settings_flow.py`、`src/gallery/ui/dialogs/backdrop.py`、
  `src/gallery/ui/dialogs/appearance.py`、`src/gallery/ui/main_window.py`

## 背景

0073 建这张菜单时只有六项，分三组。到 0098，它长到九个顶层条目、最深四层，而毛病不是
「项太多」：

1. 三根分隔线切出四段，但四段**不能命名** —— 应用级 → 库级 → 又回应用级 → 维护。同一类东西
   被劈在两处，中间夹着别的。
2. 「外观」一项承载九行、四段、两件事：主题档位与背景图。它是整张菜单最深的入口。
3. 库级与应用级混排，而 0073 的核心判据（换库该不该重来）在菜单里**看不见**。
4. 影片网站前缀与缓存上限只对当前这个库有效，用户无从判断。
5. 「清空缩略图缓存」在「文件」菜单，管同一个东西的「缓存上限」在「设置」里。

## 决策

### 1. 分组按「用户能说出口的话题」，不按存储作用域

三段，每段一句话念得出来：**显示与播放 / 影片与缓存 / 维护**。

```
设置
├─ 主题 ▸              跟随系统 / 浅色 / 深色
├─ 背景 ▸              浅色背景 ▸ · 深色背景 ▸ · 自定义背景色… · 生成背景… · 用照片做背景… · 管理背景…
├─ 动画速度 ▸          慢 / 中 / 快 / 关
├─ 放映间隔 ▸          3 / 5 / 8 / 15 秒
├─ 影片网站 ▸          Jable.tv / MissAV / 自定义…
├─ 外部应用顺序…
├─ 启动时打开上次的库 ✓
├────────────────────
├─ 缓存上限 ▸          1 / 2 / 5 / 10 GB / 不限制
├─ 清空缩略图缓存
├────────────────────
├─ 打开日志文件夹
└─ 关于 Gallery
```

作用域仍然按 0073 各存各的（应用级写 `state.json`，库级经 `Library` 写 `config.toml`），
但它**不再是菜单的分类依据**：换库之后勾选态自己会跟着变，用户不必先知道这件事才能用菜单。

### 2. 「主题」与「背景」拆成两项

「外观」只剩三档主题，于是它改名「主题」。背景色与背景图归新的「背景」，里面按
「这一档用哪张 → 纯色用哪一种 → 从哪儿弄一张新的」排列。层级不增反降：`浅色背景 ▸`
从第 3 层升到第 2 层。

### 3. 缓存的上限与清扫挨着放

「清空缩略图缓存」从「文件」菜单搬到「缓存上限」下面：一个管预算、一个管清扫，管的是同一批
文件。它的可用性仍由 `_update_action_states` 那一处算（还盯着正在跑的清理任务），
**不进 `_library_setting_actions`** —— 两个写者会互相覆盖。

### 4. 「关于」与「打开日志文件夹」留在维护段

macOS 的惯例是把「关于」放进应用菜单，但本项目的菜单栏是自建的（0073 决策 1），且
Qt 认的是英文菜单名，中文标题不会自动归位。这一轮不动它；将来要搬只需给那一枚 `QAction`
设 `AboutRole`。

### 5. 「改完立刻看得见」的东西不进这张菜单

`显示文件扩展名`、`缩略图大小`、`排序`、`分组`、`浏览方式` 留在「显示」：它们改完立刻看见
画面变化。**即时性决定它住在哪张菜单，作用域只决定它存在谁的文件里**。这条判据同时解释了
为什么库级的排序在「显示」、而库级的缓存上限在「设置」。

## 后果

- 结构回归测试跟着改：`tests/ui/test_settings_menu.py` 锁定三段的内容与分隔线位置，
  并锁「清空缓存不再在文件菜单里」。
- `SettingsFlowMixin` 的宿主耦合面多一条 `_clear_cache_action`（`tests/ui/window/test_host_contract.py`）。
- 「管理背景」对话框重做：列表与行内输入框跟对话框同一套底色，改名改成行内编辑（不再弹
  系统的输入框），删光之后留一行占位，且跟随主题切换。它有自己的一组测试。
- 存储、写回、撤销、监听一律不动：这张菜单只写 `state.json` 与库的 `config.toml`，
  **用户的照片一个字节都不碰**。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 用「这个照片文件夹 ▸」把库级三项套起来 | 指示代词不成类目名；「照片文件夹」读起来像一个文件夹操作，而它下面装的是网址前缀与缓存档位。作用域不是用户能说出口的话题 |
| 把设置搬进一个设置窗口 | 0073 留的触发条件是「项多到需要分组说明」。现在 24 项、两级，先把分组理干净；等项数再翻一倍再说 |
| 用置灰的 `QAction` 当分组标题 | 在 macOS 菜单里读起来像坏掉的项 |
| 继续把背景图挂在「外观」里 | 一个子菜单同时表达「主题档位」与「用哪张图」，两件事的默认值、生效条件、失败回退都不一样 |
| 影片网站与缓存上限留在顶层、只加分隔线 | 分隔线只能切段，不能说明「为什么这几项在一起」；而「影片」与「缓存」恰恰是两个说得出口的话题 |
