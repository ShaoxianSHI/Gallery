# ADR 0110：「设置」菜单按话题再切成五段，不加深层级

- 状态：已接受
- 日期：2026-10-31
- 相关 ADR：0099（按话题分三段）、0109（放映背景音乐）
- 相关代码：`src/gallery/ui/window/settings_flow.py`、`tests/ui/test_settings_menu.py`

## 背景

0099 把这张菜单理成三段。之后又加了「语言」（0106）与「放映背景音乐 / 背景音乐音量」
（0109），顶层长到 16 行、9 个子菜单，而第一段「显示与播放」独占 7 行。分隔线只有两根，
「界面」与「放映」两件事混在同一段里。

一个自然的下一步是把话题收成四个子菜单（界面 / 放映 / 外部应用 / 缓存）。那会把
`设置 → 界面 → 背景 → 浅色背景 → 某张图` 推回第 4 层，与 0099 决策 2 降低层级的方向相反，
而且换一次主题要多悬停两级。

## 决策

### 1. 只加分隔线，不嵌套

五段，每段一句话念得出来：**界面 / 放映 / 外部应用与启动 / 缓存 / 维护**。

```
设置
├─ 主题 ▸
├─ 语言 ▸
├─ 背景 ▸
├─ 动画速度 ▸
├────────────────────
├─ 放映间隔 ▸
├─ 放映背景音乐 ▸
├─ 背景音乐音量 ▸
├────────────────────
├─ 影片网站 ▸
├─ 外部应用顺序…
├─ 启动时打开上次的库 ✓
├────────────────────
├─ 缓存上限 ▸
├─ 清空缩略图缓存
├────────────────────
├─ 打开日志文件夹
└─ 关于 Gallery
```

### 2. 哪几项归同一段

- **界面**：主题、语言、背景、动画速度 —— 只改眼前的呈现，改完立刻看得见。
- **放映**：放映间隔、背景音乐、音量 —— 「自动放照片时怎么放」的三个参数。
- **外部应用与启动**：三项都以「打开」为共同话题 —— 点照片交给哪个应用、番号跳到哪个网站、
  启动时打开哪个库。
- **缓存**：上限与清扫管的是同一批文件（0099 决策 3 不变）。
- **维护**：报问题时才去的地方，与 0099 决策 4 一致。

### 3. 存储作用域仍然不是分类依据

应用级与库级照旧各存各的（0073），菜单里不按它切段。换库之后勾选态自己会跟着变。

## 后果

- `tests/ui/test_settings_menu.py` 锁的段数与分隔线位置改成五段；其余用例不动。
- 动作对象、`_settings_actions` 的键名、快捷键、勾选态同步一律不变，宿主耦合面不增。
- 没有新增文案：这一段只有分隔线。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 四个话题子菜单（界面 / 放映 / 外部应用 / 缓存） | 顶层降到 8 行，但背景图那一支回到第 4 层；换主题也要多悬停两级 |
| 把「启动时打开上次的库」单独切成一段 | 一段只有一行，读起来像误摆进去的分隔线 |
| 按应用级 / 库级分两段 | 0099 已经否决过：作用域不是用户能说出口的话题 |
| 建设置窗口 | 0099 的条件是「项数再翻一倍」；现在是 16 行，先把分段理干净 |
