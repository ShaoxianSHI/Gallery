# ADR 0097：「外观」里可以自己挑两档背景色

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0005（整个窗口共用一块底色）、0073（设置菜单：应用级与库级各存各的）、
  0096（底色只在窗口上铺一次）
- 相关代码：`src/gallery/core/library/session.py`、`src/gallery/ui/theme.py`、
  `src/gallery/ui/dialogs/appearance.py`、`src/gallery/ui/window/settings_flow.py`、
  `src/gallery/ui/main_window.py`

## 背景

底色已经统一成一块（0005），铺它的也只剩窗口一处（0096）。但那一块永远等于系统调色板的
内容区色：白、`#171717`，或者系统给别的什么。用户想换个色调（暖一点的纸色、偏冷的深灰）
没有任何入口。

难点不在「记一个颜色」，在于**正文色不跟底色走**：浅色下是深字、深色下是浅字，都是系统
调色板给的（0005 决策 5）。只换底不换字，那把深色填进「浅色那一档」就成了浅字压浅底 ——
而那种界面不会有任何地方报错。

## 决策

### 1. 两档，各存各的，空表示跟随系统

`Preferences.light_background` / `dark_background`，`#rrggbb`，空串 = 用系统那一档。
**进会话文件**（应用级）：判据跟 0073 的「外观」同一把尺 —— 换一个库不该换一套配色。

### 2. 每一档只收自己那一侧

浅色那一档要亮于 HSL 的 `L = 0.5`，深色那一档要暗于它（`session.normalize_background`）。
挑反了对话框里说清楚、**不改任何值**；手改坏的文件读出来当「没设过」，不是报错 ——
和这份文件的其它字段同一套待遇。

### 3. 哪一档生效由**系统**决定，不由挑的颜色决定

`current_theme()` 先按调色板的 `Base` 判深浅，再问用户给这一档挑了没有。于是 `is_dark`
不会因为挑了颜色而翻，正文、链接、提示 / 错误、浮层那几档全都不必另算一份。

### 4. 下发仍走 `ThemeWatcher`

`set_backgrounds()` 设完立刻 `refresh()`（`apply_theme` + `changed`）——**与系统换外观走的
是同一条路**，自己画底色的控件（日历、横幅）因此不用多接一个信号。启动时在 `_build_ui`
里先把存着的那两档装上，第一帧就是对的。

### 5. 入口在「外观」子菜单末尾，单独一段

那三个单选（跟随系统 / 浅色 / 深色）决定「用哪一档」，这一项只给这一档挑个底色。
它不是第四种外观，所以不进 `QActionGroup`、也没有勾选态。

## 后果

- 换底色的成本是一次整树下发（与系统换外观相同，毫秒级）；`#rrggbb` 进会话文件，
  两档各一项。
- 输入面、对话框、菜单、日历、横幅全都跟着走：它们读的都是 `AppTheme.background`
  （0035 / 0096），没有第二份颜色。
- 代价是**两档各自被限制在自己那一侧**：想要「深色模式下用浅色底」得先在「外观」里切到
  浅色。这是 3 号决策换来的 —— 反过来要同时翻正文、链接、提示、浮层四族派生色。
- 会话文件里多两个键：老版本读不懂它们，但那份文件本来就是「读不懂就回默认」。

## 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 挑了颜色就让 `is_dark` 跟着翻 | 正文、链接、提示 / 错误、浮层那一档全按深浅算，一翻就要同时翻四族；而它们的正确值是「系统那一档」算出来的 |
| 一个颜色管两套 | 浅色与深色共用一个底，必有一边难看（近白的底配深色模式的浅字） |
| 存进 `.gallery/config.toml` | 外观是应用级的（0073），换库不该换底色；而且没打开库时也得能预览 |
| 每档各一枚「恢复默认」 | 两档一起清就够了；多一枚按钮换不来什么 |
| 只给几个预设色块 | 用户要的是「自己选」；而两档 + 一侧的约束已经把能挑坏的情况挡住了 |
| 让用户随便挑（不做左右两侧的限制） | 那就是浅字压浅底，而且这种界面不会有任何地方报错 |
