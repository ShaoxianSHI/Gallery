# ADR 0103：配色是一个对象 —— 双击编辑它的颜色，「+」新增一套

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0035（圆角轮廓）、0098（背景图与遮罩）、0100（文案口径）、
  0101（自定义配色）、0102（多色配色，交互由本篇取代）
- 相关代码：`src/gallery/core/backdrops/recipe.py`、`src/gallery/ui/dialogs/backdrop.py`

## 背景

0102 把两件事挤进了同一个「+」：**新增一套配色**与**给当前这套再加一个颜色**。结果是
「点加号，色块变了」，用户既不知道自己是在改哪一套，也改不了八套预设里的任何一套 ——
预设是写死的常量，界面上只能选、不能动。

「配色」本身是一个有身份的东西（有名字、有一串颜色、会被配方整份记住），所以编辑的入口
应当挂在**那一格**上，而不是挂在一个全局的加号上。

## 决策

### 1. 单击选中，双击编辑那一格的颜色

色板里每一格就是一套配色。**双击**它打开「编辑颜色」对话框；确定之后替换掉**这一格**的
配色，位置不动。预设也改得 —— 改完它就成了一套自定义配色（配方里的 `preset` 是
`ink-custom`，名字仍用原标题，见决策 4）。

编辑**不新增一格**：用户改的是他双击的那一格，不是「另存一份」。

### 2. 「+」= 新增一套配色

点「+」先弹出同一张编辑对话框，起点是一个由浅到深的六档（`palette_from_color`，与 0101
的新建路径一致）；确定之后在这一行末尾多出一格并当场选中，取消则什么都不加。

最多新增三套（八套预设之外）：那一行放不下的更多格子没有意义。到上限时「+」按不动并说明
原因。**编辑已有配色不受这个限制** —— 它不占新位置。

### 3. 编辑对话框：一份颜色清单

逐行一个色块：点色块换色，每行一个「移除」，下面一个「添加颜色…」。**至少两个**（少了就
没有渐变）、**最多八个**（再多在 16:10 的淡背景上也分不出层次）。

确定之后，这些颜色**按次序均分**整条浓度轴、原样使用：

```
颜色  c0   c1   c2   c3
位置 0.0  0.33 0.67 1.0
```

0102 那套「先把颜色往白色里兑、再分带」的推导没有了：用户是在**对着色块**改，看到什么就该
得到什么。起点（决策 2）仍然是浅色，所以不动手的默认样子依旧是一张淡晕染。

### 4. 原样确认不替换

如果交回来的颜色与原来逐项一致，这一格保持原样（连预设都不变成自定义）。这样「双击看一眼
再保存」不会悄悄把 `ink-01-mist` 换成一条看起来一样、实际停点略不同的自定义配色。

### 5. 每一格显示自己的渐变

色块底色改成一整条 `qlineargradient`（预设也显示），顺序就是浅 → 深。边框仍按 0035 的办法
预先与**这几个颜色的平均色**合成成不透明 —— 一圈 1 点宽的边框跨不出那么大的色差。

## 后果

- 0102 的「追加颜色」与右键「重新挑选」两条交互取消；`palette_from_colors` 从「兑白 + 分带」
  改成「原样均分」，`palette_from_color` 只剩一个用途：新建时的起点。
- 编辑一套预设之后，它在本对话框里就是自定义配色：`palette_of(recipe)` 认不出来，保存时的
  默认名字由对话框把标题当 `fallback` 递进去（0101 已经这样做了）。
- 停点会被均分：预设原来的停点并不完全均匀（`0, .28, .52, .74, .88, 1`），所以改过一个颜色
  之后整条的分布会略微变匀。原样确认不动它（决策 4），避免「什么都没改却变了」。
- 数据安全边界没变：仍然只写缓存与清单，用户的照片一个字节都不碰。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 「+」既是新增配色又是加颜色（0102） | 两个动作挤在一个入口上，用户不知道自己在改哪一套；而且预设永远改不了 |
| 编辑预设等于「另存一份新配色」 | 会凭空多出一格；用户双击的是这一格，改完就该还在这一格 |
| 直接改 `PALETTES` 里的常量 | 全局可变状态；而且配方只记名字，已存背景会跟着变 |
| 编辑时保留原来的停点位置 | 界面给的是一份**颜色**清单，不是位置清单；要保留就得再引入「位置」这个用户看不见、却会影响结果的东西 |
| 允许一套配色只有一个颜色 | 一个颜色没有「浅→深」，生成出来是一块纯色，与「设置纯色背景」重复 |
