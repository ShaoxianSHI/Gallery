# ADR 0043：鼠标后侧键 = 「上一级」

- 状态：已接受
- 日期：2026-10-06
- 相关 ADR：0037（窗口那一圈：三个键一律显式写死）、0041（层级栈：`Esc` = 弹栈顶一帧）、
  0040（筛选：`Esc` 只管位置不管条件）
- 相关代码：`src/gallery/ui/side_buttons.py`、`src/gallery/ui/main_window.py`
  （`_build_actions` 里连的那一行与 `_on_back_button`）、`src/gallery/ui/write_ops.py`
  （`_on_rename_active_changed` 里记的那一格）、`tests/ui/test_side_buttons.py`

## 背景

有些鼠标拇指侧有两个键，靠前的一个与靠后的一个。全世界的软件都拿**靠前那个**当「返回」
（浏览器、访达、预览）。用户的要求：「有些鼠标有前后两个侧键，把后侧键和 `Esc` 的操作绑定。
这也符合一般软件管理，后侧键表示返回。」

而 Gallery 的「返回」**已经有一条命令**了：`Esc` = 弹栈顶一帧（ADR 0041 决策 1；大图页与网格页
共用同一条，决策 6）。所以这不是一个新功能，是给那条命令补一个鼠标上的入口。

麻烦的是**怎么接住这一次按下**。侧键在 Qt 里是一次普通的鼠标按下（macOS 上 `buttonNumber` 4 →
`Qt::BackButton`），落在光标底下那个控件上 —— 而网格是 `PhotoGrid(QListView)`，它把这一次按下
**收下并 accept**，事件不会冒到窗口。实测（摘掉过滤器，只在窗口上挂一个探针）：

| 落在哪儿 | 事件走到哪 |
|----------|------------|
| 网格的视口 | **哪儿也没到**（滚动区吃掉了） |
| 大图页的视口（`QGraphicsView`） | 冒到 `MainWindow.mousePressEvent` |
| 标题栏那一段（普通子控件） | 冒到 `MainWindow.mousePressEvent` |

最常用的那一页恰好是**唯一接不住**的一页，而症状是「在照片上按侧键完全没反应，在窗口顶上按才
有用」，界面上看不出任何理由。

## 决策

### 1. 触发的是 `Esc` 那同一个 `QAction`

后侧键不另写一份「返回」：触发的是 `_up_action`。于是启用状态、菜单里那一条、真正干活的
`go_up` 都只有一份，**包括那一刻它是禁用的情形**（已经退到库根）：后侧键跟着一起什么也不发生。
这与 ADR 0041 决策 6 是同一个理由 —— 两条同键命令必然有一个按不到（症状是「有时按了没反应」，
而哪一处按不到取决于加载顺序）。

### 2. 「这一下把改名的输入框收掉了」时不触发

Qt 是**先把焦点给鼠标底下的控件、再把事件交给事件过滤器**的（实测顺序：
`focusOut` → 改名提交 → 过滤器）。于是改到一半按后侧键时，等这一层看见这一下，输入框**已经收起**、
那条动作**也已经重新亮起来** —— 直接触发就是「既把名字提交了，又把人带着退一层」，而这一按的
意思明明只是「点别处」（与左键完全一样）。

所以 `MainWindow._on_rename_active_changed` 在输入框收起时记一格，条件是**此刻按着的键里有后侧键**
（`QApplication.mouseButtons()`）—— 「收掉它的是不是这一下」只有那一处知道；记号由
`_on_back_button` 消费掉一次，于是回车提交之后按后侧键仍然照常退层。

名字照提交（焦点一走就提交，是访达那一套既有行为，红线 1 那一格：改名必记 journal、可 ⌘Z）——
**这一层管不了也管不着**：提交就发生在 `focusOutEvent` 里，比过滤器早。

### 3. 接在 `QApplication` 上的事件过滤器

`ui/side_buttons.py` 的 `SideButtonFilter`，而不是窗口的 `mousePressEvent`，也不是每一页各接一次。
代价是**每个事件都多走一趟 Python**（实测每个事件 +0.4 µs：两万次鼠标移动事件 37.5 → 45.7 ms；
一次框选里每秒几千个事件，量级在噪声里）。换来的是只有这一处记得这件事 —— 每一页各接一次会漏，
而漏掉的症状是「那一页的后侧键没反应」，没有任何报错。

### 4. 只认「落在本窗口顶层里」的那一次按下

编辑元数据那个模态对话框与弹出菜单都是别的顶层，它们开着的时候后侧键不归这一扇窗口管 ——
那扇对话框有自己的 `Esc`，后侧键不该越俎代庖去弹栈顶。`WindowHost` 一次只留一扇窗口，但判据按
「有几扇」写，不按「现在恰好有几扇」写。

### 5. 前侧键不接

它没有可绑的动作：层级栈只有 push / pop，没有「前进」那一份 redo（ADR 0041）。给一个不存在的
概念绑键，等于让它按下去什么也不发生之外，用户还得另外去弄明白为什么这一枚键是哑的。

## 后果

- 侧键在网格、大图页、日历页、标题栏上都退一层，与 `Esc` 完全一致（含退到库根之后不再动）。
- **改名字输入框开着时按后侧键：名字提交、层不动**（决策 2）。这与在照片区点一下左键的后果相同。
- 模态对话框开着时后侧键不生效（对话框自己的 `Esc` 仍然关它）。
- 菜单里「上一级」那一行仍只写 `⎋`：侧键是硬件上的一枚按钮，没有对应的键位可写，而
  `menu_style.show_key` 只画 `QAction` 上有的键（ADR 0021）。
- 搜索胶囊正输入时按后侧键仍然**退一层**（条件不动，与 ADR 0040 决策 11 的分工一致：
  「上一级」管位置，`⇧Esc` 管条件）。搜索框失焦**不提交**（`SearchField.edit_ended`），所以这一下
  没有「顺手提交了条件」那一层后果。

## 被否决的方案

- **在 `MainWindow.mousePressEvent` 里接**（最省事的一处，标题栏那三个鼠标覆写旁边）：网格的视口
  把这一次按下收下了，压根冒不到窗口。
- **每一页各挂一次过滤器**：能work，但「新加一页忘了接」是静默失效，而且要改四个文件 ——
  同一件事四份写法正是本仓库反复治的那类病。
- **把侧键翻译成一个合成的 `Esc` 键事件再发出去**（这样「谁抢了 `Esc`」那套分派原样复用）：
  实测与真按 `Esc` **不等价** —— 快捷键表在事件送达控件之前就匹配掉了 `Esc`（那条动作注册在
  窗口上），`RenameEdit` / `SearchEdit` 抢 `Esc` 的那套压根轮不上；它还要额外回答「焦点不在本窗口
  时发给谁」，而那正是决策 4 已经解决的问题。
- **让侧键在改名字那一刻去「取消改名」**（那才是 `Esc` 在那一刻做的事）：提交就发生在输入框的
  `focusOutEvent` 里，早于事件过滤器 —— 等这一层看见这一下，名字已经在磁盘上了（决策 2 那一格）。
- **在系统设置里读一个「鼠标侧键做什么」的偏好**：本软件没有偏好设置这一层（界面偏好全在
  `.gallery/` 下的配置里，且只有库级那几项），为这一条键新建一层不值得。
