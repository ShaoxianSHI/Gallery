# ADR 0101：背景图可以自己挑配色，菜单那几项同时改名

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0097（两档背景色）、0098（两档背景图）、0099（设置菜单分段）、
  0100（用户可见文案的口径）
- 相关代码：`src/gallery/core/backdrops/recipe.py`、`src/gallery/ui/dialogs/backdrop.py`、
  `src/gallery/ui/window/settings_flow.py`

## 背景

生成背景图时只能在八套预设配色里挑。预设覆盖了雾蓝、蜜桃、薄荷、灰阶这些常见方向，
但用户想要的是「和我这张照片的底色接近的那种」—— 而预设表是写死的。

同时「背景」子菜单里那几个名字不齐：`自定义背景色…` 说的其实是**纯色**（与图片并列的另一种
来源），`用照片做背景…` 与 `生成背景…` 一个带「做」一个不带，而 `管理背景…` 管的是两者共同的
缓存。

## 决策

### 1. 「+」那一格：一个颜色换一套同色系的晕染

生成对话框的色板末尾加一格**不填颜色、只有加号**的圆角矩形。点它弹系统取色器，挑完就多出一格
填着那个颜色的色块并当场选中；再点「+」换的是同一格，不会越点越多。

推导在核心层：`palette_from_color(color)` 把用户选的颜色按固定停点往白色里兑，
`[0.06, 0.14, 0.26, 0.40, 0.52, 0.60]` 是每个停点里原色占的比例。

- **最深只到 60%**：背景图压在正文底下，再浓就是一块深色（0098 的遮罩管得住亮度，
  管不住「整张图一个颜色」）。
- **停点越靠后越浓**：于是它仍是一张有层次的晕染，而不是一块纯色底。
- **颜色整份写进配方**：预设名是 `ink-custom`，但 `Recipe.colors` 本来就是完整的调色板
  （0098 决策 2），所以清掉缓存、换台机器都能按颜色重算，不需要新的字段、也不升 `VERSION`。
- **不进 `PALETTES_BY_NAME`**：那是写死的预设表，塞一个运行期生成的值进去就是全局可变状态。
  代价是 `palette_of()` 认不出它，默认名字由对话框把配色标题当 `fallback` 递进去
  （`name_suggestion(recipe, fallback=…)`）。

### 2. 名字改成同一族，四个来源之间不再切一刀

| 旧 | 新 |
|---|---|
| 自定义背景色… | **设置纯色背景…** |
| 生成背景… | **生成水墨背景…** |
| 用照片做背景… | **使用照片背景…** |
| 管理背景… | 管理背景…（不变） |

「设置纯色背景」说的是「这一档用纯色」，与「用某张图」并列；「生成水墨背景」点名生成出来的
是水墨晕染，而不是任意图案。

子菜单现在只有一根分隔线，在**两档清单**与**四种来源**之间：

```
背景 ▸
  浅色背景 ▸
  深色背景 ▸
  ──────────
  设置纯色背景…
  生成水墨背景…
  使用照片背景…
  管理背景…
```

下半那四项是同一件事的四种来源（纯色 / 生成 / 照片 / 管理已有的），彼此之间再切一刀只会让
「管理背景」看起来像另一类东西。

## 后果

- 「+」那一格沿用 `CHIP_SIZE` 与 5 点圆角，只是底色透明、描的是虚线：**它不表示一种当前配色**，
  选中态只在真的建出自定义配色之后才出现。
- 自定义配色点过一次之后一直留在「+」左边；它参与 `QButtonGroup` 的单选，所以点回预设再点它
  能回来（点击回调在点击时读当前的配色对象，不捕获第一次建出来的那个）。
- 自定义那套的默认名字是「自定义 · #rrggbb」；`name_suggestion` 的默认仍然返回「背景」——
  这是给「配方里认不出配色」的旧数据留的。
- 菜单改名只是文案（0100），但测试与 ADR 0098 / 0099 里出现的路径一并改了。
- 数据安全边界没变：生成仍然只写缓存与清单，用户的照片一个字节都不碰。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 把用户挑的颜色原样当最浓那一档 | 深色会成为整张图的底色，正文压不住；而遮罩只能把亮度压回去，压不住「一块纯色」 |
| 让用户挑两个端点颜色 | 一个入口能说清的事，两个端点还要解释「中间是怎么过渡的」；这一轮先只给一个颜色 |
| 把自定义配色注册进 `PALETTES_BY_NAME` | 全局可变状态，而且清单里的旧配方会让它越积越多 |
| 在 `Recipe` 里新增一个 `palette_title` 字段 | 字段进配方哈希，等于让所有旧缓存失配；而这个名字只影响**新建时**的默认名字，不影响渲染 |
| 「+」那一格建出配色后变成色块、再加一个新的「+」 | 每挑一次多一格，色板会一直变长；而且「新增」这个入口就不见了 |
