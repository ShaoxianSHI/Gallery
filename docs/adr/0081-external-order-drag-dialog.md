# ADR 0081：外部应用顺序改成一个可拖动的对话框（取代 0080 决策 2）

- 状态：已接受
- 日期：2026-10-24
- 相关 ADR：0080（三份次序与存法）、0073（「设置」菜单不新建设置窗口）、0034 / 0067 / 0079
  （那几项应用本身）
- 相关代码：`src/gallery/ui/dialogs/external_order.py`、
  `src/gallery/ui/window/settings_flow.py`、`src/gallery/ui/window/widgets/external_button.py`

## 背景

0080 把次序做成了「设置 › 外部应用顺序 › 图片 / 网格 / 日历」三个子菜单，点某一项就把它
挪到最前。实际用起来的问题是：**一次只能把一项提到最前**，想把 `图片` 那一页的
`ImageGlass` 从末尾挪到第二、或者整体倒过来，得按「想要的倒序」一个个点；每点一次菜单都会
收起，操作次数与距离都不小。而且菜单里只能表达「谁第一」，表达不了「谁在谁后面」。

## 决策

### 1. 设置里一个入口，打开一个三页的对话框

「设置」里的那一项从子菜单改成动作 **「外部应用顺序…」**，打开模态对话框；三页是三个标签页
（图片 / 网格 / 日历）。每页一张 `QListWidget`，**只在页内拖动**（`InternalMove`）：
跨页拖没有意义，那会把两个位置的次序混成一条。

### 2. 保存时才写会话，取消什么都不动

对话框里改的是它自己那份列表；按「保存」才把三页的次序一次性写进会话偏好，按「取消」
（或 ⌘W / Esc）原样不动。**一次写入**，不会出现「第一页存了、第二页没存」的半套状态。

### 3. 拖回内置次序就存空元组

与 0080 决策 5 同一条理由：结果等于默认时不留自定义记录，省掉一次无意义的写盘。

### 4. 每页一个「恢复这一页的默认顺序」

按钮在各自那一页里，只重排当前页；**内置次序里没有的应用**（后来才装的）跟在后面，按它
此刻的位置 —— 恢复默认不该顺手抹掉一项。

### 5. 列表里只放这一页会摆、而且装了的应用

仍是 0080 决策 2 的后半条：名单按 `pages` + `available` 算，**不按 `enabled`** —— 后者还带着
「这一张照片有没有坐标」这类条件，设置不该随正在看哪张照片变。图标也照条目自带的那一份画，
于是第一行看起来就是左半那一下。

## 后果

- 新增 `ui/dialogs/external_order.py`（对话框与它的样式），并从 `ui/dialogs/__init__.py` 导出；
  「设置」菜单里那一项从子菜单变成动作。
- 设置层不再需要按页拼菜单、维护勾选态；它只负责把三页的内容交给对话框、把答案存回偏好。
- 数据安全边界没变：这一层只写会话偏好，用户的照片一个字节都不碰。
- 宿主耦合面不变（`SettingsFlowMixin` 仍只要 `_external_button` 来取条目）。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 保留「点一下移到最前」 | 一次只挪一项，且每次都要重新展开菜单；改三项以上就很笨 |
| 在 `QMenu` 里做拖动 | 菜单不是可拖列表，Qt 的原生菜单也不接管这种手势；自己画一套不如用列表 |
| 上移 / 下移两个菜单项 | 要连点，且菜单第一次弹出之后每次都要重开 |
| 另建一个完整的设置窗口 | 仍然只有这一项需要排序；为它造一整扇设置窗口（ADR 0073 否决过）代价更大 |
| 三页挤在一个列表里 | 三页的应用集合不同、次序也各自独立，一张列表表达不了「这是哪一页的次序」 |
