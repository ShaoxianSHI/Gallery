# ADR 0070：`Esc` 退不动时取消选中

- 状态：已接受
- 日期：2026-10-22
- 相关 ADR：0040（筛选：`Esc` 只管位置）、0041（层级栈：`Esc` = 弹栈顶）
- 相关代码：`src/gallery/ui/window/navigation_flow.py`、`src/gallery/ui/main_window.py`、
  `src/gallery/ui/browser/grid.py`

## 背景

ADR 0041 把 `Esc` 定成「弹栈顶一帧」，ADR 0040 又把它与「撤一条条件」彻底分开。两条合起来
的结果是：在「全部照片」、相册模式的库根、日历页这些栈上已经没有上一层的地方，`Esc` 被置灰，
按下去什么也不发生。

而用户在那一层仍然点得出一个选中的东西（文件夹、分组、照片、日历的一格）。取消选中本来只有
一个手势：点空白处。键盘上没有对应的路。

## 决策

1. **`Esc` 先看能不能退，能退就退一层**；退不动时取消当前选中的那个对象。两条路共用一个
   `QAction`、一个键 —— 不新增第二个 `Esc` 动作（ADR 0041 决策 6 的「同一个键不能有两个主人」）。
2. **「退得动」的判据不变**：仍是 `_can_go_up()`（栈深 > 1）。取消选中只接手它本来空着的那一格，
   不改变任何一层里的导航行为。
3. **取消选中的范围**：网格上清掉选区与当前项；日历上清掉选中的那一天。扩选锚点一起清掉，
   否则下一次 `⇧` 点会从刚取消掉的那一格铺开。
4. **菜单文案跟着状态走**：退得动时是「上一级」，退不动且有对象可取消时是「取消选中」。
   同一枚动作在菜单里始终说它此刻会做什么。
5. **退不动、也没有对象可取消时仍然置灰**，不为了「有反馈」去弹一句话。

## 后果

- `⇧Esc` 仍然只撤最后一条筛选条件，与这一条互不抢键（ADR 0040 决策 11）。
- 从相册退到库根时，退回去的那一格仍然选中着；此时再按一次 `Esc` 收掉它，位置不动。
- 日历页上 `Esc` 不会顺带切换浏览方式 —— 换方式仍走「退出」与浏览方式菜单。
- 动作可用性由选区变化触发重算；日历那一路新接了一根 `selection_changed`。

## 被否决的方案

- **另立一个 `Esc` 动作**：两个同键动作会进 Qt 的歧义判定，症状是「有时按了没反应」。
- **让 `Esc` 在有选中时总是取消选中**：那会把「退一层」从最常用的路径上抢走，用户的每一次
  退层都要先取消选中再按第二次。
- **用 `⇧Esc` 取消选中**：那个键已经属于「撤掉最后一条条件」，且取消选中比撤条件更常发生，
  不该要求按修饰键。
