# ADR 0106：文案收拢成查表，中英双语

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0011（地名不翻译）、0073（应用级偏好）、0100（用户可见文案的口径）
- 相关代码：`src/gallery/core/i18n.py`、`src/gallery/core/locales/`、`src/gallery/ui/banners.py`

## 背景

界面文案是散着长的：1571 处中文字符串、1283 条不重复的句子，落在 110 个源文件里。
`ui/banners.py` 与 `ui/desktop.py` 是仅有的两处收拢过的（动作结果横幅），而菜单标签写在
`_build_actions` 里、对话框写在各自的 `__init__` 里、错误信息写在 `core/` 各处的 `raise` 上。
口径有 ADR 0100，但「这句话住在哪儿」没有答案。

散落本身不是缺陷 —— 单语软件里，文案贴着用它的那段代码反而好读。它成为缺陷的那一刻是
**要上第二种语言**：同一句话没有唯一的身份，就没有地方放译文，也没有办法判断「哪些还没翻」。
而 `core/` 也在产用户可见中文（`GalleryError.message`、逐项失败原因、字段与分组标签、日历的
星期与年月、大小与日期格式），所以「只收 ui 的中文」不够。

## 决策

### 1. 一个机制，不是一个文件

文案住进 `src/gallery/core/locales/<语言>/<领域>.py`，每个领域一个模块，模块里的键必须以
领域名开头（`banner.py` 里只有 `banner.*`）。`core/i18n.py` 只做三件事：选语言、查表、填参数。

按领域拆而不是一个巨型文件：一个 1283 行的 `zh_CN.py` 永远在冲突，review 时也看不出
「这次动的是哪一类话」。而「所有文案在一处」指的是**一个可枚举的键空间**，不是物理上一个文件。

### 2. 中文是源语言，迁移时逐字不动

`zh_CN` 里的值就是迁移前那句话，标点、空格、「」、⌘ 一个字都不改。于是：
**现有 11250 处测试中文字面量一条都不用改**，它们继续当迁移的验收标准。中文值同时也是
术语与口径的准绳（ADR 0100），别的语言以它为准。

### 3. 只有两类文字进目录

- **界面文案**：标签、菜单、对话框、横幅、提示、按钮。
- **`core/` 产出的用户可见消息**：`GalleryError.message`、`Failure.reason`、字段/分组/日历的
  显示名、大小与日期格式、逐项失败原因。

**不进的**：

- 用户照片里的元数据、用户自己填的事件名与相册名 —— 那是内容，不是文案（ADR 0011）。
- 地名。这轮不翻译：要支持英文界面需要一份多语地名库，是另一个项目；目前 `places.tsv.gz`
  是英文的，`places/countries.py` 只存中国的省。**英文界面下照原样显示**。
- 日志。给维护者看的东西保持一种语言，排查时少一层歧义。
- 正则、SQL 列名、EXIF 字段名、`NSEWnsew` 一类的取值。
- **写进磁盘的默认值**（事件默认名「未命名旅行」、副本名后缀「的副本」、背景与配色的默认名、
  `config.toml` 的注释）：它们只按**生成那一刻的语言**写出去，之后不重译 —— 否则同一份数据会
  随界面语言变形。它们仍然要进目录（因为生成时要选语言），但不参与回译。

### 4. 整句模板，不拼片段

一条消息就是一句完整的话，参数用 `{name}` 占位：

```python
t("banner.rename.journaled", name=entry.name)
t("banner.rename.not_journaled", name=entry.name)
```

**不许把同一句话切成「前缀 + 片段」再拼**：`"已按日期范围将" / "已将"` 这种前缀、`"；未能记录
操作日志，⌘Z 不可撤销"` 这种尾注，翻成英文语序一定错。分支就是两条键。

**例外是并列的分句**：`"已粘贴 3 项到「相册」；另有 1 项未能粘贴：磁盘已满。"` 这种由若干
完整分句拼起来的横幅，可以保留拼接，但**分句本身必须是完整的**，且分隔符与句末标点由目录给
（`banner.separator`）。拼接顺序仍由代码决定 —— 这是可接受的，因为每一段单独读都成立。

### 5. 复数与数字

中文没有单复数，英文必须有。目录的值允许 `(一份, 多份)` 两元组，用
`t_plural("banner.photos_bound", count, name=...)` 取。参数里的数字由调用方传，**数字两侧的
空格进模板**（ADR 0100 决策 6），不要用代码补。

### 6. 语言是应用级偏好，切换后重启生效

语言在建 `QApplication` 之前就要定，所以它进 `core/library/session.py` 的 `Preferences`
（与动画速度、外观同族），不进任何 `config.toml`。取值 `system` / `zh_CN` / `en`：

- `system`：系统语言以 `zh` 开头 → `zh_CN`，其余 → `en`；
- 显式选择优先于系统。

**第一阶段不做逐控件重新翻译**：改语言写进偏好，横幅说「重启 Gallery 后生效」。真正的运行时
切换要遍访每个控件与动作，而画出来的文字（日历、卡片）与建出来的控件是两套时序 —— 那是另一条
ADR 的事。

`QMessageBox` / `QFileDialog` 自己的按钮文案由 Qt 提供，**要另外载入 `qtbase_<语言>.qm`**，
否则中文界面里会冒出英文 `Cancel`。它与本目录是两套来源，不能互相替代。

### 7. 缺键不抛异常

查表顺序：当前语言 → `zh_CN` → 键本身。渲染时缺键不该让界面崩掉或空白；完整性由测试钉住，
生产环境的回退只是最后一道保险。参数对不上时保留未替换的占位符，同样由测试拦。

### 8. 两道守护

- **键空间完整**：每种语言必须有同一组领域模块，每个模块的键集合必须与 `zh_CN` 相同；
  两边的占位符集合（含复数两档）必须相同。**逐领域比较**，所以迁移可以一个领域一个领域走，
  每个提交都是自洽的。
- **中文不再回流**：`ui/` 里不许再出现中文（或日韩）字符串字面量，`core/` 只放行目录、
  数据表与显式登记的豁免（正则、`places/countries.py`、日志）。**新加文案只能加进目录。**

## 迁移顺序

每一步单独一个提交，`zh_CN` 的渲染结果逐字节不变：

1. 机制与空目录、审计脚本，加键空间与回退的测试。
2. `banner` 领域（`ui/banners.py`、`ui/desktop.py`）—— 动作结果的整句模板，分支最多。
3. `menu` / `dialog` / `viewer` / `calendar` 等界面领域。
4. `core` 的消息：`error`、`metadata`、`library`、`event`、`external`。日志不动。
5. `en` 补齐到全量（若前面按领域成对提交，则这一步主要是复查）、设置菜单入口、系统语言检测、
   Qt 翻译载入、打包验证。

## 后果

- 现有测试继续断言中文原文，改动是否走样由它们说话；英文另加冒烟测试。
- 英文比中文长：`banner_width`、标题栏、菜单宽度、像素断言要复查一遍，必要时改成
  「不重叠 / 不截断」的判据。
- 按名称排序在中文里走拼音（ADR 0074），英文界面下要按 `locale` 排 —— 独立的小决策，
  不阻塞本 ADR。
- 文案改动的入口从「改代码里的字面量」变成「改目录里的值」：ADR 0100 的口径可以在目录上
  加一条守护（结果词、禁用词），比扫全仓库可靠。
- 目录是代码（Python 字典），不是数据文件：没有提取/编译步骤，打包（nuitka）也不用额外带
  资源。代价是译者拿到的是 `.py`；将来真有外部译者，再写一个导出/导入 CSV 的脚本。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 所有文案塞进一个 `zh_CN.py` / `en.py` | 1283 行单一文件永远在冲突；按领域拆开仍是「一个键空间」 |
| gettext，中文当 msgid | 改一个标点就静默丢译文；同一句中文在不同语境要 msgctxt；还多一步提取与编译 |
| Qt 的 `.ts` / `QTranslator` | `core/` 不能 import Qt，用户可见消息有一半在 core；两套机制并存比一套差 |
| core 只抛键，由 ui 翻译 | 要动每一处 `raise` 与每一个 `str(exc)`；`GalleryError.message` 的既有契约就是「给用户看的中文」 |
| 运行时切换语言 | 要遍访每个控件、动作与画出来的文字，收益是「少重启一次」，风险与工作量都不成比例 |
| 把地名一起翻 | 需要多语地名库；ADR 0011 已经决定地名不做半截翻译 |
| 日志也进目录 | 日志是维护者视角，一种语言更容易对照上报内容 |
