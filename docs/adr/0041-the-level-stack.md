# ADR 0041：「我在哪」是一条栈，不是五个字段

- 状态：已接受
- 日期：2026-10-06
- 相关 ADR：0026（搜索：检索是「换了一层」）、0040（筛选：在当前视图内收窄，不入栈）
- 相关代码：`src/gallery/ui/window/state/level_stack.py`、
  `src/gallery/ui/window/level_stack_mixin.py`、`src/gallery/ui/window/`（其余各 flow mixin）、
  `src/gallery/core/library/config.py`

## 背景

「我在哪一层」原先由**五个独立的可变字段**表达（`_browse_mode`、`_current_dir`、`_group_view`、
`_drill_photos` 连着 `_from_calendar` / `_drill_label`），彼此之间有一堆**没人声明的互斥关系**，每
加一条路径都要靠人记住这五个该一起清哪些；而 `go_up` 与 `_can_go_up` 各手写一遍那串 `if`，顺序就是
层级深度。

## 决策

### 1. 栈：帧的四种 + 栈底决定浏览方式

```
根帧（三种，决定浏览方式）：全部照片 │ 相册视图 │ 日历页  +  逐层压栈
  全部照片： 根 → 搜索结果
  相册视图： 根 → 相册* → [分组] → [照片]      每层都可插「搜索结果」
  日历视图： 根 → 日历格 → [分组] → [照片]      每层都可插「搜索结果」
```

四种帧：`AlbumFrame`（相册，磁盘路径）、`GroupFrame`（分组，`facet`+`key`+已排好的照片）、
`CalendarFrame`（日历那一格，照片 + 名字）、`SearchFrame`（整库检索的结果），外加大图页那一帧
`PhotoFrame`；**`SearchFrame` 之上不再压 `GroupFrame`**（决策 2a）。

**栈底那一帧就是浏览方式**，`_browse_mode` 这个独立字段没有了：两条链（相册链 / 日历链）**互斥**
—— 日历格下面不可能是相册，那不是靠 `if` 判掉的，是类型上就排除了，「有分组又有日历格」那种状态构造
不出来。

四条规则：

1. **`Esc` = 弹栈顶一帧**；只有根帧时无事可做。`_can_go_up` 归 `stack.can_pop()`（=
   `depth > 0`）。**大图页那一帧也归这条管**（见决策 6）。
2. **筛选不入栈，但随帧存**（见决策 3）。
3. **切换浏览方式 = 清栈换根**，落在各自底部、不带任何残留。
4. **会话只存栈底的浏览方式**：重开永远是那个浏览方式的底部，**位置一律不记**。

`replace_top` 与 `push` 分开：在大图页里翻上下一张**不是**往深里走（否则 `Esc` 要按几十次才退得出
去），所以照片帧是「换栈顶」。

### 2. 筛选不入栈，**但随帧存**

筛选不改变「我在哪」，它是当前这一层的收窄，所以它不是一帧。但它**属于某一帧、跟着那一帧走**：压入
搜索结果那一帧时把「这一层筛选前的样子」一起存进去，弹回来时恢复。反过来做（全局一份、进出层时自己
记着恢复）就是「清栈时忘了清筛选」那一类 bug 的来源 —— `set_browse_mode` 里那个「只有整库检索要清」
的 `if` 正是这种手工同步。

### 2a. 搜索结果**平铺**，不压分组帧

搜索结果只允许平铺所有搜到的照片，想要分组就用筛选。这一条把 `_group_view` 的判据从「从底往上找最后
一个分组帧」简化成「看栈顶」：分组于是只可能压在相册 / 日历格上，任何调用点都不可能再把它读成「我在
分组里」而做出分组专用的行为（典型的是写操作只作用在组内照片上 —— 那正是约束 1）。而「想要分组就用
筛选」在机制上成立，是因为筛选不改变「这一层是什么」、搜索是**换了一层**（ADR 0026 决策 7）而换的那
一层是平的。

### 3. 作用域切换 = 纯粹的 push / pop

作用域切换按钮那两档（`SEARCH_SCOPE_LIBRARY` / `SEARCH_SCOPE_LEVEL`）：筛选 → 搜索**压**一帧
`SearchFrame`，搜索 → 筛选**弹**掉那帧。不管栈顶原本是什么，所以这条是纯粹的 push / pop，不牵扯「当
前帧是什么」。

### 4. 大图页上发起搜索 = 弹掉照片帧、压搜索帧

与在进大图之前的分组 / 相册页上搜索行为一致。不选「压在照片帧之上」—— 那条路能让用户「看一眼照片再
搜」，但搜索结果里只给路径、不给「第几张」，退回去找不到刚才那张。

### 5. 会话只记浏览方式

`LibraryUIState.browse_mode` **已经存在**，一个字段都不用加。栈不进会话：位置一律不记，重开落在那个
浏览方式的底部 —— 用户在一个浏览方式里待了很久，切走再切回来并不见得想回到刚才那个位置。

### 6. 「上一级」一条命令管两处：大图页与网格页

栈里既然有 `PhotoFrame`，那么大图页的 `Esc` 与网格页的是**同一件事**：弹掉栈顶那一帧。原先它们是两
个 `QAction`，那时「退一层」还没有统一判据，只能按当前页面分派；而两个 `QAction` 挂同一个 `Esc`，一
旦某处忘了更新置灰，谁先触发全看加载顺序。

实现落在 `NavigationFlowMixin._leave_frame` 的 `PhotoFrame` 那一支，走
`ViewerFlowMixin.leave_detail_page`，与 `show_grid` 共用同一份收尾（含落在大图页累积下的外部变
化，ADR 0013）；`show_grid` 本身**留着**（关大图、删掉最后一张都走它），只是不再是菜单项。

### 7. 画哪一页 = 栈的函数（`page_role_of`）

页面**不是各条路径各自决定的一件事**：原先有九处 `setCurrentWidget` 各自挑一页，两份记账迟早对不
上。映射收在一条纯函数里（`level_stack.page_role_of`，不碰 Qt）。**未展开的那一格归日历页**：它是
「日历格 + 照片」一起进出的一对，屏幕上从没见过它的网格。

```
没有库                                          → 欢迎页
栈顶是照片帧                                    → 大图页
栈底是日历、顶上没有展开的层                    → 日历页
其余（相册 / 分组 / 展开的日历格 / 搜索结果）   → 网格页
```

`_sync_page_to_stack()` 是**唯一**给内容页 `setCurrentWidget` 的地方（回归测试扫 `ui/window/`），但
它**不挂在四个写入口上自动跑**：`_enter_calendar_drill` 要先把这一格的几张摆进模型、再换页（换早了
那一刻算出来的可见行对不上），所以由每条路径在**该换的那一拍**显式叫一声。`_in_detail_page()` /
`_on_grid_page()` / `_on_calendar_page()` 一律读栈（`_page_role`），不再看控件。

## 后果

- `_browse_mode`、`_current_dir`、`_group_view`、`_drill_photos`、`_from_calendar`、`_drill_label`
  六个字段全部消失，换成一条 `LevelStack`；`_group_view` 原来有 **7 处**改写、`_editing_condition`
  有 **8 处**，现在各归一处。
- `_is_library_search` / `_is_filtering` 收敛成「栈顶是不是搜索帧」—— 原先那个「条件非空且 scope 不
  是 level」的判据要同时看两个字段，而它是七个调用点各自问一次的地方。

## 实施时定下来的几条约束

- **相册链是「一层一帧」**：从库根点进「旅行/2024」要压**两**帧；压一帧的话「旅行/2024」与「旅
  行/2025」在栈上长得一样，退一次就掉回库根。
- **`go_up` 是「先弹、再收尾」**，所以 `_leave_frame` 里不能再走 `enter_folder`（那会又压一帧）；同
  理 `enter_folder` 里必须**先弹搜索帧、再压相册链**，否则弹掉的是刚压上去的那一层。
- **`_leave_search_frame` 必须用传进来的那一帧，不能重新查栈**：`go_up` 弹完之后
  `self._search_frame` 已经是 `None`，重新查会以为「压根没有搜索帧」而直接返回。
- **摘掉某一层要用与位置无关的写法**（`LevelStack.without_frame`），不能写成「弹到它不在为止」：整
  库检索压在日历格之上，连续弹会把刚压上去的搜索帧一并弹掉。
- **日历格是「多张一层、单张一对」**：多张的那一格摊成网格、自己是一层，`Esc` 在它上面停一次；只有
  一张的那一格**不摊网格**，直接进大图，「日历格 + 照片」**一起进、一起出**，一次 `Esc` 就回日历。
  判据落在 `CalendarFrame.expanded` 上（`False` = 那一对），**不按「进来时几张」在别处各自记一
  份**。
