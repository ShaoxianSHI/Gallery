# ADR 0041：「我在哪」是一条栈，不是五个字段

- 状态：已接受
- 日期：2026-10-06
- 相关 ADR：0026（搜索：检索是「换了一层」）、0040（筛选：在当前视图内收窄，不入栈）
- 相关代码：`src/gallery/ui/window/level_stack.py`、`src/gallery/ui/window/level_stack_mixin.py`、
  `src/gallery/ui/window/`（其余各 flow mixin）、`src/gallery/core/library/config.py`

## 背景

「我在哪一层」原先由**五个独立的可变字段**表达：`_browse_mode`、`_current_dir`、`_group_view`、
`_drill_photos`（连着 `_from_calendar` / `_drill_label`）。而它们之间有一堆**没人声明的互斥
关系**（有分组就不该有日历那一格、有条件时浏览方式的含义会变、……），于是每加一条路径都要靠人
记住「这五个该一起清哪些」。

漏掉的后果不是报错，而是**看起来完全正确的死路**：

- **搜索结果里按 Esc 没反应**（用户报的两处之一）。整库检索的结果「接管当前层」，而它既不是
  文件夹也不是分组 —— `go_up` 那串 `if` 里压根没有它，于是 `_can_go_up()` 恒为 `False`。
  搜索后直接按 Esc 能退出是**巧合**：那时焦点还在搜索框里，走的是搜索框自己的 Esc，与 `go_up`
  无关。进一趟分组、焦点回到网格，那条路就断了。
- **在大图页上搜一下**：`_reload_level` 无条件把栈顶换成网格页，照片帧凭空消失，之后退不出来。

而 `go_up` 与 `_can_go_up` **各手写一遍那串 `if`，顺序就是层级深度** —— 顺序错了的症状是「退错
了一层」，不是任何一句能自检的东西。加一种新层级要记得同时改这两处。

## 决策

### 1. 栈：帧的四种 + 栈底决定浏览方式

```
根帧（三种，决定浏览方式）：全部照片 │ 相册视图 │ 日历页  +  逐层压栈
  全部照片： 根 → 搜索结果
  相册视图： 根 → 相册* → [分组] → [照片]      每层都可插「搜索结果」
  日历视图： 根 → 日历格 → [分组] → [照片]      每层都可插「搜索结果」
```

四种帧：`AlbumFrame`（相册，磁盘路径）、`GroupFrame`（分组，`facet`+`key`+已排好的照片）、
`CalendarFrame`（日历那一格，照片 + 名字）、`SearchFrame`（整库检索的结果），
外加大图页那一帧 `PhotoFrame`。

**`SearchFrame` 之上不再压 `GroupFrame`**（决策 2a）—— 搜索结果是平的。

**栈底那一帧就是浏览方式**，所以 `_browse_mode` 这个独立字段没有了。这比「浏览方式是独立字段」
更彻底：两条链（相册链 / 日历链）**互斥** —— 日历格下面不可能是相册，那不是靠 `if` 判掉的，
是类型上就排除了。原来那种「有分组又有日历格、浏览方式的含义变了」的状态构造不出来。

四条规则：

1. **`Esc` = 弹栈顶一帧**；只有根帧时无事可做。`_can_go_up` 归 `stack.can_pop()`（= `depth > 0`）。
   **大图页那一帧也归这条管**（见决策 6）。
2. **筛选不入栈，但随帧存**（见决策 3）。
3. **切换浏览方式 = 清栈换根**，落在各自底部、不带任何残留。
4. **会话只存栈底的浏览方式**（用户明确要的）：重开永远是那个浏览方式的底部，**位置一律不记**。

`replace_top` 与 `push` 分开：在大图页里翻上下一张**不是**往深里走（否则 `Esc` 要按几十次才退得
出去），所以照片帧是「换栈顶」。

### 2. 筛选不入栈，**但随帧存**

用户定的：筛选不改变「我在哪」，它是当前这一层的收窄。所以它不是一帧。

但它**属于某一帧、跟着那一帧走**：压入搜索结果那一帧时把「这一层筛选前的样子」一起存进去，
弹回来时恢复。反过来做（全局一份、进出层时自己记着恢复）就是「清栈时忘了清筛选」那一类 bug 的
来源 —— 而现在正有这个：`set_browse_mode` 里「只有整库检索要清」的 `if` 就是这类手工同步。

### 2a. 搜索结果**平铺**，不压分组帧

用户定的：「搜索结果上不要再压分组帧了，搜索结果只允许平铺所有搜到的照片。想要分组就用筛选。」

**这一条顺带把 `_group_view` 的判据从「从底往上找最后一个分组帧」简化成「看栈顶」** —— 那不是
顺手的事：搜索结果既然平铺，分组就只可能压在相册 / 日历格上。而早先那个版本里「在搜索结果里
`_group_view` 仍非空」，29 个调用点里任何一处把它读成「我在分组里」都会做出分组专用的行为
（典型的是写操作只作用在组内照片上 —— 那是红线 1 那条）。所以这条产品决定同时收掉了一整类判断
歧义。

「想要分组就用筛选」在机制上成立的原因也在这里：筛选不改变「这一层是什么」，所以分组照旧作用在
这一层上；而搜索是**换了一层**（ADR 0026 决策 7），换的那一层是平的。

### 3. 作用域切换 = 纯粹的 push / pop

作用域切换按钮那两档（`SEARCH_SCOPE_LIBRARY` / `SEARCH_SCOPE_LEVEL`）：

- 筛选 → 搜索：**压**一帧 `SearchFrame`；
- 搜索 → 筛选：**弹**掉那帧。

不管栈顶原本是什么（用户：「除了搜索外的其他位置都能压入搜索」）。所以这条是纯粹的 push/pop，
不牵扯「当前帧是什么」。

### 4. 大图页上发起搜索 = 弹掉照片帧、压搜索帧

用户定的：「在大图页搜索就把大图弹出，再把搜索入栈，和在进大图之前的分组/相册页搜索行为一致。」
不选「压在照片帧之上」—— 那条路能让用户「看一眼照片再搜」，但搜索结果里只给路径、不给「第几张」，
于是退回去找不到刚才那张。

### 5. 会话只记浏览方式

`LibraryUIState.browse_mode` **已经存在**，一个字段都不用加。栈不进会话：位置一律不记，
重开落在那个浏览方式的底部。理由与决策 3 相同 —— 用户在一个浏览方式里待了很久，切走再切回来
并不见得想回到刚才那个位置（他这趟去另一个浏览方式干的事，多半与刚才那个位置无关）。

### 6. 「上一级」一条命令管两处：大图页与网格页

栈里既然有 `PhotoFrame`，那么大图页的 `Esc` 与网格页的是**同一件事**：弹掉栈顶那一帧。
原先它们是两个 `QAction`（「返回网格」与「上一级」共用 `Esc`，互为开关），那是**栈模型
落地之前**的写法 —— 那时「退一层」还没有一个统一判据，只能按当前页面分派。

合并不只是为了少一行菜单，而是因为**两条同键命令必然有一个按不到**：两个 `QAction` 挂同一个
`Esc`，同一时刻只亮一个是对的，可一旦某处忘了更新置灰，谁先触发全看加载顺序，症状是
「有时按 Esc 没反应」而界面看不出错。

实现上落在 `MainWindow._leave_frame` 的 `PhotoFrame` 那一支：它原来只处理了「底下是日历格就
回日历」就 `return`，**没有把栈换回网格页** —— 所以网格那边真正做的事（换页、选中刚看的那
一格、把大图页攒下的外部变化落下去，ADR 0013）当时只能由 `show_grid` 单独做，菜单里于是
有了两条命令。现在那一支走 `ViewerFlowMixin.leave_detail_page`，与 `show_grid` 共用同一份收尾。

`show_grid` 本身**留着**（关大图、删掉最后一张之后退回网格都走它），它只是不再是菜单项。

### 7. 画哪一页 = 栈的函数（`page_role_of`）

页面**不是各条路径各自决定的一件事**。原先有九处 `setCurrentWidget` 各自挑一页，而「我在哪」
已经由栈表达 —— 两份记账迟早对不上，症状正是「日历页已经摆在前面，而标题还写着那一格，
要再按一次 `Esc` 才恢复」。

映射收在一条纯函数里（`level_stack.page_role_of`，不碰 Qt）：

```
没有库                                          → 欢迎页
栈顶是照片帧                                    → 大图页
栈底是日历、顶上没有摊开的层                    → 日历页
其余（相册 / 分组 / 摊开的日历格 / 搜索结果）   → 网格页
```

**未摊开的那一格归日历页**：它是「日历格 + 照片」一起进出的一对，屏幕上从没见过它的网格
（决策 1 的「单张一对」）——把它算成网格页就又制造出「日历页摆在前面、标题却写着大图页」。

`_sync_page_to_stack()` 是**唯一**给内容页 `setCurrentWidget` 的地方（守护测试扫 `ui/window/`）。
它**不挂在四个写入口上自动跑**：`_enter_calendar_drill` 要求「先把这一格的几张摆进模型、再
换页」（换早了那一刻算出来的可见行对不上），所以由每条路径在**该换的那一拍**显式叫一声。

`_in_detail_page()` / `_on_grid_page()` / `_on_calendar_page()` 一律读栈（`_page_role`），
不再看控件 —— 「在大图页」与「栈顶是照片帧」于是不可能各说一套。

## 后果

- `_browse_mode`、`_current_dir`、`_group_view`、`_drill_photos`、`_from_calendar`、`_drill_label`
  六个字段全部消失，换成一条 `LevelStack`。其中 `_group_view` 原来有 **7 处**改写、
  `_editing_condition` 有 **8 处**，现在各归一处。
- `_is_library_search` / `_is_filtering` 收敛成「栈顶是不是搜索帧」—— 原先那个
  「条件非空且 scope 不是 level」的判据要同时看两个字段，而它是七个调用点各自问一次的地方。
- 搜索结果里 `Esc` 退得出去、大图页上搜索不再弹回网格 —— 这两条不用专门修，它们是模型的
  结果而不是补丁。

## 实施时定下来的几条约束

- **相册链是「一层一帧」**：从库根点进「旅行/2024」要压**两**帧。压一帧的话「旅行/2024」与
  「旅行/2025」在栈上长得一样，退一次就掉回库根。
- **`go_up` 是「先弹、再收尾」**，所以 `_leave_frame` 里不能再走 `enter_folder`（那会又压一帧）；
  同理 `enter_folder` 里必须**先弹搜索帧、再压相册链**，否则弹掉的是刚压上去的那一层。
- **`_leave_search_frame` 必须用传进来的那一帧，不能重新查栈**：`go_up` 弹完之后
  `self._search_frame` 已经是 `None`，重新查会以为「压根没有搜索帧」而直接返回。
- **摘掉某一层要用与位置无关的写法**（`LevelStack.without_frame`），不能写成「弹到它不在为止」：
  整库检索压在日历格之上，连续弹会把刚压上去的搜索帧一并弹掉。
- **日历格是「多张一层、单张一对」**：多张的那一格摊成网格、自己是一层，`Esc` 在它上面停一次；
  只有一张的那一格**不摊网格**，点开直接进大图，「日历格 + 照片」**一起进、一起出**，一次
  `Esc` 就回日历。判据落在 `CalendarFrame.expanded` 上（`False` = 那一对），**不按「进来时
  几张」在别处各自记一份** —— 两份记账迟早对不上，症状是「日历页已经摆在前面，而标题还写着
  那一格，要再按一次 `Esc` 才恢复」。
