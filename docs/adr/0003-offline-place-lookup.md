# ADR 0003：按坐标反查行政区划，走离线自带数据

- 状态：已接受（第 3、6 节已分别被 ADR 0011、0012 取代，见那两节下的说明）
- 日期：2026-10-01
- 相关 ADR：0011（地点语言规则）、0012（数据改为随包分发，本 ADR 的下载部分已被取代）
- 相关代码：`src/gallery/core/places/dataset.py`（原 `geonames.py`）、`src/gallery/ui/main_window.py`

## 背景

面板已经能显示 GPS 坐标，但坐标对人没用，而 EXIF 里**根本没有地点名字段** —— 它只存坐标。地点名要么
来自 IPTC / XMP（相机和 Lightroom 会写 `City` / `Country`，但绝大多数原图没有），要么得靠坐标反查。

可选的反查方式与实测代价：

| 方式 | 实测 | 问题 |
|------|------|------|
| `reverse_geocoder` | 返回 city/country/admin1/admin2，正合需求 | `install_requires=['numpy','scipy']`（scipy 约 40 MB），2016 年的包，安装要编译 C 扩展 |
| `geonamescache` | 只依赖 typing-extensions | wheel **33.4 MB**；全球城市只有 admin1 **代码**，仅美国有州名 |
| `geopy` + Nominatim | 包 0.1 MB，精度可到街道 | **要把坐标发给第三方服务器** |
| 自备 GeoNames 公开数据 | `cities15000.zip` 3.2 MB + `admin1CodesASCII.txt` + `countryInfo.txt`，三个文件均公开可下载 | 要自己写最近城市查找（约 40 行） |

## 决策

### 1. 自带 GeoNames 数据，不引入反查库

数据用 GeoNames 的公开文件（CC BY 4.0），自己解析、自己做最近城市查找（haversine 暴力扫描两万多座
城市，约几十毫秒，放在后台线程里）。这样**不新增任何依赖**，避免为了一个次要功能拖进 scipy 或 33 MB 的
数据包，也不受第三方库年久失修的影响。

### 2. 坐标绝不出本机

**只下载公开的城市数据，不上传用户坐标。** 这是与在线反查服务的本质区别，也是不选 Nominatim 的唯一原因 ——
一个「照片只留在你硬盘上」的软件，不该因为要看个地名就把照片的拍摄地发给别人。

> **本节已被 ADR 0012 取代**：三个文件不再运行时下载，数据随应用分发。保留这一节是为了说明
> 「为什么曾经要下载」。

### 3. 数据按需下载，缓存在应用级缓存目录

- 首次需要反查时下载三个文件（合计约 3.3 MB），失败就只显示坐标并说明原因。
- 缓存放**应用级**缓存目录（`~/Library/Application Support/Gallery/cache/geo/`），不放库内：这份数据与库
  无关，放库内会让每个库各下一份。
- 它是缓存：删掉会重新下载，符合「`.gallery/` 里除 config.toml 外都是缓存」的同一原则。

### 4. 推断出来的地点必须标注来源

显示成「**Bordeaux · New Aquitaine · France（按坐标推断）**」。文件里写的和软件推的不是一个可信级别，混
在一起用户会以为那是照片自带的元数据 —— 与 ADR 0002「降级要如实说出来」是同一条原则。文件里已经有地点信息
时**不再推断**，免得给出两个可能互相矛盾的答案。

### 5. 太远就不给结论

最近城市超过 300 km 时返回「没有结果」。说「离这里 800 公里的城市」比不说更糟：用户会当真。

### 6. ~~国家用中文，城市保持 GeoNames 原名~~（已被 ADR 0011 取代）

> 原决策：国家名用一份随代码走的 ISO 代码 → 中文映射（约 120 条，几 KB）；城市名保持 GeoNames 原名。
>
> **ADR 0011 改了这条**：现在只有中国的地点用中文，其余一律用 GeoNames 原名，那份映射表也缩到只剩 `CN`
> 一项。当时「只翻国家、不翻城市」的半截做法，拼出来是「法国 · New Aquitaine · 波尔多」—— 一层一个语种。

## 后果

- 离线反查是「最近的城市」而不是精确地址：在海边、山里可能偏几公里到几十公里，所以措辞与标注都要弱化确定性。
- 下载与解析都在后台线程；下载失败、数据损坏、文件缺失都只降级为「只显示坐标」。
- ADR 0001 第 10 条提到的「文件里写的照片元数据」与这里的推断是两码事，代码里也分两条字段（`地点` vs
  `地点（推断）`）。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 在线 Nominatim | 把用户照片的拍摄坐标发给第三方，与本地优先直接冲突 |
| `reverse_geocoder` | 为一个次要功能引入 scipy（40 MB）与 2016 年的编译型老包 |
| `geonamescache` | 33 MB 数据，且除美国外拿不到行政层级名称 |
| 把数据随仓库分发 | 违反「仓库里不放任何大尺寸二进制」这条仓库约定；按需下载同样是可重建缓存 |
| 不标注「按坐标推断」 | 用户会把推断结果当成照片自带的元数据 |
