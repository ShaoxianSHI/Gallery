# ADR 0080：外部应用的次序由用户定，三个位置各一份

- 状态：已接受（决策 2 的菜单交互由 0081 换成拖动对话框）
- 日期：2026-10-24
- 相关 ADR：0034（用外部应用打开）、0067（大图页那一列图片应用）、0073（「设置」菜单与
  应用级偏好的存法）、0079（系统「日历」）、0050（界面由状态算出来的映射只有一个编排点）
- 相关代码：`src/gallery/core/library/session.py`、`src/gallery/ui/main_window.py`、
  `src/gallery/ui/window/settings_flow.py`、`src/gallery/ui/window/widgets/external_button.py`

## 背景

「用外部应用打开」的下拉框里，次序原先**写死在 `MainWindow._external_entries` 的元组里**
（ADR 0034 / 0067 / 0079）。左半那一下是「第一个此刻可用的」，于是左半显示谁、下拉框里谁在
第一行，都由那一个元组决定。三页能开的东西不一样（大图页是图片软件与地图、网格页是访达与
QSpace、日历页是两个日历应用），用户对「哪一项最常用」的答案也不同：有人想用 ImageGlass
代替预览，有人希望左半直接是 Google 日历。

## 决策

### 1. 三份次序，存应用级会话偏好

三个位置与 `PageRole` 同名：`detail` / `grid` / `calendar`。存 `Preferences.external_orders`，
写进 `state.json` —— **次序是关于这台机器的偏好**，换个照片文件夹不该重来（ADR 0073 的判据）。
`with_external_order(page, ids)` 只认那三个名字，写出去永远是同一个形状；空元组表示
「照内置次序」，因此不必为一个没改过的位置留记录。

### 2. 设置菜单里三页各一个子菜单，点一下就能挪到最前

「设置 › 外部应用顺序」下面三个子菜单：图片 / 网格 / 日历。每一页列出**这一页会摆、而且这台
机器上装着**的应用，按当前次序排；点某一项就把它挪到最前（第一项带勾，它是左半那一下）。
最底下是「恢复默认顺序」，只清这一页。

**子菜单在展开时才填**：能摆哪几项、当前什么次序都会变（装没装应用、换过设置），所以不预建。
这份清单按条目的 `available` 过滤，**不按 `enabled`** —— `enabled` 里还带着「此刻看的那张照片
有没有坐标」这类条件，设置菜单不该随正在看哪张照片改名单。

### 3. 没提到的 id 保持内置次序排在后面

存的是应用 id。卸载过的应用留下的 id 认不出来、后来新装的应用不在名单里，这两种都落到
「没提到」那一支：**相对位置照内置次序**，不会把别的项挤掉或丢掉。排序是稳定的。

### 4. 次序在翻页时由窗口交给按钮，左半图标跟着换

`ExternalAppsButton.set_order(ids)` 只记这一页的次序，`refresh()` 按它重建菜单与左半图标；
`MainWindow._update_action_states` 在每次刷新前问一遍 `_external_order_ids()`
（= `preferences.order_for(当前页)`）。按钮不知道页面，页面也不自己排菜单 ——
与 ADR 0050 的「状态算出来的那几份映射只有一个编排点」同一条。

### 5. 点本来就在最前的那一项时，不留下自定义记录

挪完与内置次序相同就存空元组，于是「恢复默认顺序」不会被点亮，也不会为一个没变化的结果
写一次会话文件。

## 后果

- `state.json` 的 `preferences` 多一个 `external_orders` 键，**不升 `SESSION_VERSION`**：
  老文件没有它就是默认（内置次序），写出去的仍是同一版；读的时候逐页校验，坏页只丢那一页。
- `ExternalEntry` 多两个字段：`pages`（会出现在哪几页）与 `available`（装没装）。前者让设置
  菜单能按页分三份，后者让「能调的应用」不随当前照片变。
- `SettingsFlowMixin` 的宿主耦合面多一个 `_external_button`（要到条目清单）；`MainWindow`
  多两个内部方法（`_external_page_kind` / `_external_order_ids`）。
- 数据安全边界没变：这一层只写 `state.json`，用户的照片一个字节都不碰。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 存进库的 `config.toml` | 换个库就得重排一次，而「左半显示谁」是关于这台机器的习惯 |
| 新建一个设置窗口 / 拖拽排序 | ADR 0073 已经说过：眼下的项都是离散选择，一个菜单够用；拖拽要多一个模态窗口与一套命中判定 |
| 「上移一位 / 下移一位」两个菜单项 | 要连点几次才能到位，而且菜单里看不出当前在哪儿；点一下到最前更直接 |
| 把没装的应用也列进设置菜单 | 摆一个点了不会生效的项，与「不摆灰条目」的既有判据冲突（ADR 0034 / 0067） |
| 一份全局次序、三页共用 | 三页的应用集合不同，一份次序会逼着列表里出现一堆与这一页无关的项 |
