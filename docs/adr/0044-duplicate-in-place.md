# ADR 0044：在原地造副本，以及「同目录」不再是空操作

- 状态：已接受
- 日期：2026-10-07
- 相关代码：`src/gallery/core/metadata/paste.py`、`src/gallery/core/metadata/naming.py`、
  `src/gallery/core/metadata/transfer.py`、`src/gallery/ui/menus.py`、`src/gallery/ui/write_ops.py`
- 相关：[ADR 0018](0018-paste-into-current-folder.md)（⌘V 粘贴）、[ADR 0019](0019-copy-move-to-album.md)
  （复制到相册 / 移动到相册）、[ADR 0014](0014-context-menu.md)（菜单栏与右键菜单共用 QAction）、
  [ADR 0023](0023-menu-groups.md)（四个组）、[ADR 0017](0017-copy-file-to-clipboard.md)（⌘C 拷贝）、
  [ADR 0043](0043-events.md)（事件绑定跟着改路径的操作走）

## 背景

两件用户按了键却什么都没发生的事，都是同一个判据造成的：

- **⌘V 粘回同一个相册**：剪贴板里那张照片本来就在这里，于是跳过，横幅说
  「1 项本来就在「京都」里」。
- **「移动到相册」挑了它已经在的那个相册**：同样跳过，同样一句话。

那一段代码里写着的理由是「用户明确要求」。那个要求是：**别在我自己的文件夹里凭空多出一堆
``一张 2.jpg``** —— 它怕的是**编号**那一半，**没说要什么都不做**。而用户在访达里按 ⌘D
（复制项目）时拿到的是 ``一张 copy.jpg``，按 ⌘V 粘进同一个文件夹拿到的也是 ``一张 copy.jpg``：
**系统从不把「已经在这儿」当成「没发生」**。Gallery 在这两处与系统相反，症状是用户按了键、
看见一句话、然后发现照片一份没多。

同一个需求的另一半是「那我要主动造一份副本的时候怎么办」—— 当时没有这条路：右键菜单里
只有「拷贝」（进剪贴板）、「拷贝路径」、「复制到相册」（要先挑一个相册）。想在原位置留一份，
得先复制到某个相册、再复制回来。

## 决策

### 1. 新命令「复制」⌘D：每一项复制到它自己所在的那一层

菜单栏「编辑」与右键菜单「拿进拿出」组里（紧跟在「拷贝路径」正下方）都有这一行。
落点覆盖**单张照片、多张照片、单个相册、多个相册、大图页、分组卡片** —— 卡片那一份的作用对象是
它**代表的那批照片**（摊平），与同段的「拷贝」「复制到相册」「移动到相册」同一套语义
（ADR 0020）；只有空白处那张没有，那里压根没有选中项。

目标目录不用挑，这是它与「复制到相册」的全部差别。核心层是
:func:`~gallery.core.metadata.paste.duplicate`：按父目录分组，每组走一次
:func:`~gallery.core.metadata.paste.copy_into` —— 于是**「绝不覆盖」与半截清理都只有一份实现**，
而每个目录仍然只 `scandir` 一次。

> 副本**保留原修改时间**（`copy2`，与粘贴同一套）：于是它排在原件旁边而不是齐刷刷跳到「今天」，
> 在日历里也落在同一天。代价是同一时刻有两张一模一样的照片，这是用户自己选的。

### 2. 名字是「原文件名 + 的副本」，撞名才退到编号

```
一张.jpg          → 一张的副本.jpg        （首选）
一张.jpg 再一次    → 一张的副本 2.jpg      （首选名被占了）
一张的副本.jpg     → 一张的副本的副本.jpg  （照字面再加一层）
京都.2024         → 京都.2024的副本       （相册没有扩展名，整个名字算名字）
```

**编号那一段不另写一份**：``duplicate_base`` 只给首选名，真正挑名字的仍然是
:func:`~gallery.core.metadata.naming.free_name_in`（ADR 0018 决策 3 从访达实测来的那套）。
对一个副本再复制一次**不剥掉已有的「的副本」**退回编号 —— 那要用户先猜到
「为什么它不叫副本的副本」。

「已经在目标目录里」这一判据由 :func:`~gallery.core.metadata.paste.wanted_name` 回答，
粘贴与「移动到相册」共用它 —— 两边各写一份的话早晚漂移，而漂移出来的后果是**同一张照片在
两条路上拿到两个不同的名字**。

### 3. ⌘V 与「移动到相册」碰到「已经在那里」时**复制一份**

这是本 ADR 推翻的两条旧决策（ADR 0018 决策 2、ADR 0019 决策 4）。用户按了键就该有一件事发生，
而「什么都没发生」不是一种安全的回答 —— 它只是把用户的意图丢掉，然后在横幅上承认了。

用户怕的**编号**由决策 2 挡住（``一张 2.jpg`` → ``一张的副本.jpg``）。

### 4. 副本不进撤销栈，横幅不许承诺 ⌘Z

撤销一次复制就是**删文件**，而删除在这个项目里只允许用户在界面上亲手触发（约束 1）。
所以造副本记 :data:`~gallery.core.metadata.journal.ACTION_PASTE`，而那个 action 在
``core.metadata.undo`` 的 ``_NEVER_UNDOABLE`` 里 —— 与粘贴同一套，**一行代码都不用为它加**。

连带修掉一个已经存在的错：「⌘Z 可以撤销」原先只读 ``MoveResult.journaled``，于是**只复制了
一份的那一批**也说得出这句话 —— 没有任何东西进过撤销栈。现在它读 ``result.moved``。

### 5. 「移动到相册」里复制出来的那一份记 `ACTION_PASTE`，事件绑定不跟

它**没有被移动**：源路径原封不动，「挪回去」无从谈起（要么把它挪到它已经在的地方，要么删掉
副本）。所以它不在 ``MoveResult.moved`` 里，而是单独的 ``MoveResult.copied``，记
``ACTION_PASTE``、不进撤销栈、不进 ``follow_moves`` 的那一份绑定。

绑定不跟是**产品决定**：副本是新文件，用户没表达过「这份也算进那个事件」的心意 ——
与「复制到相册」同一取向（ADR 0043 决策 8 的反面）。

### 6. 顺带删掉 `Skipped`

「本来就在那里」这一支不再产生跳过，于是 ``paste.Skipped`` / ``transfer.Skipped`` /
两边的 ``skipped`` 字段与横幅里那一句全部变成死代码。一并删掉：留着就是
「病根修掉之后变成过时误导」。``Skipped.message`` 在界面上其实**从来没被读过**。

## 后果

- 用户可以在四种落点上造副本，不必绕道「复制到相册 + 粘回来」。
- ⌘V 与「移动到相册」不再有空操作。
- 造副本**撤不回来**，横幅明说（或者说「没能记下操作日志」时也不承诺）。这是约束 1 的直接
  后果，不是取舍。
- 撤销栈上少了一类记录：按过 ⌘D 之后按 ⌘Z 撤的是**上一次**那件事。
- 新文件由监听器（ADR 0013）自己显示，**不选中新副本** —— 那要等它扫到，而新副本与原件在
  按修改时间排序的网格里是挨着的，用户能看见。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 沿用访达的 ``一张 copy.jpg`` | 用户要的是「的副本」，而且中文系统上访达的默认副本名也不统一 |
| 粘回同一层时改成 ``一张 2.jpg`` | 那正是用户当初明确不要的那一半：凭空多出来的编号文件他分不出是哪来的 |
| 让「复制」可撤销（撤销 = 移到废纸篓） | 与其余每一条撤销语义都不同（撤销=移走 vs 撤销=删除），且要新增一条撤销动作 |
| 把造副本的绑定也复制一份 | 用户没表达过这个心意；「复制到相册」今天也不这么做，两处必须一致 |
| 给分组卡片也摆「复制」那一行 | ~~卡片不是磁盘上的东西，「造一份卡片」说不通~~ —— **已推翻**：卡片虽然不是文件，但它代表的那批照片是，与同段其余几条同一套摊平语义（ADR 0020）；少一行反而像这一层不支持 |
| 副本用当前时间（访达那样） | 与粘贴不一致，且默认按修改时间排序的网格里副本会跳到今天那一段 |
