# ADR 0087：⌘R 在没选中东西时刷新当前层，并让索引重新对账

- 状态：已接受
- 日期：2026-10-24
- 相关 ADR：0013（实时监听）、0026（检索索引）、0038（缓存可重建）、0040（筛选）、
  0054（横幅文案）、0059（`ui/` 的分层）
- 相关代码：`src/gallery/ui/main_window.py`、`ui/window/library_flow.py`、
  `ui/window/watch_flow.py`、`ui/window/calendar_flow.py`、`ui/thumbs/pipeline.py`、
  `core/library/facade.py`、`core/library/index.py`

## 背景

浏览依赖两套东西同时跟得上磁盘：当前层的扫描结果，以及检索索引。实时监听（ADR 0013）会
把大部分变化增量落到界面上，但它不是保证：

- FSEvents 在云盘、网络共享、外接盘与睡眠唤醒之后会漏事件；
- 监听本身出错时，界面从此不再自动更新（横幅会如实说，但今天只能重开库）；
- 索引的文件表只在打开库那一遍对账，且只补新增、不删已经不在的行。漏掉的删除会让检索
  继续找到一张打不开的照片。

用户需要一个轻量的「现在重新读一遍磁盘」的命令，而不是每次都重开库。

## 决策

### 1. ⌘R 有两个主人，可用性严格互斥

选中一格时 ⌘R 归「重命名…」（既有行为，ADR 0025）；**没有选中任何一格**、且当前在网格页
或日历页时归「刷新」。两条 `QAction` 共用同一个键，**同时可用时 Qt 会判成歧义快捷键、两条
都不触发**，所以 `_update_action_states` 里的判据必须保证最多只有一条亮着，并有回归测试
盯着「两条都不可用或只有一条可用」。

大图页不刷新：那里 ⌘R 改的是标题栏那一行。搜索结果是查询、日历格是那一天，都不是「当前
文件目录」，那两处刷新关掉；大图页、搜索层与日历格里按 ⌘R 什么也不发生。

### 2. 刷新 = 重新列当前层，走既有的重载链

刷新调用 `_reload_level()`，与换排序 / 换分组是同一条路：取消这一层的后台任务、换代、
清缓存、重新扫描、读元数据、分组排序、喂日历、恢复空层提示。所有收尾只有一份，不另写
一条平行路径。

**分组视图里先把组弹掉**（`_reenter_group_later`）：组员是上一次分组算出来的快照，重扫
磁盘之后只能整库重算，算完回到同一个组。组已经不在了就留在上一层。

**代价**：这是一次完整的重载，屏幕会先空一下再填回来，滚动位置不保留。与换排序时看到的
一样，不另做「原地换一批」的增量路径 —— 那条路监听器已经在走（ADR 0013），刷新要的是
「不信增量、从头读」。

### 3. 检索索引也重新对账

`Library.index_photos` 从「只补新增」改成**两个方向都走**：补上新增 / 改过的行，也删掉
已经不在的行（`FacetIndex.prune`）。删除**只在这次扫描没有跳过任何目录 / 文件时才做**：
「没看见」可能是权限不足、外接盘掉线或云盘占位，那些情况下保留索引行比删错安全。取消
也跳过删除。

刷新会作废 `_index_roots` 里这个库的记账，并掐掉正在跑的那一遍索引 —— 它读的是刷新之前
那份磁盘。新一遍索引在这次扫描收尾之后启动，不阻塞界面；新增的照片立刻能搜到，删掉的
照片不再出现在搜索结果里。

索引仍然只是缓存：删错、删干净都不影响照片本身，下一次扫描会重建等价状态。

### 4. 缩略图的失败结论也要作废

流水线里的 `_failed` / `_empty` / `_covers` 是「这个文件读不出来 / 这个相册是空的」的
记忆，只在切库时清。云盘上一张半截照片后来下完了，或者一个空相册后来进了照片，刷新必须
让它重新试一次。`ThumbnailPipeline.forget_all()` 只清这三份结论，不动进行中的任务 ——
它们回来时模型已经换了，`set_thumbnail` 会按路径丢弃。

### 5. 菜单

顶层「视图」改名为「显示」，因为这一栏现在从「刷新（重新读磁盘）」开始，再是上一级、浏览
方式、分组、排序、缩放、缩略图大小。刷新单独一组摆在最上面，与下面「怎么摆」的命令分开。

## 后果

- 监听漏事件之后有一个明确的恢复动作，不必重开库；监听出错的那条横幅也会提到 ⌘R。
- 刷新是**纯读 + 可重建缓存**：不写用户的照片，不新增文件，不碰 `events.db`。
- 索引对账要再遍历一遍目录树，跑在后台；很慢的盘上会晚一点才反映到搜索结果，但网格 /
  日历已经先生效。
- 在相册模式下，刷新只重扫当前目录，索引那一遍仍是整库的（检索范围是整库）。
- 刷新不处理「外部移动了照片」这件事：绑定跟着旧路径走，仍由开库时的孤儿检查（ADR 0043）
  负责。刷新只保证**现在磁盘上有什么**。

## 被否决的方案

| 方案 | 否决理由 |
|------|----------|
| 给刷新另配一个快捷键（如 ⇧⌘R） | 用户要的是 ⌘R；多一个键就得让用户记「什么时候能用」，而「有没有选中」本来就是现成的判据 |
| 标题栏加一颗刷新按钮 | 本项目刻意没有工具栏；那一行已经排着搜索胶囊、放映与外部应用，多一颗常驻按钮会挤掉照片 |
| 刷新只做增量（像监听器那样就地插行） | 那正是「不信增量、从头读」要避开的那条路；漏掉的删除与改名恰恰是增量补不回来的 |
| 每次刷新都无条件 `prune` 整个索引 | 无权限目录、掉线的外接盘会让「没看见」变成「删掉」，搜索会少一批还存在的照片 |
| 重开库当作刷新 | 慢、会丢当前层与选区，而且用户要的就是保持在原地 |
