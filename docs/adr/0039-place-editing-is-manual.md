# ADR 0039：位置编辑的两个方向改成手动触发

- 状态：已接受
- 日期：2026-10-06
- 相关 ADR：0003（离线反查）、0010（打开时解析入库）、0030（写回原文件）、
  0031（位置的双向编辑 —— **本条取代它的决策 1 表格后两行与决策 7**）
- 相关代码：`src/gallery/ui/dialogs/metadata_edit.py`、`src/gallery/core/metadata/place_edit.py`

## 背景

ADR 0031 定了「坐标改了就自动反查地名、地名改了就自动正查坐标」，两个方向都是实时的；问题是对话框**显示的那一份**与**真正写下去的那一份**会
对不上。城市库里北京、上海、天津、重庆、香港、澳门这 151 条的 `region` 是空的：界面反查到上海而查不
到省时，三处填充点（`_fill_from_coordinates`、`_fill_from_names`、`_on_picked`）都把「反查没有结论」
读成「别动这个框」，而核心层 `_place_assignments` 对空的那层写 `""`（那是**删掉**）—— 用户根本没碰过
那个框，它却被清空了，界面上仍显示旧值。第二个口子是界面反查的 250 毫秒防抖（`LOOKUP_DELAY_MS`）：改
完坐标立刻点保存，界面那份是旧的而核心层拿的是新坐标。

## 决策

### 1. 跨层填充只发生在用户按下的那一刻

按钮两个，放在九宫格上面一行：**地点 → 经纬度**、**经纬度 → 地点**。ADR 0031 决策 7 那套「实时回填」
连同 250 毫秒防抖一起去掉；`_refresh` 只再管候选列表（那是补全，不是写盘），不再改任何框。**为什么值得多一次点击**：
省掉的是一次点击，换来的是「点错了能立刻看出来」。自动回填把界面和写盘拆成两套判断，要靠人去核对；手
动触发只有一套 —— **框里是什么，就写什么**。

### 2. 对话框显示的就是将被写入的那一份

它是**编辑表单**，不是只读展示。所以按钮回填按城市库的结果**逐层写入，包括空的那一层**：反查到上海而
库里没有省份，就把「省 / 州」框清空，界面上立刻看得见。这一条是本 ADR 的核心。ADR 0031 决策 4 讲的是**自动**反
查失败（附近 300 公里没有城市）—— 那条仍然成立，而且现在更重要：手动按了按钮而反查不到，就**一个字都不改**并
如实说明。反过来，**反查到了、而那一层本来是空的，就必须显示成空**：留着上一座城市的省（「上海 · 浙
江省」）既错又看不懂。

### 3. 按钮一律以城市库为准，不因为是用户手敲的就手下留情

按下去的就是「以城市库为准」这个意思，于是目标那几栏**全部按库里的结果覆盖**，包括他十分钟前亲手敲进
去的那个。保留一半才是更坏的答案：那半栏显示的是旧值，而保存时它照样会被覆盖 —— 界面上有一半是假的。
反过来，**反查不到的时候一个字都不改**（ADR 0031 决策 3、决策 4）—— 那种情况是「没有结论」，不是「结
论是空的」，两者必须分开。

### 4. 核心层不再隐式跨层填充

`plan_place_edit` 去掉两个分支：坐标变了而地名没动时不再反查地名，地名变了而坐标没动时不再正查坐标。
它现在只做一件事：**把用户填的那几层翻译成要写进的字段**。这样「界面显示的 = 写下去的」不靠界面层自
觉，而是结构上只有一条路；代价是「我改了坐标，地点名自动跟着变」这个便利没有了 —— 那正是决策 1 换来
的一致性。`resolver` 仍然接受但不再使用：调用点不必跟着改，而它本来就是给那两条查询用的。

### 5. 候选列表保持实时

三个地名框边打字边给候选（ADR 0031 决策 7 里这一条与跨层填充无关）保留。**选中一个候选仍会补上省与国家**，
但只在**空着**时补 —— 那是补全，不是覆盖。

## 后果

- 界面与写盘**在结构上**不可能不一致：按钮是唯一的跨层填充处，而它改的就是框本身。
- 少了一次「敲完自动填」的顺手。两次点击换一次确认，值得。
- **ADR 0031 决策 1 表格**的后两行与**决策 7**由本条取代；决策 2（正查）、决策 3（查不到绝不编坐标）、
  决策 4（反查不到就保留）、决策 6（清掉海拔与定位时间）、决策 8（三层地名写成一行）都不变。
