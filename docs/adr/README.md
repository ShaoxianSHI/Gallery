# 决策记录（ADR）

重大设计决策在动代码之前先在这里留下一条简短记录：**背景 → 决策 → 后果 → 被否决的方案**。
编号递增，文件名用英文短横线风格，内容用中文。

## 数据安全约定（下文的「约束 N」指的就是这七条）

用户把真实照片交给这个软件，任何数据损坏都是不可接受的。这七条是全项目不可协商的前提：

1. **绝不删除、移动用户照片。** 唯一豁免是**重命名**：只允许用户在界面上亲手触发、每次都记账、可撤销。
2. **不修改原文件，除非用户显式触发。** 扫描、索引、预览、缩放一律只读，写入必须来自一次明确的用户操作。
3. **元数据写回一律走 exiftool 子进程**，不手写二进制去改 EXIF；写回前记下原值，写回后回读校验。
4. **每次写回都在 `.gallery/journal/` 留下可回滚记录。** 先记账再动文件；回滚本身也要回读校验；进程死在中间的那次同样要留下原值。
5. **`.gallery/` 里除 `config.toml` 外都是缓存**，删掉之后必须能靠重新扫描恢复等价状态。
6. **不往用户的照片目录写非 `.gallery/` 的文件。**
7. **东西只放两个位置**：库内的一切都在 `.gallery/` 下，缩略图按库路径摘要放在应用缓存目录。

**怎么称呼它们**：下文与别的 ADR 里可以直接写「约束 1」到「约束 7」，编号就是这份清单的编号 ——
这份文件随仓库分发，所以读者查得到。**代码注释里要写规矩本身**（「只增不改」而不是「约束 1」）：
注释常常被单独复制到工单、聊天记录或别的仓库里，那里没有这份清单。

标题只答「定了什么」，理由与代价在各篇里；被取代的决策在状态列里点名。

**用词一律用通用的**：回归测试（不是「守护」）、前置条件（不是「闸」）、占位（不是「补位」）、
防抖（不是「去抖」）、硬编码（不是「写死」）、回退（不是「兜底」）。
**一处例外**：Python 的 `threading` 里那个 `daemon=True` 译作「守护线程」，
它和「守护测试」是两回事，别一起换掉（ADR 0027）。
