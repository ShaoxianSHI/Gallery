# ADR 0047：从「演迹」导入演出 —— 读它导出的 .xlsx，一批建成演出事件

- 状态：已接受
- 日期：2026-10-07
- 相关 ADR：0043（事件体系）、0045（演出这一类）
- 相关代码：`src/gallery/core/events/import_shows.py`、
  `src/gallery/core/library/facade.py`、`src/gallery/ui/window/event_flow.py`

## 背景

用户在看演出的 App「演迹」里记了一批演出，想一次把它们搬进 Gallery，而不是一场场在
「记录为 → 演出」里手填。「演迹」能把列表导出成一张 `.xlsx`：一张工作表、一行一场，
表头是中文列名 —— 前 15 列是演出（演出名称 / 艺人 / 嘉宾 / 主题·剧目 / 日期 / 城市 /
场馆 / 票价 / 实付 / 座位 / 标签 / 评分 / 演出类型 / 购买渠道 / 感想 / 备注），
后 5 列是另一类东西（活动名称 / 活动时间 / 花费 / 活动地点 / 活动备注）。

要定三件事：入口放哪、这个表格怎么读、读出来的东西算不算「用户文件」。

## 决策

### 1. 入口在「文件 → 导入演出 → 从「演迹」导入」，解析与写库分两层

菜单栏「文件」里多一层子菜单，挨着「打开文件夹」—— 两者都是「把外面的东西拿进来」。
点下去挑一个 `.xlsx`，Gallery 把里面每一行建成一条**演出事件**。

解析在 `core/events/import_shows.py`（纯函数，不碰事件库也不碰 Qt），写库是
`Library.import_shows(path)`：它逐条走既有的 `create_event`，于是 journal、缓存作废、
新建事件那一条路完全一致。界面只负责挑文件、说结果。

### 2. xlsx 用标准库读，不为一件小事引第三方依赖

一个 `.xlsx` 就是一个 zip，里面 `sharedStrings.xml`（共享字符串）与
`worksheets/sheet1.xml`（工作表）两张 XML。用 `zipfile` + `xml.etree` 直接读，够这一层用了，
于是核心层不多一个依赖，也不必为它写一条 ADR 之外的打包说明。

### 3. 列按中文表头认；缺列不算错，少了「演出名称」才报错

表头是名字而不是位置：版本之间列会增减，按位置读会在某一版悄悄错位。**认不出的列直接忽略**
（「标签」就没有对应字段），但连 `演出名称` 都没有的话，看起来根本不是这个格式 ——
那时抛 `ShowImportError` 说清楚，而不是猜着读下去。

**没有演出身份的行跳过**：一行只有「活动」那几列时，它是另一类东西；一行只有零星几栏、
连名称 / 剧目 / 艺人都没有时，也记不成一场演出。跳过的那几行在横幅里报个数（行号与原因进日志），
免得用户以为表格少了几场。

### 4. 日期只取整天，开场时间留空

「日期」那一列在 Excel 里是串号（从 1900 年起的天数），**小数部分**是导出里那个时刻。
但它的显示格式本身只到天（`numFmt` 14），而且那串小数还原成本地时间要先假定一个时区 ——
假定错了会静默写进一个错的开场时间。**错的时间比留空更糟**，所以本层只取整数部分当日期，
开场时间交给用户自己补。

### 5. 导入 = 一串新建事件，不进撤销栈，一个用户文件都不碰

建事件本来就不上 `⌘Z` 那一摞（撤销它就是删），一次导入因此也不进：导入错了去事件清单里
逐个删。导入只写 Gallery 自己的 `.gallery/events.db`，不碰照片（红线 1）。

## 后果

- 从「演迹」导出、到在 Gallery 里按演出挑照片，只差一次导入。
- 导入是**可重复**的：跑两次就有两份事件，Gallery 不替用户去重（没有可靠的判重键）。
- 「标签」列不导入；开场时间留空；活动那几列不导入。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 引入 `openpyxl` / `pandas` 读表 | 一个工作表、两张 XML 的事，为它背一个第三方依赖不划算 |
| 按列的位置（A/B/C…）读 | 版本之间列会增减，错位时静默写错字段 |
| 把串号的小数按 UTC 还原成本地开场时间 | 要假定一个时区，跨机器会写进错的时间；错的时间比留空更糟 |
| 导入进撤销栈（一次 `⌘Z` 撤销整批） | 与「新建事件不进栈」这条既有规矩冲突，且绑定 / 撤销要跨十几条记录 |
| 导入时按名称 + 日期去重 | 同名同日可以真的有两场，没有可靠的判重键，去重会误删用户的东西 |
