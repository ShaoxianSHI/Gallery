# ADR 0012：地点数据改成随包分发的一份城市库

- 状态：已接受
- 日期：2026-10-02
- 相关 ADR：0003（离线反查）、0010（打开时解析入库）、0011（地点语言规则）
- 相关代码：`scripts/build_places_db.py`、`src/gallery/core/places/`、
  `src/gallery/resources/places.tsv.gz`

## 背景

地点反查用了两年 GeoNames 的 `cities15000`，一路都是**运行时猜**出来的结论，而用户从
「松岗」「沙河」这样的地名上发现了两个绕不过去的问题：**区被当成了城市**（深圳宝安区松岗街道的
照片显示「中国 · 广东省 · 松岗」—— GeoNames 把中国的区、街道、镇、村都标成了居民点，全球 974 条
`PPLA4` 里 **777 条（80%）是中国**），以及**城市名挑错了**（深圳全市显示「中国 · 广东省 · 宝安」
—— 中文名从 84 个 alternate names 里按「取最短、同长度取第一个」挑，深圳的候选是
`['宝安', '寶安', '新安', '深圳', '深圳市']`，旧县名「宝安」赢了）。两个都不是调参能解决的，
**它们缺的是信息** —— 那份数据里没有「松岗属于深圳」这条隶属关系，中文名也只能靠猜；试过的三条路
也全部走不通：往行政级别高的爬，深圳福田变成 **Hong Kong**（香港是 `PPLC` 首都，级别最高，32
公里外），排除 `PPLA3` / `PPLA4`，松岗变成**潭头**、上海浦东从 `Shanghai` 退化成 `黄浦`，退回
「找最近的城市」则松岗变成**东莞**（邻市 28 公里，比深圳的 34 公里近）。最后这条是关键：
**「地理上最近的城市」与「它所属的城市」是两回事**，而 `cities15000.txt` 只答得出前一个。

## 决策

### 1. 换成 `dr5hn/countries-states-cities-database`，并在生成期把结论算完

那份数据里有两样 GeoNames 没有的东西：**`native` 字段**（直接给本地名，深圳就是 `深圳`，不用猜）
与 **`parent_id`**（「松岗属于深圳」这条隶属关系是**写着的**）。于是不再在运行时判断，而是
**生成期把「叫什么、放在哪个坐标」一次算完**：

```
scripts/build_places_db.py  →  src/gallery/resources/places.tsv.gz
                                  省 \t 城市 \t 国家 \t 纬度 \t 经度 \t 人口
```

21,236 条、378 KB（gzip）。**运行时只剩一次最近邻查询**，`core.places` 里不再有任何翻译与层级判断。

### 2. 直辖市、香港、澳门不设省级那一层

在源数据里它们是「既是省又是市」的单位（`type=municipality` / `special administrative region`），
且带坐标。所以：

```
上海·浦东 → 中国 · 上海    澳门·氹仔 → 中国 · 澳门    深圳·松岗 → 中国 · 广东省 · 深圳
香港·沙田 → 中国 · 香港    台湾·台北 → 中国 · 台湾 · 臺北    波尔多 → France · Gironde · Bordeaux
```

**重庆不能只放一个锚点**：它横跨 470 公里、省质心离城区 43 公里，所以直辖市辖区内的每个点都标成
市名，而不是在质心放一条记录。

### 3. 删掉下载

城市库随应用分发，于是三件事一并消失：3.3 MB 的首次下载、`~/Library/Application
Support/Gallery/cache/geo/`、以及「正在下载城市数据…」那条横幅，`GeoDataError` 这个错误类型也
随之没有了。**用户的坐标仍然一个都不出本机** —— 与在线反查服务的本质区别不变（ADR 0003）。

### 4. 索引里的旧地点名作废

地点名存在 `.gallery/index.db` 里，`place_ok` 记着「已经查过了」。不升版本的话，老库里的「宝安 /
松岗」会永远留着，新扫的却是「深圳 / 深圳」，同一个库里新老混排且再也刷不掉。因此
`SCHEMA_VERSION` 5 → 6，代价是一次全量重读。

## 后果

- 地点反查开箱即用、永不联网，也不必担心下载失败或城市库版本对不上；中国大陆的照片不再出现「区名
  冒充城市名」和「旧县名冒充城市名」两种错误。
- **授权换了**：GeoNames 是 CC BY 4.0，这份是 **ODbL-1.0**（衍生数据库须同样开放 + 署名），
  对外发布时要单独声明。**数据源也只有它一家**，没有备份 —— 源站若消失或改格式就得重新找，
  `scripts/build_places_db.py` 的 docstring 记着这份源数据的几处坑，改之前先读。
- 仍然解决不了的：92 个中国区缺 `parent_id`（黄埔、通州），只能退回「找最近的城市」；少数记录被
  标成 `city` 但其实是区（上海「前置条件北」），靠「同范围内人口大 3 倍就丢弃」消歧 ——
  那是补丁，不是数据。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 继续用 GeoNames，靠启发式规则猜 | 三个方案都试过，最好的一个把松岗说成东莞；靠猜的规则迟早还会错 |
| 只用这份数据的 `native` 补中文名，地理仍用 GeoNames | 两个数据源合并，两边对不上时说不清是谁的错；隶属关系那一半仍然没有 |
| 下载 195 MB 的 `alternateNamesV2` | 现有三个文件加起来才 3.4 MB。它确实有 `isHistoric` / `isPreferredName`，但为一个显示细节加 60 倍的下载不值得 |
| 运行时继续下载，自带库只做回退 | 两个真相来源，同一张照片两次打开可能给出不同地名 |
