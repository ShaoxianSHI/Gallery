# ADR 0042：作用域切换按钮是一次性动作，不摆选中态

- 状态：已接受
- 日期：2026-10-06
- 取代：[ADR 0040](0040-filter-within-the-current-view.md) 决策 5 里「**一个可勾选的按钮**」与
  「选中时整枚按钮填满高亮色」那两句，以及「按钮不挂悬浮提示」的那条理由
- 相关 ADR：0040（筛选：在当前视图内收窄）、0035（输入面与浮层的颜色只从一处解析）、
  0041（「我在哪」是一条栈）
- 相关代码：`src/gallery/ui/search_field.py`（`ScopeToggle` / `toggle_style` / `scope_arrows`）、
  `src/gallery/ui/main_window.py`（`_on_scope_switched`）、`src/gallery/ui/window/search_flow.py`

## 背景

ADR 0040 决策 5 摆在搜索胶囊右边的那枚按钮是**可勾选**的：整枚按钮在「筛选当前视图」那一档填满
高亮色（`palette(highlight)`，与弹出菜单里选中项同一档），图标也跟着从 `text_at(0.55)` 提到
`text`。理由当时写得很明确 —— 22 点的圆角小块上没有文字标签，而「唯一的『现在开着吗』信号就是
那一片颜色」。

那个理由有一个前提：**用户会回来查这个按钮**。而实际上这一枚按钮是**一次性的**：它做的是「掉
个头」，按下去之后剩下的事（占位文字从「搜索照片…」变成「筛选照片…」、菜单里那一项打上勾、
面包屑那一段从「搜索结果（N）」变成「筛选后（N）」）全都已经发生了。于是按钮亮着的那一片颜色
是**上一件事的结果**，不是「此刻是哪一头」——用户按完看着它亮着，再按一下 expecting 切回去，
按钮又暗回来了：这正是它该做的，可它长得像一台开关。

## 决策

### 1. 按钮不再有「选中 / 未选中」两态，它是一次性动作

`ScopeToggle` **不再 `setCheckable`**，也**没有** `set_filtering`：两种作用域下它长得一模一样 ——
同一个底色（输入面那一档 `field_background`）、同一枚图标（墨色恒为 `text_at(0.55)`）、同一圈
轮廓。它按一下就是「掉个头」，不留在任何一态上。

**「此刻是哪一头」说在另外两处**，两处都是本来就在的：

| 位置 | 说什么 |
|---|---|
| 胶囊里的占位文字 | 「搜索照片…」/「筛选照片…」（ADR 0040 决策 5 的那两句，两句一眼能分） |
| 菜单里「筛选当前视图」那一项 | 勾 |

**按钮不再是第三个说法。** 状态仍然照旧是**库级偏好**、仍然记在 `config.toml` 的 `[ui]`
（ADR 0040 决策 6），仍然由 `set_search_scope` 这一个入口改 —— 变的只是它不再**显示**自己。

**方向由外面算**：`switched` 这个信号**不带参数**，「掉个头」是在 `MainWindow._on_scope_switched`
里按当前 `_search_scope` 取反的。按钮自己不记状态 —— 记下来就等于把它变回一台开关，而那正是本条
要取消的东西。

### 2. 按钮**仍然不挂悬浮提示**

ADR 0040 决策 5「不挂提示」的理由（填充色已经说清开着还是关着）随决策 1 一起失效，所以这条要
重新给理由，而不是跟着删掉：

- **它没有状态可说** —— 提示能说的只有「按下去会做什么」，而两支反向箭头说的正是这件事；
- **「此刻是哪一头」紧挨着就写着** —— 占位文字就摆在左边一格（胶囊内），两句话一眼能分，
  再挂一句提示是在把同一件事在两处说；
- 守护测试从「按一下之后仍然是空的」改成断同一件事（`test_the_button_has_no_hover_hint`）。

### 3. 反馈改由**按下**给出，而不是由**状态**给出

按钮按下去之后自己不变，于是必须给一点**瞬时**反馈：`:pressed` 把底色提亮一档（深色下
`lighter(112)`、浅色下 `darker(104)`，与「外部应用」那枚药丸的悬停提亮同一档）。悬停仍由
`paintEvent` 自己画轮廓（高亮色，`draw_outline` 那条路，理由见 `ui/outline.py`）。

**这三档合起来仍然只是同一个矩形的常态、悬停、按下**：常态输入面底色、悬停高亮轮廓、按下提亮
一档。**不引入第四档**
（不要再给「按下时轮廓也换一档」），也**不把悬停提亮搬进按下** —— 按下那一档要的是「我按到了」，
不是「我在它上面」。

### 4. 守护测试从「选中时填满」换成「两档一模一样」

`test_selecting_the_button_fills_it_not_just_its_edge` 连同它断的那件事一起去掉，换成
`test_the_button_stays_the_same_in_both_scopes`：**两种作用域各量一次按钮中心那一块的像素**，
断它们相等、且都不是 `Highlight`。量法（`grab()` 取中心那一格）原样搬过来 —— 它量的是「画出来的
是什么颜色」，不是样式表里有没有那个词。

补一条 `test_pressing_the_button_twice_comes_back`：**按两下回到原处**，断的是「掉个头」的语义
（一个只进不退的开关就不是它）。**它按的是真的按钮**，于是顺带断「信号接上了、按钮没被置灰」——
没有库时按钮是灰的，`click()` 什么也不发，对着空窗口量的会是「没反应」。

## 后果

- `ui/search_field.py`：`ScopeToggle` 少三个字段（`_active`、`_applied_active`、`set_filtering`），
  信号由 `toggled(bool)` 变成 `switched()`；`toggle_style` 少一个 `active` 参数，
  `scope_arrows` 少一个 `active` 参数（墨色恒定）。
- `ui/window/search_flow.py`：`_sync_search_scope` 少调一次 `set_filtering` —— 它现在同步的是
  **两处**（占位文字与菜单勾），不是三处。
- `ui/main_window.py`：`_on_scope_toggled(filtering)` → `_on_scope_switched()`，判据从信号带来的
  那个 bool 变成「当前作用域取反」。
- 作用域的机制**一个字没变**（仍是 ADR 0040 决策 1 的两档、仍是库级偏好、仍然只有
  `set_search_scope` 一个入口、仍然不清条件）；这次改的只是**那一枚按钮怎么画**与**它带不带
  参数**。
- 测试：`tests/ui/test_filter_flow.py` 那一族里换掉一条、加一条，其余用例把「按一下」从
  `setChecked(True)` 改成真的 `click()`（**并因此要开着库** —— 置灰的按钮 `click()` 不发信号，
  那是这一族新引入的一个坑）。

## 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 保留勾选态，但让**图标**两样（搜索 ⇄ 筛选各自一枚） | 两枚长得不一样的图标读起来像两个功能（ADR 0040 决策 5 已经因为这个理由用过同一枚）；而它们是同一个动作的两端 |
| 保留填充色，改成「显示下一次按下去会切到哪一头」 | 那就不是「此刻是哪一头」了，而占位文字已经在说此刻 —— 标题条上于是有三个说法，而其中两个说的不是同一件事 |
| 两段式分段控件（搜索 \| 筛选） | ADR 0040 已经否决过一次（胶囊左边要多长一截，且两格共享圆角轮廓要另写一遍绘制） |
| 按钮不摆状态、提示改成「按下去会做什么」 | 本来就该这么说 —— 但占位文字就在左边一格，而两支反向箭头已经说了「掉个头」；再加一句是第三处重复 |
| 干脆删掉按钮，只留菜单里那一条 | 作用域是这一族里用得最频繁的一次切换（「这一屏里没 Canon 的都去掉」），藏在菜单里等于把它埋了 |
