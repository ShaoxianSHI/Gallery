# ADR 0029：提示横幅覆盖在内容上，说完就走

- 状态：已接受
- 日期：2026-10-04
- 相关代码：`src/gallery/ui/banner_overlay.py`、`src/gallery/ui/main_window.py`、`src/gallery/ui/write_ops.py`
- 相关：[ADR 0005](0005-one-background.md)（整块窗口一个底色、刻意不建状态栏）、[ADR 0025](0025-rename-in-the-title-bar.md)（挂在窗口上的一层怎么摆位）、[ADR 0021](0021-viewer-context-menu.md)（大图页上「此刻作用于谁」）、[ADR 0024](0024-main-window-and-menus-split.md)（横幅措辞与入口的分工）、[ADR 0008](0008-delete-to-trash.md) / [ADR 0019](0019-copy-move-to-album.md)（做完之后横幅上那一句）

## 背景

横幅是「一次动作做完之后的那一句中文」，措辞在 `ui/banners.py`（一行 Qt 都没有），
显示在 `MainWindow`。它的**摆法**是二十来天前顺手定的：网格页那个竖排布局里的
`addWidget(self._banner)`，夹在面包屑与网格之间。三个毛病，都是用户每天都会碰到的：

1. **每一条消息都把网格往下挤一段。** 竖排布局少了一个成员，照片区就矮一截，
   网格重排、滚动位置跟着动 —— 而用户正要看的正是刚被挤走的那一屏。扫完库的那句
   「部分内容没能读取」尤其难看：它出现的那一下，屏幕上整屏照片都跳了一次。
2. **大图页上根本看不见。** 横幅是 `_grid_page` 里的控件，切到大图页它整个在背后。
   于是看照片时做的每一件事（⌘Z 撤销、⌘C 拷贝、⌘⌫ 移走这一张）说的那句话全部落在
   背后，用户得退回网格才知道刚才那一下到底做了什么。
3. **说过不走。** 「已重命名为…」「已把 3 项移到废纸篓。⌘Z 可以撤销。」这些**读完就没有
   新内容**的话一直挂着，把网格最下面那一排照片压住。

三个毛病是同一个成因：**把一条时有时无的话当成了一行永远在的内容**。

## 决策

### 1. 横幅挂在窗口上，**不进任何布局**

父控件是 `MainWindow` 自己，尺寸与位置自己算 —— 与 `TitleBar`、`SearchField` 同一手法
（ADR 0025）。摆位与高度是三段**纯算术**（`banner_width` / `banner_rect` / `text_height`），
因此不必造一个真窗口就能测。

**为什么不给它留一行**：面包屑同样浮在内容之上，我们还是给它留了一行 —— 因为它
**永远在**。横幅不是：一行位置有时有一个控件、有时没有，等于让底下所有东西每天
抖几十次。

细节：

- **横向居中、纵向浮在内容区顶边下方**（`MARGIN_TOP` 10 点）—— 那一带正好是面包屑所在
  的一行。盖的是**导航信息**而不是最后一排缩略图：面包屑过几秒就重新露出来（而且
  说过就走的那几句本来就只待四秒），而用户正在挑的永远是下面那几行照片。
  *这一条是按用户反馈定的*：第一版做在底部靠边处，用户看着「像贴着窗口边」，改到上面。
- **横向最宽 560 点**，长消息换行（高度按宽度算，不裁半行）。再宽就成了段落。
- **文字居中**（`AlignCenter`）。宽度是「装得下就多宽」，左对齐的话窄横幅永远偏在
  一侧，一眼看上去就是没摆正。回归测试量的是**画出来的墨迹**（哪几列有字）而不是
  `alignment()` 的值 —— 用户看见的是墨迹落在哪儿。
- **对鼠标透明**（`WA_TransparentForMouseEvents`）：它正压在网格上，忽略掉点击的话，
  点它就变成了点空处。
- **配色就是原来那一对橙色**：`rgba(255, 176, 32, 0.16)` 的底 + `0.45` 的边。换成别的
  颜色是把一件已经用过很久的东西改成另一件 —— 用户每天看惯了它。只有**字色**跟着主题
  走（原先写的 `palette(text)` 在 Qt 样式表里并不成立，实际走的是控件默认色，
  也就是正文色那一份）。
- 窗口改大小、换页、展开收起元数据面板之后都要重摆一次。**大图页上元数据面板摆着时，
  居中的是整个窗口而不是照片区**（`_banner_area` 拿中央控件自己的几何，面板交给
  `_banner_avoid`）。**原先是反过来的**（`_banner_area` 减去面板），2026-10-25 按用户反馈
  改的：面板摆着时横幅落在照片那一半的正中间，看着像只对照片说话，而它这一句说的是整个
  窗口里刚发生的事。
  *两件都要的做法是「位置一分不动、只收窄宽度」*：面板不该被盖住，于是把宽度收到
  「居中之后右边缘停在它左边」；收到 `MIN_AVOID_WIDTH` 240 点以下就不再让了 ——
  两三字一行的竖条比短暂压住面板左边缘更难认。**不能反过来把 `area` 缩掉**：那样中心点
  会跟着跑偏，跑掉的正是这次要治的那个毛病。

### 2. 两页共用同一个控件 —— 因此大图页上也看得见

这是「挂在窗口上」的直接结果，也是决策 1 的另一半：横幅不再属于某一页，于是用户在
大图页上做的每一件事的反馈都落在**他正在看的那张照片上面**，不必退回网格。

### 3. 哪些说过就走，哪些留着

判据只有一条：**用户看完要不要动手**。

| 说过就走（`auto_hide=True`） | 一直留着（默认） |
|---|---|
| 粘贴 / 复制到相册 / 移动到相册 / 移到废纸篓 / 撤销 / 改名的**成功**确认 | 上面任何一句里**含失败或没记上日志**的 |
| 新建相册、设为 / 取消相册封面 | 出错与「没能做成」 |
| 拷贝路径、拷贝文件、复制元数据、复制分组条件 | 「这一层是空的」与「部分内容没能读取」 |
| 在访达中显示、清空缩略图缓存 | 后台进度（它自己会被下一条更新或收尾取代） |
| 缩略图解码失败（后台消息，说完就走） | |

两点是刻意的：

- **默认是「留着」，要自动收必须显式点名。** 少标一条的代价是多挂四秒；多标一条的
  代价是**把用户还没看完的话收走** —— 后者要糟得多，所以默认值取保守的那一侧。
- **判据看的是结果对象，不是那句中文。** 移到废纸篓的那句里可能夹着「但 1 项没移走」
  与「⌘Z 撤销不了」，于是收不收起由 `result.failures` / `result.journaled` 决定
  （`not result.failures and result.journaled`）。**去中文里找「失败」两个字是条错路**：
  措辞一改就跟着错，而错过的那一次是「用户没看完自己被收走的话」。

时长 **4 秒**（`AUTO_HIDE_SECONDS`），比 `BANNER_STICKY_SECONDS`（2 秒，后台消息的让位期）
长：那句话刚显示的两秒里后台消息还在让位，之后到收起来之间还留着两秒，够扫一眼。

**「一直留着」不是「一直留着」：用户已经走到别处去了就收。** 大图页上**翻一张照片**
（← / →、面板上的 ← / →、甩一下）或**退回网格**时，横幅连同「谁占着它」的记账一起收掉
（`MainWindow._clear_banner`，2026-10-25 按用户反馈加的；原先只有回退上级文件夹 / 换库 /
进度收尾才收）。

理由不是「四秒太久了」，而是**那句话已经不对着眼前的东西说了**：它讲的是刚才那一张
（刚复制了它的路径、刚把它移走），而屏幕上已经是下一张、甚至已经不是大图页了 —— 它多半
又是那句默认留着、不自动消失的出错或后台进度，于是能一直压到用户退回去为止。

两点边界：

- **只清「大图页上那句」。** 网格页上自己出的那一句（「这个分组里没有照片了」）不在此列 ——
  写进 `show_grid` 时必须先判「现在真的在大图页上」，否则 Esc 连按、删一张之后都会把网格上
  刚出的话无声抹掉。
- **不能盖住「跳到下一张」之后才说的那句话。** 大图页上 ⌘⌫ 的次序是
  `write_ops.trash_selected` 里**先跳后说**：`_show_next_after_trash()` 在 `_show_banner()`
  之前。次序一旦反过来，「已把「b.jpg」移到废纸篓。⌘Z 可以撤销。」就是一句刚说完就消失的话 ——
  `tests/ui/test_trash_flow.py` 里有一条专门固定这个次序。

**记账必须与横幅一起清**（`_clear_banner` 挨个 `NoticeSlot.clear()` 加上 `_level_notice`）：
横幅没了而「谁占着它」的账本还留着的话，下一条后台进度会以为上面还写着自己的字而继续让着，
而 `_update_level_notice` 更会**收掉一条它并不拥有的横幅** —— 把用户刚做完一件事的那句话抹了。

### 4. 定时器归控件管，`hide()` 就停

收掉横幅的地方不止「显示下一条」一处：换层、换库、**翻图与退出大图**（决策 3 末段）、
进度收尾都是直接 `hide()` 的。
所以定时器在 `BannerOverlay.hideEvent` 里停，而不是只在 `show_message` 里重置 ——
只重置的话，先前那个定时器会在**下一条**消息刚显示时原样再收一次。

### 5. 定时器到了就 `hide()`，不淡出

Qt 的淡出要自己驱动一个动画，而这一条出现的时机（后台进度刚报上来）常常紧跟着另一条；
淡到一半被换掉只会比直接换更乱。半透明的底加上「没有动画」，读起来仍然是「一层浮在
上面」。

## 后果

- **横幅会盖住面包屑那一行几秒。** 这是有意换来的：网格与滚动位置一动，用户就得重新找
  「刚才看到哪儿了」，而盖住的那几秒他知道自己刚才做了什么（决策 1）。因为那一句多半
  说完就走，挡住面包屑的时间也就四秒。
- `MainWindow._show_banner` 多了一个 `auto_hide` 关键字参数（默认 `False`），写入操作
  那五个入口（`ui/write_ops.py`）各自点名。
- `tests/ui/test_chrome.py` 里多了两条回归测试：网格几何在出消息前后必须一模一样、
  大图页上横幅必须可见。**两条都验过**：把横幅放回竖排布局里，它们当场变红。
  `tests/ui/test_banner_overlay.py` 里另有一条量墨迹左右是否对称的（字要居中），
  同样验过：去掉 `AlignCenter` 就是 369 像素的偏。
- 样式表从 `main_window` 挪到了横幅自己身上（颜色还是原来那一对橙色）。因此
  `theme._push_palette` 文档里那句「网格页上就有一份横幅样式表」一并改了 —— 那份
  样式表现在跟着横幅走，而它是窗口的孩子，逐控件下发仍然覆盖得到。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 继续给它留一行，只是收窄一点 | 网格照样被挤动；问题不在宽窄，在「占行」 |
| 浮在**底边**靠窗口边处 | 看着像贴在窗口边上，也像半个状态栏（那个刻意不建）；第一版就是这么做的，用户要求改到上面 |
| 换成「实底 + 一道提示色的边」的新配色 | 一块压实的材料在照片上很好认，可它把原来那对橙色换掉了 —— 用户每天看惯的东西不该由这一条 ADR 顺手改掉 |
| 文字左对齐（QLabel 的默认） | 横幅宽度随文字变，左对齐的窄横幅永远偏在一侧；回归测试量墨迹，不量标志位 |
| 大图页上另摆一份横幅 | 同一件事两个真相源：两份都得记得更新，还会出现两页各说一句话的场合 |
| 做成底部状态栏 | 照片区少一行显示高度（`tests/ui/test_chrome.py` 守着的那条），而这里本来是刻意不建状态栏的 |
| 每条消息弹一个 `QMessageBox` | 一条消息一个对话框：扫一个库就能弹几十次，浏览无法进行 |
| 淡入淡出 | 见决策 5 |
| 收起来的时候顺带把滚动位置还原 | 网格压根没被挤动，没有「还原」可言；这条是照着一个已经不存在的毛病写的补偿 |
| 由中文里有没有「失败」二字来决定 | 见决策 3，措辞一改就跟着错 |
