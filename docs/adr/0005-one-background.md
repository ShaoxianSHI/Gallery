# ADR 0005：整个窗口共用一块底色，跟随系统主题

- 状态：已接受（第二轮修订：标题栏也交给我们画，底色改用内容区色）
- 日期：2026-10-05
- 相关代码：`src/gallery/ui/theme.py`、`main_window.py`、`viewer/detail.py`、
  `panels/metadata.py`、`panels/breadcrumb.py`

## 背景

窗口里套着好几层，各铺各的底色。实测（macOS 深色 / 浅色）：

| 层 | 系统给的颜色（深色 / 浅色） |
|----|------------------------------|
| macOS 原生标题栏 | `#3b3e3f` / `#f2f4f7`（半透明材质，随壁纸变） |
| 菜单栏、网格的窗口层（调色板 `Window`） | `#323232` / `#ececec` |
| 缩略图网格视口（调色板 `Base`） | `#171717` / `#ffffff` |
| 大图区、元数据面板（当年硬编码的 `#1C1C1E`） | 恒为 `#1C1C1E` |

后果是肉眼可见的接缝：浅色主题下点开照片会突然黑一大块，深色主题下则是三四种不同的黑。

第一轮只把颜色统一到 `Window`，结果同时踩了三个坑，都被用户一眼看出来了：

1. **标题栏匹配不上。** 它是系统画的半透明材质（`#3b3e3f` / `#f2f4f7`，还会随壁纸变），
   既不接受我们的调色板，也不可能用某个固定颜色对准它 —— 统一到 `Window` 之后，标题栏与
   下面仍然差一档。
2. **`QApplication.setPalette()` 会把应用调色板固定。** 显式设过一次之后，系统再换浅色 /
   深色时 Qt 不再更新它。表现就是「切到浅色，只有 macOS 画的标题栏跟着变浅，其余还是黑的」——
   自适应整个失效。
3. **`Window` 太浅。** 深色下 `#323232` 是一层灰，照片压不住；用户要的是更深的那种黑。

另外两个 Qt 行为决定了实现方式：

- 带样式表的控件会被 `QStyleSheetStyle` 塞一份**自己的**调色板，应用级的变化到不了它们
  （网格页上就有一份横幅样式表）。
- 自己画背景的控件（大图区、元数据面板）不会因为调色板变化而重画。

## 决策

### 1. 底色只有一个来源：系统调色板的 `Base`（内容区色）

`ui/theme.py` 是唯一入口：把 `Window` / `Base` / `AlternateBase` 三个铺底色的角色全部指向
`Base` 的那一个颜色 —— 浅色下是白，深色下是 `#171717`（比 `Window` 的 `#323232` 深得多）。

### 2. 标题栏那一段交给窗口自己画

`Qt.ExpandedClientAreaHint | Qt.NoTitleBarBackgroundHint`：去掉系统那层材质，客户区铺到整个
窗口，标题栏于是由窗口自己的底色来画，和下面连成一块（见 `theme.unify_title_bar`）。

实测过的两条边界：

- 红黄绿三个按钮仍由系统画在最上层，窗口标题文字也还在（深色下自动转成 `#969696`）；
- 内容区留在安全区内（顶部空出 28 点），面包屑不会挤到按钮下面 —— 所以**不要**顺手关掉
  `WA_ContentsMarginsRespectsSafeArea`，那正是它干的活。内容铺上去之后系统不再代劳拖动，
  拖动由 `MainWindow.mousePressEvent` 里的 `startSystemMove()` 接管。

### 3. 绝不调用 `QApplication.setPalette`

应用调色板是平台的地盘：它被固定的那一天，跟随系统外观就失效了。所以 `apply_theme` 只改
**控件自己**的调色板，并且遍历控件树逐个下发（带样式表的那一支不会自己跟上）。
每次建窗口都要重新下发一遍 —— 新窗口不会自动带上别人那份。

### 4. 跟随系统主题，两个信号都接

`paletteChanged` 与 `QStyleHints.colorSchemeChanged` 都连到同一个处理函数：谁先谁后、
是不是都发，各平台不一样，少接一个就可能漏掉一整轮。自己画底色的控件（大图区、元数据面板）
再连 `ThemeWatcher.changed`，重读一次颜色即可。

### 5. 文字色由底色派生，不硬编码

元数据面板的字色从主题派生：深色主题下是「浅字压深底」，浅色主题下自动变成「深字压浅底」。
提示 / 错误色按主题深浅各给一个，两者对比度都够。

## 后果

- 浅色：标题栏那一段、面包屑、网格、大图、元数据面板全是 `#ffffff`；
  深色：全是 `#171717`。真机截图逐点取色验证过，来回切换外观也成立。
- 大图区与元数据面板在浅色下从黑底浅字变成浅底深字。可读性由派生公式保证，
  `tests/ui/panels/test_metadata.py` 仍在量渲染出来的像素并卡对比度。
- 想改整体底色只改 `BACKGROUND_ROLE` 一处。
- 面包屑的路径段按钮显式设为透明，避免在 macOS 上又冒出一排系统按钮色的圆角块。
- 代价：换主题时要遍历控件树（几百个控件，毫秒级），且此后每个控件都持有显式调色板，
  不再随应用调色板自动继承 —— 所以**每次**换主题、**每次**建窗口都要重新下发一遍。
- 标题栏不再是系统那层材质：窗口没有标题栏底纹，标题文字仍由系统画在正中。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 固定深色（无视系统主题） | 覆盖用户的系统偏好；浅色系统下用户会看到一整个黑窗口 |
| 固定浅色 | 同上，反过来 |
| 底色取 `Window`（第一轮的做法） | 深色下 `#323232` 太灰，照片压不住；而且标题栏是另一层材质，取它也对不上 |
| 用调色板去匹配原生标题栏 | 那是半透明材质，实测深色 `#3b3e3f`、浅色 `#f2f4f7`，随壁纸变，匹配不准 |
| 用 `QApplication.setPalette` 统一下发 | 会把应用调色板固定，系统换外观时界面再也跟不上（这正是第一轮的 bug） |
| 标题栏盖一层毛玻璃（更早的一版，已回滚） | 那一段底下本来是空的，没有东西可糊 |
| 自己画无边框窗口 + 自绘红黄绿按钮 | 为了一个颜色去接管窗口装饰，代价远大于收益 |
| 给每层各留一点色差做层次感 | 层次靠分隔线与留白，不靠底色明暗差；色差正是这次要去掉的东西 |
