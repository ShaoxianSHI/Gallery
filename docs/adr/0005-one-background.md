# ADR 0005：整个窗口共用一块底色，跟随系统主题

- 状态：已接受
- 日期：2026-10-05
- 相关代码：`src/gallery/ui/theme.py`、`detail_view.py`、`metadata_panel.py`、`breadcrumb.py`

## 背景

窗口里套着三层，各铺各的底色：

| 层 | 改动前的底色 |
|----|--------------|
| 标题框（菜单栏）、面包屑那一层 | 系统调色板的 `Window` 角色 |
| 缩略图网格视口 | 系统调色板的 `Base` 角色 |
| 大图区、元数据面板 | 写死的 `#1C1C1E`（当年按「macOS 深色看图背景」定的） |

后果是肉眼可见的接缝：

- **浅色主题下最刺眼**：上面三层是三种相近的浅灰，点开照片却突然黑一大块；
  右侧元数据面板也是黑的，与浅色标题栏并排摆着。
- **深色主题下是三四种不同的黑**：系统窗口色、列表底色与写死的 `#1C1C1E` 互不相同。

同时有两个已知的 Qt 陷阱让这件事不能只靠改几个常量解决：

1. 带样式表的控件会被 `QStyleSheetStyle` 塞一份**自己的**调色板，此后
   `QApplication.setPalette()` 再也到不了它们（网格页上就有一份横幅样式表）。实测：
   改一次应用调色板，标题栏变了、网格那一层还停在原处。
2. 自己画背景的控件（大图区、元数据面板）不会因为调色板变化而重画。

## 决策

### 1. 底色只有一个来源：系统调色板的 `Window` 角色

`ui/theme.py` 是唯一入口：把 `Window` / `Base` / `AlternateBase` 三个铺底色的角色
全部指向同一个颜色，菜单栏、面包屑、网格视口、欢迎页于是自动是同一块底色。

选 `Window` 而不是 `Base`：macOS 的标题栏正是系统给 `Window` 的那个颜色。改用 `Base`
（内容区色）会让标题框那一段比正文浅一个色阶，最显眼的地方反而留着接缝。

### 2. 跟随系统主题，不固定深浅

系统切浅色 / 深色时（`paletteChanged`）自动重新统一一遍。自己画底色的控件
（大图区、元数据面板）各自连 `ThemeWatcher.changed`，重读一次颜色即可 ——
这样写死 `#1C1C1E` 的地方一个都不剩。

### 3. 换主题时把调色板逐个下发到控件树

因为上面第 1 条陷阱，`apply_theme` 在 `setPalette` 之外还会遍历所有顶层窗口的
控件树逐个 `setPalette`。只有这样，带样式表的那一支才会一起变。

### 4. 文字色由底色派生，不写死

元数据面板的字色从主题派生：深色主题下是「浅字压深底」，浅色主题下自动变成
「深字压浅底」。提示 / 错误色按主题深浅各给一个，两者对比度都够。

## 后果

- 浅色主题下大图区与元数据面板从黑底浅字变成浅底深字。可读性由派生公式保证，
  `tests/ui/test_metadata_panel.py` 仍在量渲染出来的像素并卡对比度。
- 想改整体底色只改 `BACKGROUND_ROLE` 一处；想换整套配色只改 `apply_theme` 里那次赋值。
- 面包屑的路径段按钮显式设为透明，避免在 macOS 上又冒出一排系统按钮色的圆角块。
- 代价：换主题时要遍历控件树（几百个控件，毫秒级），且此后每个控件都持有显式调色板，
  不再随应用调色板自动继承 —— 所以**每次**换主题都要重新下发一遍。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 固定深色（无视系统主题） | 覆盖用户的系统偏好；浅色系统下用户会看到一整个黑窗口 |
| 固定浅色 | 同上，反过来 |
| 底色取 `Base` 而不是 `Window` | 标题栏由系统按 `Window` 画，会在最显眼的地方留下色阶差 |
| 只统一网格与大图，标题栏不管 | 用户点名的就是标题框那一层；不统一等于没做 |
| 标题栏改成盖在照片上的毛玻璃（曾做过，已回滚） | 那一段底下本来是空的，没有东西可糊；照片顶到窗口上沿之后面包屑又和缩略图挤在一起 |
| 给每层各留一点色差做层次感 | 层次靠分隔线与留白，不靠底色明暗差；色差正是这次要去掉的东西 |
