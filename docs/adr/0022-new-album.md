# ADR 0022：网格空白处的「新建相册」⇧⌘N，建完就地改名

- 状态：已接受
- 日期：2026-10-12
- 相关代码：`src/gallery/core/metadata/album.py`、`src/gallery/core/library/facade.py`、`src/gallery/ui/menus.py`、`src/gallery/ui/main_window.py`、`src/gallery/ui/write_ops.py`
- 相关：[ADR 0004](0004-rename-on-disk.md)（约束 1：只许用户亲手触发）、[ADR 0013](0013-filesystem-watch.md)（新东西怎么显示）、[ADR 0018](0018-paste-into-current-folder.md)（只增不改的那类写操作）、[ADR 0014](0014-context-menu.md)（右键菜单的取向）

## 背景

访达在文件夹空白处右键有一条「新建文件夹」⇧⌘N，按下去当场多出一个文件夹，输入框直接摆
在它上面，光标已经在等用户起名。Gallery 能建相册吗？不能 —— 相册是磁盘上的子文件夹，
用户要新建只有两条路：在访达里建，或者复制一个已有相册再删掉里面的照片。

相册是 Gallery 里唯一一种「用户自己造出来的」条目。照片是从相机 / 手机里同步过来的，
而「2025-苏州」这种分层是用户自己的分类习惯，软件没有理由替他猜，也不能替他建。

## 决策

### 1. 建在「当前这一层」对应的那个文件夹里

| 当前这一层 | 建在哪 |
|---|---|
| 相册模式（在某个相册里） | 当前这一层的文件夹；顶层就是库根 |
| 全部照片 | 库根（整层是平铺的，唯一说得清的目录是它） |
| **分组里** | **没有** —— 菜单里不出现这一条，快捷键也置灰 |

分组那条与粘贴（ADR 0018 决策 1）看似同一个理由，其实更硬：分组是元数据切出来的视图，
**网格上那一层摆的全是照片**，新建出来的相册卡片插进去就是错的东西。粘贴至少还有个
「这一组照片本来就在同一个相册」的目录可说，分组里连这个都没有。

判据与粘贴共用同一个入口（`MainWindow._level_directory`），因此「粘到哪去」与「建到哪去」
永远不会说出两个答案。

### 2. 默认名「新建相册」，撞名就按访达的规矩改叫「新建相册 2」

**绝不覆盖**已有目录 —— 那可能是用户自己整理出来的。编号规矩与粘贴、移动到相册是同一份
实现（`core.metadata.naming.free_name_in`），不做第二套。

不用「未命名相册」：菜单项叫「新建相册」，默认名就叫它，用户一眼知道刚才是自己干的。

### 3. 建完**立刻进入行内重命名**，走的是既有的那条路

这是访达那个手感的关键，也正好复用了 Gallery 已有的行内重命名（ADR 0004）：新相册那一格
选中着，名字那一行变成输入框，直接打字就是改名字，回车确认。

于是**紧接着的那一次改名是普通改名**：记账、`⌘Z` 可撤销。这条必须说清楚 ——
`⌘Z` 撤得回的是**名字**，不是那个空文件夹本身（理由见决策 5）；文件夹要删就选中它按
`⌘⌫`，那条路有日志、能再撤销。

### 4. 立刻显示，不等监听器

监听器（ADR 0013）要等文件系统事件，这一来一回有几十毫秒；而行内重命名**必须有那一格**
才能开始。所以界面自己把它插进模型（按扫描器的排序插到该在的位置），同时把这一个路径记进
「自家写操作」集合，监听器稍后报上来的同一件事不会重复应用 —— 与改名、删除那几处完全一致。

### 5. 只增不改、不进撤销栈，但记账

- **只增不改**：建出来的是一个**全新的空文件夹**，用户的照片一个字节都没动，
  原有目录结构也没被改动 —— 变的只是「这个目录里多了一项」。它不碰任何照片，
  不移动任何东西，因此不触犯约束 1。
- **不进撤销栈**：撤销一次新建就是**删掉一个文件夹**，而删除在这个项目里只允许用户在
  界面上亲手触发（约束 1）。`undo._PUSH_ACTIONS` 不收它，于是 `⌘Z` 那一摞栈照旧只装
  改名、移到废纸篓与移动到相册。
- **仍然记账**：写一条 `action=create` 的日志（建在哪、建了什么、什么时候、结果如何）。
  记账失败不推翻已经建成的文件夹，由界面如实说明。
- 紧接着那一次改名照旧记账、照旧可撤（决策 3）。

### 6. 不走后台线程

`mkdir` 是一次系统调用，不搬数据（粘贴一次几百 MB，那才是必须走后台的量级）。放在主线程上
调用，用户按下快捷键到看到输入框之间没有可感知的等待。

## 后果

- 网格上会动用户文件的入口从四条变成五条（新增「新建相册」）。它与粘贴同属「只增不改」那一类：
  只记账、`⌘Z` 撤不掉、绝不覆盖。README 的快捷键表、右键菜单表与那条说明都已改。
- 相册从此可以是 Gallery 里造出来的：用户不必先去访达挖一个空文件夹。
- 新建出来的空相册在网格上画文件夹图标（流水线问过一次「里面第一张照片」没有就作罢），
  与用户在访达里手工建的空文件夹完全一样。
- 一个空文件夹躺在库里是个合法状态，Gallery 不去清理它、不提醒它空着。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 弹 `QInputDialog` 问名字 | 访达不做这一步。问了就得多一次回车，而行内改名已经是这个软件里现成的交互 |
| 建完**重扫当前这一层** | 会清空网格（选中与滚动位置全丢），而这次改动只有一行 |
| 建完只弹横幅、不进改名 | 用户得自己再点一次「重命名…」；访达是建完就等光标 |
| 建完进 `⌘Z` 撤销栈 | 撤销就是删文件夹，删除只许用户亲手触发（约束 1） |
| 进撤销栈但「撤销 = 移到废纸篓」 | 同上；而且照片进废纸篓是另一条需要用户明确点头的操作 |
| 批量新建（模板、`2025-01` … `2025-12` 一次建） | 「后台整理」是约束 1 明确排除的：软件替用户造出一批目录，用户没点头 |
| 分组视图里也建（建在这一组照片共处的那个相册里） | 那一层网格上只有照片，插进去的是一张相册卡片，位置就不对了（决策 1） |
| 默认名用「未命名相册」 | 与菜单项不同名，用户不知道刚才是自己干的 |
