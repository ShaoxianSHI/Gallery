## 背景

分组目前只有一种呈现：每组在网格里占**一格**（封面 + 组名 + 张数），双击进入才看得到组员。
想「一边翻一边看」的时候这种形态不合适 —— 同一时刻只看得到一个组，而且进入、退出各要一次
双击 / 一次 `Esc`。用户要的是 Finder 图标视图那种分组：**照片连续铺开，每组开头一条标题与
分隔线，一屏里能同时看到好几组**。

ADR 0009 当时否决过它，理由写得很具体：「那要求网格支持跨列的标题行，而 `QListView` 的
IconMode 每个条目占一格，要做就得整块重写排版」。这个前提**不成立**：IconMode 在关掉
`gridSize`、打开逐条 `sizeHint` 之后，会按条目自己的宽度从左到右摆、行高取该行最大值；一个
「宽度 = 整行」的条目装不下当前行时会换到下一行，正好把那一行占满。整行标题因此不需要写
排版引擎，代价只是逐条问一次尺寸（实测 3000 条约 6.9 ms，与文档里记的旧数字同一量级）。

## 决策

### 1. 两种形态叫「卡片式」与「分区式」

- **卡片式**：现状，每组占一格，双击进入；
- **分区式**：新增，每组开头一条整行标题 + 分隔线，照片连续铺开。

入口在 `分组` 子菜单**末尾、分隔线之后**，两项互斥、可勾选，与 `排序` 里的 `升序 / 降序`
同一套位置与勾选机制（菜单栏与右键空白处共用 `_fill_group_menu`，所以两处自动一致）。
选「不分组」时**两项置灰**（不给提示）：它们描述的是分组长什么样，没有分组时无从谈起。
偏好是**库级**的，存进 `.gallery/config.toml` 的 `[ui] group_layout`（与分组字段、排序方向
同一处，换库各算各的）。

### 2. 分区标题是模型里的一行，不是层级栈的一帧

分区模式下模型的行是「相册卡片…，分区标题，照片…，分区标题，照片…」。标题行**不可选中、
不可获得焦点**（`flags` 去掉 `ItemIsSelectable` 与 `ItemIsEnabled`）。Qt 自己就会跳过它：
点按、双击、`⌘` 点、`⇧` 点、`⌘A`、方向键、橡皮筋框选都不会落到它身上，模型重置后也不会
把它设成当前项 —— 「不能改名、不能删、不能打开」因此不需要在每个命令里各写一遍。

由此：

- 分区模式下**不存在 `GroupFrame`**：双击标题什么都不发生，`Esc` 仍是「退上一层」，
  面包屑不出现组名。切换模式时把栈上的分组帧弹掉（与换分组字段同一句）。
- **组级命令挂在标题上**：右键标题弹的是**这一组**的菜单，不是选区的那份 ——
  「编辑事件…」「把照片移出事件」「清除事件封面」（事件分组时）与「复制分组条件」。
  这几条只作用于标题代表的那一组，因此不会误动「上次选中、此刻看不见」的那批照片。
  **打开 / 在访达中显示 / 拷贝 / 移到废纸篓这类作用在选区上的命令一概不出现**：
  标题不在选区里，把它们摆出来等于让命令作用在别的对象上。
- **一张照片只出现在一个分区**：按关键词分组时一张照片可以属于多个组，而模型靠「同一路径
  只有一行」撑着（`_row_by_path`、`shows_path`、缩略图回填全依赖它）。分区模式下**先到
  先得**，标题上的张数是这一行下面**实际显示**的张数，所有分区的张数加起来等于这一层的照片
  数。空掉的分区（成员全被前面的分区拿走）不产生标题。
- 分区模式**不改任何归属计算**：`build_groups` 一字不动，只是渲染方式不同。

### 3. 排版：逐条 `sizeHint`，不重写排版引擎

- **卡片式继续 `setGridSize()` + `uniformItemSizes(True)`** —— 现有排版、列数核对与滚动范围
  行为一字不改。
- **分区式**：`setGridSize(QSize())` + `setUniformItemSizes(False)`；委托对照片返回格子尺寸，
  对标题返回 `QSize(排版宽度, 36)`。标题因此独占一行并强制换行。
- 标题的排版宽度取 `_layout_width()`（已经无条件扣掉滚动条那一档），由网格写给委托；
  右边最多留十几个像素，与照片区本来留的那点空隙一致。
- `_first_row_columns()` 改成**分区感知**：不能量第一行（第一行可能是标题，或因标题换行而
  少摆一格），要量**一段成员数够了的分区**的第一行。这条不成立时切档动画与锚点会整体漂。
- `visible_rows()` 改成**按布局快照二分**：标题插进来之后，按格高步长采样 `indexAt` 会漂移、
  整行照片漏掉。

### 4. 切档动画改用「两份布局快照」，不再用行号算术

现有过渡建立在「第 row 格位置 = `(row // 列数) × 格高`」上，分区模式有三处打破它：标题行
夹在中间、行高有两种；列数一变，后面所有分区的位移量取决于它前面有几个标题；标题的尺寸与
照片不同，一个 `cell` 描述不了。

新增 `ui/browser/layout.py` 的 `GridLayout`（纯像素数学，不碰 Qt 的事件与绘制）：

```
GridLayout(columns, cell, header, spans)
  rect(row) / top(row) / height(row)   # 标题整行宽；成员按 columns 铺开
  rows_near(top, bottom)               # 二分，给可视区与预取
```

`GridTransition(old: GridLayout, new: GridLayout, scroll_shift)`：

- 位置与尺寸在两份快照之间插值，标题两端尺寸相同，于是**只平移**；
- 第 0 帧仍是切档前那一屏（含标题在旧位置），末帧就是最终布局 —— 与今天同一条不变式；
- `_frame_top` / 行窗口二分、锚点（「用户正看着的那一格」保持原位）、居中滚动全部问同一份
  快照；`old_columns / new_columns / old_cell / new_cell` 退成快照的派生属性，既有测试的
  判据一个字不用改；
- 几何在切档那一刻一步到位，动画只碰绘制 —— 这条分界线不变。

**标题自己跟着滑到新位置**（它也是模型里的一行，过渡期间由 `_paint_transition_viewport`
画出来），并且铺一层不透明的 `palette.Base` 底：动画中不同条目的位移量不同，标题会短暂压到
上一分区最后一行照片上，透明底会让照片从字里透出来。正常状态看不出区别（底下本来就是底色）。
不做粘性标题（滚动时吸顶）—— Finder 的图标视图也没有。

### 5. 分区模式下的就地写操作

删照片、粘贴、改名换扩展名（可能换组）都会让「谁属于哪一段」过时。处理与卡片式同一取向：
**整层重算**（`_level_is_grouped()` → `_reload_level`）。监听器那一路本来就这么做（ADR 0013
决策 3 的那条例外），补的是「删除之后如果这一层是分组的，直接重排」，顺带摘掉空掉的标题。

## 后果

- 同一屏能同时看到多个分组；「进入分组」只在卡片式里存在，`GroupFrame` 的语义因此更干净：
  它只表示「用户点开了一张卡片」。
- 模型里多了一种条目（`SectionRef`），`counts()`、`display_name`、缩略图窗口、筛选总数、
  右键落点各要认它一次；每一处都有回归测试盯着「标题不是照片」。
- 一张照片在分区式里只出现一次（按关键词分组时），与卡片式的「可以在多张卡片里看到」不同。
  这是模型不变量的直接结果，不是取舍。
- 全量排版从 1.7 ms / 3000 条涨到 6.9 ms / 3000 条（实测，卡片式不变）。分组本身已经是
  O(n) 重算，切档与拖窗口才会碰到排版，同一量级内接受。
- 分区式里没有「组卡片上的打开 / 在访达中显示 / 拷贝 / 移到废纸篓」：那些命令作用于选区，
  而标题不进选区。要拷走一整组，选中标题下面那段照片即可。

## 被否决的方案

- **伪条目占位**（把剩下的格子填成空条目强制换行）：列数一变就得重算占位行，而它发生在切档
  开始那一刻 —— 改模型就是 `modelReset`，动画当场作废；行号也不再等于条目下标。
- **`QTableView` 多列 + `setSpan`**：能力最全，但模型要变成二维，`index.row()` 不再等于条目
  下标，`select_row` / `row_of_path` / `entry_at` / 写操作里「`currentIndex` 配 `entry_at`」
  那一类组合会静默错位。为一个显示形态不值得。
- **每个分区一个子网格**：分区数可以上千（按天分组），选择、键盘、框选、缩略图流水线、切档
  都要跨控件协调。
- **只画分隔线不换行**：一条横线要么穿过一行照片，要么落在一段与组边界无关的位置，标题会
  和上一组的照片挤在同一行。
