# ADR 0093：视频的外部播放器 IINA——固定在详情页第一位

- 状态：已接受（决策 3 的「IINA 固定第一」由 0095 改成「播放器占最前一段」）
- 日期：2026-10-25
- 修改：[0080](0080-external-app-order.md) 决策 3 的「没提到的 id 一律排在后面」—— IINA 例外；
  [0092](0092-video-metadata-panel.md) 决策 4 的「视频面板给一句只读理由」—— 改成只把按钮置灰。
- 相关 ADR：0034（用外部应用打开）、0067（大图页的图片应用白名单）、0080（外部应用次序）、
  0092（视频的元数据与 GPS）
- 相关代码：`src/gallery/core/external/apps.py`、`src/gallery/ui/main_window.py`、
  `src/gallery/ui/window/widgets/external_button.py`、`src/gallery/ui/window/settings_flow.py`、
  `src/gallery/ui/viewer/video.py`、`src/gallery/core/library/index.py`

## 背景

视频大图页的外部应用下拉框里原来只有访达 / QSpace，以及有 GPS 时的两个地图；图片应用
（预览 / ImageGlass）被 `_viewer_ready` 明确挡在视频之外。用户希望在应用里放不了的时候，
**用专门的视频播放器 IINA** 接着看，而且它应该排在视频页的第一位。

两件事要一起回答：

- **旧的自定义次序里没有 IINA。** ADR 0080 决策 3 说「没提到的 id 保持内置次序排在后面」，
  于是新加的这一项会排到最后，与「第一位」相反。
- **IINA 只对有视频的页面有意义。** 放进图片应用那份白名单（`VIEWERS`）会让它在照片页上也出现。

地图那两项不需要新逻辑：`_map_point` 本来就不看文件类型；需要的是让**已有的索引行**重新读到
视频的 GPS（ADR 0092 把 `QuickTime:GPSCoordinates` 加进 `WANTED_TAGS` 时，老行里还没有它）。

## 决策

### 1. IINA 是独立的一项，只在视频页出现

`core.external.apps.IINA`：`id="iina"`、显示名 `IINA`、bundle id `com.colliderli.iina`。
**不放进 `VIEWERS`**：那是图片应用的白名单，IINA 是视频播放器。`ExternalEntry` 的 `pages`
只有 `detail`，`enabled` 是「大图页上正看着一个视频，且本机装着 IINA」，`available` 是
「本机装着它」—— 没装就整条不摆，与预览 / QSpace 同一条判据。

### 2. 交给 IINA 之前先暂停应用里的播放器

`desktop.open_with_app([视频路径], app=名册查到的那条路径, name="IINA")` —— 与 ADR 0067 同一套：
递的是文件自己的路径、应用包路径由 Launch Services 给、中文显示名只进文案。
**先 `VideoView.pause()`**：不暂停的话两个播放器会同时出声。暂停而不是 `stop()`：交接失败
（IINA 被移走、`open` 起不来）时页面还在，用户点一下就能接着看；`stop()` 会把这一页清成黑屏，
那时连播放按钮都没有对象可作用。

### 3. IINA 固定第一，但不改 ADR 0080 的通用规则

内置次序里 IINA 排在最前。用户存下的次序里**没有** IINA 时，`order_for_page` 把它补在最前；
用户自己排过之后（设置对话框也读同一份有效次序，保存时就把 IINA 写进去了）以存下的为准。

**只给 IINA 开这一个例外**，不改「没提到的 id 排在后面」：后者是卸载残留与将来新应用共用的
兜底，改成「按内置位置插入」会改变所有人的自定义次序，收益只有这一项。

### 4. 地图对视频不需要新代码，但索引要重建一次

`_map_point` 先读面板缓存、再读索引，两步都不看文件类型；视频有坐标时「地图」与
「Google 地图」本来就会出现。已有库里的视频行是在 ADR 0092 之前写的，没有 GPS 这一栏，
于是把索引的 `SCHEMA_VERSION` 从 7 升到 8：整表重建一次（索引是缓存），重新读一遍 GPS / 相机。
没有坐标的视频（微信导出、屏幕录制）仍然不摆地图 —— 没有落点可开。

### 5. 视频面板只把「编辑元数据」置灰，不再多一行理由

ADR 0092 原先让面板在「位置」标题旁写「视频的元数据是只读的」。视频页上这句是噪音：
按钮灰着已经说明了。`set_metadata_editable(..., notice=False)` 只置灰、不摆理由；
照片那条路（没装 exiftool）仍然照旧把可行动的理由写在原处。

## 后果

- IINA 装了就在视频页摆着，排在 QuickTime Player 之后（ADR 0095）；没装就整条不出现。
- 存过自定义次序的会话：IINA 会被补到详情页最前，直到用户在「设置 › 外部应用顺序」里
  动过一次（那次保存会把 IINA 写进次序，此后完全按用户的排法）。
- 索引在下次打开库时重建一次；重建完带 GPS 的视频才会出现两个地图。
- 没有新依赖：IINA 是用户自己装的；应用只按 bundle id 问一次名册、起一个 `open` 进程。
- 视频面板少一行字，按钮仍然不可点；照片的写回那条路一个字节都没变。

## 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 把 IINA 放进 `VIEWERS` | 那是图片应用的白名单，会在照片页上多出一项打不开的软件 |
| 交接前 `stop()` 而不是 `pause()` | 起不来时页面被清成黑屏，用户没有可点的播放对象 |
| 改 ADR 0080 的通用规则为「没提到按内置位置插入」 | 影响所有应用的自定义次序，收益只有 IINA 这一项 |
| 用 `open -a IINA` 按名字开 | `open -a` 不认显示名，名称随发行版 / 系统语言变（ADR 0034 / 0067） |
| 没有 GPS 也摆地图 | 点下去只能开一张空白地图；没有落点就没有对象 |
| 给视频面板保留「只读」那句理由 | 用户看到的是一个灰按钮加一行多余的解释；按钮本身就说明白了 |
