# ADR 0021：大图页的右键菜单 —— 与网格那张几乎一致，只把「打开」换成「退出」

- 状态：已接受
- 日期：2026-10-07
- 相关代码：`src/gallery/ui/viewer/detail.py`、`src/gallery/ui/menus.py`、`src/gallery/ui/main_window.py`
- 相关：[ADR 0014](0014-context-menu.md)（网格那四种落点）、[ADR 0019](0019-copy-move-to-album.md)（复制 / 移动到相册）、[ADR 0008](0008-delete-to-trash.md)（移到废纸篓）、[ADR 0018](0018-paste-into-current-folder.md)（粘贴粘到哪一层）

## 背景

[ADR 0014](0014-context-menu.md) 决策 1 明确写了「**这一版不做大图页的右键菜单**」，理由是
「删完之后网格里的选中落到哪、`_current_row` 怎么对账」这笔账当时没算。那笔账的另一半是**页面
本身**：大图页没有选区可言（网格还在下面，但用户在看的是 `_current_row`），于是菜单里那些
命令作用到谁，得先说清楚。

用户的要求很具体：**在照片上右键，弹出的菜单和缩略图上单张照片那张基本一致，只把最上面的
「打开」换成「退出」，快捷键写上 Esc 的图标**。这是一次范围明确的需求，而不是一次重新设计 ——
所以这一条 ADR 记的是「照做时要算清的那几笔账」，不是菜单该长什么样。

## 决策

### 1. 大图页是第五种落点，菜单逐行相同，只换第一行

`TargetKind` 加一个 `DETAIL`，`build_detail_menu` 走**同一个** `_add_open_and_reveal` 出口
（`closing=True`），而不是另写一张菜单：行序只有一份，将来改一条命令不必记得改两个地方。

第一行是「退出」，最右列写 `⎋` —— 与「打开 ↵」同一枚机制
（`ShortcutColumnMenu.show_key`，**只画不生效**）。不给它真快捷键：大图页上的 `Esc` 已由
`DetailView.keyPressEvent` 接走（用户按 Esc 要回网格），两个动作抢同一个键，谁先触发全看加载顺序。

ADR 0019（复制 / 移动到相册）是同一轮里落地的，它给照片菜单加的两条也照旧出现在大图页：
它们作用于整个选择，而大图页的「整个选择」就是正在看的那一张（下面决策 3）。移走的那张由
监听器在**回到网格时**才从这一层摘掉（ADR 0013：变化在大图页攒着），所以这一页不会看着行号
突然错位。

### 2. 没有「粘贴」

网格那张菜单里「粘贴」出不出现只看剪贴板（ADR 0018），而大图页连「当前这一层」都没有 ——
那一层随时可能被换掉，粘到哪说不清。整条不出现，不摆一条点不动的。

### 3. 作用对象由 `_selected_entries()` / `_focus_row()` 统一给：大图页 = `_current_row`

**这是这一页最容易出的错。** 翻图（`←` / `→`）只动 `_current_row`，网格的选区停在打开大图的
那一格 —— 照网格选区算，「在访达中显示」「拷贝路径」「复制元数据」作用到的会是一张**屏幕上
根本没有**的照片。两个方法（连同它们驱动的 ⌘C / ⇧⌘C / ⌘⏎ / ⇧⏎）因此都按「此刻作用于谁」
回答，而不是「此刻选中了什么」。

顺带改掉一个巧合：大图页按 `⇧⏎` 从此是「在默认应用中打开」（原先它落到 `DetailView` 里成了
回车，于是顺带退回网格）。菜单里那一条亮着，按下去就该是那一行说的事。

### 4. ⌘⌫ 删掉正在看的那一张，**接着看下一张**

这是 ADR 0014 当年推迟的那笔账，现在算清：

- 作用对象是 `_current_row` 那一格，摘行也只摘那一行；
- 落在哪一格复用网格那套 `_select_after_removal`（原位，没了就是最后一格）—— 于是「下一张」
  正好顶上来，没有下一张就看上一张；
- **大图页与网格必须从此指着同一格**：`_current_row` 与网格当前项对不上时，⌘Z 取回来的照片
  会插到别处去；
- 只有两种情况退回网格：那一格是相册 / 分组卡片，或整层一张照片都不剩了。留在一张已经不
  存在的照片上，比退回网格更糟。

用户明确不要「删完退回网格」：看照片时最顺手的动作是「这张不要，下一张」。

### 5. 「重命名…」摆着但置灰

行内改名的输入框在网格里，大图页的改名字段还没有。**按用户要求先把菜单摆好，写回与 UI
留到接字段的那一条决策里。** 置灰而不是「亮着但不接线」：点下去什么也不发生的行，
比灰着的行更让人以为软件坏了。网格那一侧的重命名一个字没改。

> **已被 [ADR 0025](0025-rename-in-the-title-bar.md) 接管**：改名字段后来落在大图页的
> 窗口标题栏里（`⌘R`），这一行于是亮了。当时说的「只需要改 `_update_action_states` 里
> 那一处判据」也确实如此。

### 6. 画面还空着时不弹菜单

`DetailView` 按 `has_image` 挡着：正在解码、或上一次解码失败时，那不是一张照片，菜单里每一条
命令的对象都不存在。

## 后果

- 写操作在大图页上有了真实路径。ADR 0008 列的「大图页不能删」这条边界因此收窄为「删完接着
  看下一张」，本 ADR 决策 4 是它现在的样子。
- `_selected_entries()` 语义变了：它回答的是「这些命令作用于谁」。它驱动着删除、拷贝、拷贝路径、
  在访达中显示四处，因此这四处一起变成了「按页面算」—— 这是有意的，两处界面必须说同一句话。
- 大图页的「重命名…」当初是一条灰着的行，接通它只需要改 `_update_action_states` 里那一处
  判据，菜单与接线都已就位（见 [ADR 0025](0025-rename-in-the-title-bar.md)）。
- 「移动到相册」在大图页把正在看的那张搬走之后，**这一页仍留着它**（模型的变化要等回到网格
  才应用）。想让它跟 ⌘⌫ 一样接着看下一张是另一笔账 —— 搬走之后那一层未必还有同一张照片，
  且它与撤销的语义不同（撤销一次移动仍然是一次移动）。用户没有提，先不做。
- README 的右键菜单表多了一行（落点：大图）。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 大图页只放不改动文件的那些命令 | 用户要的是「基本一致」；只读的一半会让这一页的菜单与网格那张对不上，用户要对照着认 |
| 「重命名…」在大图页干脆不出现 | 用户要求先摆好菜单。置灰已经说清了「还没有」，不出现就看不出这份菜单的形状 |
| 删除后退回网格 | 用户明确要接着看下一张（见决策 4） |
| 把「粘贴」也放进去 | 那一页没有「当前这一层」，粘到哪说不清（ADR 0018） |
| 给「退出」一个真快捷键 `Esc` | `Esc` 已由 `DetailView.keyPressEvent` 接走；两个动作抢同一个键，谁先触发全看加载顺序 |
| 大图页另写一张菜单 | 行序会变成两份，改一条命令要改两处，而两处迟早不一样（ADR 0014 被否决方案里的同一条） |
