# ADR 0084：影片评分改成 1–5 的选择按钮

- 状态：已接受
- 日期：2026-10-24
- 相关 ADR：0043（事件的字段定义）、0063（影片事件）、0068（影片来源）、0082（更多来源）
- 相关代码：`src/gallery/core/events/kinds.py`、`src/gallery/core/events/models.py`、
  `src/gallery/core/events/conversions.py`、`src/gallery/core/events/schema.py`、
  `src/gallery/ui/dialogs/event_edit.py`

## 背景

旅行与演出的评分早就画成**一排五个按钮**（1–5，再点一下取消），影片的评分却还是一格文字输入框。
同一个「评分」在两类事件里长得不一样，用户要记两套操作；而影片这一格原先声明成 `REAL`，
本意只是「先让来源站的小数存进来」，界面上从来没有半星可选。

JavDB 给的是两位小数（例如 `4.59`），而面板上只有五个整数按钮。直接换成按钮而不处理旧值，
会出现「打开一个旧影片、按保存，评分被清空」：`4.59` 与任何一个按钮都对不上，写回去时会归一成空。

## 决策

### 1. 影片评分与旅行 / 演出共用同一档

`MOVIE` 的 `rating` 改成 `INTEGER`，值域用与另外两类同一个 `RATING_CHOICES`。面板由字段定义
生成，所以这一处改完，界面自动变成五个按钮，`event_edit.py` 不需要认识影片。

### 2. 来源站的小数四舍五入，收不进去就当没评分

`MovieInfo.to_draft` 把 `4.59` 写成 `"5"`，`0` 与 5 以上写成空。规则集中在
`kinds.rating_text`：来源站用 `0` 表示「还没有人评」，而界面只有 1–5。

### 3. 已有影片的评分在 3 → 4 迁移里就地归一

一条显式 `UPDATE`：`ROUND(rating)` 落在 1–5 就取整，否则写 `NULL`。**不重建表、不动事件本身**，
其余字段一个都不碰。旧库的评分列声明仍是 `REAL`，SQLite 会把它读成 `5.0`，所以
`conversions._from_sql` 把整数值的浮点收成 `int` —— 否则面板上那个按钮叫「5」而库里读回 `"5.0"`，
两者永远对不上。

## 后果

- 影片评分不再保留小数：`4.59` 与 `4.49` 都显示成 4 或 5，这是「只有五档」的必然代价。
- 旧事件库升到版本 4 之后，原本的 `4.59` 会变成 5、`0` 会变成空；这是一次不可逆的归一，
  但它让「打开旧影片按保存」不再清空评分。
- 三个来源里只有 JavDB 给评分；其余来源的这一格本来就是空的。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 保持输入框，只把提示改成「1–5」 | 没有解决用户报的问题：两类事件的同一个字段仍然长得不一样 |
| 保留 `REAL`，只加 `choices` | 新写入会变成 `5.0`，旧的小数也没有按钮可选；面板打开再保存就会丢值 |
| 评分改成半星 / 十档 | 用户要的是与演出一致的五档；半星还要另做一套按钮与迁移 |
| 迁移时重建 `event_movie` 表把列声明改成 `INTEGER` | 事件是重建不出来的用户数据；列声明的亲和性不影响读写，读那一侧归一一次就够 |
