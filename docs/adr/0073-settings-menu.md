# ADR 0073：顶层「设置」菜单，应用级与库级偏好各存各的

- 状态：已接受
- 日期：2026-10-22
- 相关 ADR：[0014](0014-menu-bar.md)（菜单栏）、[0038](0038-cache-in-library.md)（库级偏好住在
  `config.toml`）、[0050](0050-one-sync-entry-point.md)（界面由状态算出来的映射只有一个编排点）、
  [0063](0063-movie-events-and-import.md)（`movie_site` 只作用于 JavDB 来源）
- 相关代码：`src/gallery/ui/window/settings_flow.py`、`src/gallery/ui/motion.py`、
  `src/gallery/ui/theme.py`、`src/gallery/core/library/session.py`、
  `src/gallery/core/library/facade.py`、`src/gallery/core/media/thumbs.py`

## 背景

到 0072 为止，能调的偏好分成两半：一半在菜单里（浏览方式、排序、缩略图档位），另一半只能
手改文件 —— 影片网站前缀 `movie_site`、缓存上限 `max_cache_bytes` 在库的
`config.toml` 里，动画时长则散在四个常量里（网格切档 160 ms、大图适应窗口 220 ms、
切换淡入淡出各 450 ms），连手改的入口都没有。

macOS 上这些东西通常收在一个设置窗口里。但本项目的菜单栏是自建的（文件 / 编辑 / 视图），
没有现成的应用菜单可挂；而眼下要做的几项都是「在几个离散档位里选一个」，一个菜单就能表达。

## 决策

### 1. 顶层「设置」菜单，不新建设置窗口

菜单栏变成四条：**文件 / 编辑 / 视图 / 设置**。分三组，自上而下：

```
动画速度 · 外观
影片网站 · 缓存上限
放映间隔 · 启动时打开上次的库
打开日志文件夹 · 关于 Gallery
```

**这一段的分组已由 [ADR 0099](0099-settings-menu-three-groups.md) 取代**（菜单栏现在叫
文件 / 编辑 / 显示 / 设置，设置里按话题分三段）；「顶层菜单 + 不建设置窗口」这条不变。

将来真要做设置窗口时，再把这几组搬进去；菜单项与设置项共用同一份动作，不产生第二套状态。

### 2. 应用级写会话，库级写 `config.toml`

| 项 | 作用域 | 存哪儿 |
|---|---|---|
| 动画速度、外观、放映间隔、启动行为 | 这个应用 | `state.json` 的 `preferences`（`AppPreferences`） |
| 影片网站、缓存上限 | 这个库 | `config.toml`（经 `Library.set_movie_site` / `set_cache_limit`） |

**判据是「换库该不该重来」**：动画速度与外观不该因为换了照片文件夹就变回默认；影片网站与
缓存上限则是这个库自己的事。两类混在同一张菜单里，但换库时只刷新后两组的勾选态 —— 走
`_sync_ui` 的第六份映射 `_sync_settings`，与其余几份一样是「从状态算出来」。

库级写入**只能经 `Library`**：界面不拼路径、不改配置文件。配置目录建不出来（只读卷、网络
共享）时抛 `ConfigError`，横幅如实说明，而不是静默不保存。

### 3. 动画速度只缩放动画，四档：慢 / 中 / 快 / 关

倍率 1.6 / 1.0 / 0.6 / 0。「中」就是改动前那些数字，所以默认体验不变。

**只缩动画时长**：横幅停留、防抖、轮询各自另有约束（自动收起必须长于停留；捏合限速必须
不短于切档动画），跟着一起缩会让那些不变量悄悄失效。

- 捏合限速取 `max(MIN_PINCH_INTERVAL_MS, 缩放后的切档时长)`；慢档 256 ms 已高过原来的
  220 ms，不跟着抬就等于「限速比动画还短」。
- 「关」是 0 ms：调用方走「直接落位」的分支（网格不启动过渡、大图不铺淡出快照、适应窗口
  直接设变换），而不是启动一个一步也走不了的动画。

### 4. 影片网站只收「前缀 + 番号」拼得出来的站点

预设是 Jable.tv 与 MissAV，另加「自定义…」。**JavDB 不能当预设**：它的影片页按内部 id 或
搜索参数走，`javdb.com/v/ipx-660` 是死链；它是抓取源，不是番号页。前缀的校验与读配置共用
`normalize_movie_site`，尾斜杠不在校验里去掉（拼地址时 `jav.movie_url` 会去），于是配置文件
仍原样读回用户写的那一行。

### 5. 外观走 `QStyleHints.setColorScheme`

「跟随系统 / 浅色 / 深色」交给 Qt 6.8+ 的 `setColorScheme`，换完之后由现有的 `ThemeWatcher`
收 `colorSchemeChanged` 再下发一轮调色板。**不在切换处手动 `apply_theme`**：信号发出那一刻
调色板还是半路状态。

### 6. 缓存上限当场生效

`Library.set_cache_limit` 同时改配置与 `ThumbnailCache.max_bytes`，并**立刻**按新上限淘汰
一次。等下一次写入才生效的话，用户会以为设置没生效；调小上限时也该马上腾出空间。

## 后果

- 菜单多了第四个顶层入口；`test_state_sync` 的映射清单与 `test_host_contract` 的宿主表面各
  多一条（`_sync_settings`、`SettingsFlowMixin`）。
- `SessionState` 多一个 `preferences` 字段。它是**追加**，不升 `SESSION_VERSION`：老文件没有
  这一项时读成默认值，写出去的仍是同一版。
- 新增 `ui/motion.py`（browser 与 viewer 共用，因此按 ADR 0060 留在顶层）。
- 数据安全边界没变：设置只写 `state.json` 与库的 `config.toml`，**用户的照片一个字节都不碰**；
  「打开日志文件夹」只交给系统 `open`，不读不写。
- 启动时是否打开上次的库成了开关；关掉之后落在欢迎页，那份最近打开名单照常可用。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 做成一个 ⌘, 设置窗口 | 眼下的项都是离散档位，一个菜单就够；等项多到需要分组说明再搬进窗口 |
| 动画速度放进库的 `config.toml` | 换个库动画速度就变，这不是关于那个库的偏好 |
| 影片网站预设里放 JavDB | 它按内部 id 或搜索参数走，前缀拼不出有效地址 |
| 「关」用 0 ms 的动画跑一遍 | 过渡与淡出在 0 ms 下的帧序不可靠，不如显式走落位分支 |
| 缓存上限只改配置、等下次写入再生效 | 用户会以为没生效；调小时也应马上淘汰 |
