# ADR 0023：五张右键菜单共用同四个组

- 状态：已接受
- 日期：2026-10-14
- 相关代码：`src/gallery/ui/window/menus.py`
- 相关：[ADR 0014](0014-context-menu.md)（四种落点各拼各的菜单）、[ADR 0021](0021-viewer-context-menu.md)（大图页菜单）、[ADR 0020](0020-group-card-operations.md)（分组卡片的命令）、[ADR 0022](0022-new-album.md)（空白处菜单）、[ADR 0016](0016-menu-stylesheet.md)（分隔线的外观）、[ADR 0028](0028-album-cover.md)（第一组后来多的两行）、[ADR 0044](0044-duplicate-in-place.md)（第二组后来多的「复制」）

## 背景

五张右键菜单是分几次、为不同落点长出来的：网格的四种（ADR 0014）、大图页那张（ADR 0021）、
分组卡片那几条后来才补上（ADR 0020）。每张都在「该怎么排」上做了决定，于是**彼此对不齐**：照片菜单里
「在访达中显示」紧挨着「拷贝」，分组菜单里却隔了一道。用户记住的却是「看一眼在上、动手在下」，切换
菜单时找不到同一条线 —— 菜单栏里那一份 `QAction` 是共用的（ADR 0014 决策 1），偏偏**排列**不共用。

## 决策

### 1. 按「这道命令到底动什么」分四组，五张菜单共用

```
看一眼     打开 · 在默认应用中打开 · 在访达中显示 · 设为相册封面 / 取消相册封面
拿进拿出   拷贝 · 拷贝路径 · 复制 · 复制到相册 · 移动到相册 · 粘贴
会动文件   重命名… · 移到废纸篓
它是什么   显示元数据信息 · 复制元数据（分组卡片上：复制分组条件）
```

组与组之间一道分隔线，组内不隔。**分组的判据是动作的性质，不是落点** —— 用户在照片上、在相册上、
在分组卡片上、在大图上看到的必须是同一组块，缺的只是那几条本来就不给这个落点的。

「会动文件」单独成组，是唯一带风险的取舍：那两条改的是**既有的那一份**（改名字、移走），其余按错了
原件还在原地。让「重命名」紧挨着「拷贝」省一道线，换来的是「要动手的那几条」混在只读命令里。

> **后续（ADR 0044）**：第二组多了「复制」⌘D。它会写磁盘，却**刻意不进**第三组 —— 判据不是「动不动
> 文件」，而是「动的是哪一份」：它是**多一份出来**，与「拷贝」「复制到相册」同一族。分组卡片那一份也
> 有这一行，于是第三组的准确说法是「**动既有的那一份**，且按错了要靠 ⌘Z 找回来」，入口仍是仅有的两条。

> **后续（ADR 0028）**：第一组多了「设为相册封面 / 取消相册封面」两行，**四段本身没变**。它们改的是
> 「这个相册在网格上长什么样」，用户的照片一个字节都没动，与「打开」「在访达中显示」同族；放进
> 「会动文件」那一段，恰好会稀释那两条真正会改用户文件的入口 —— 那道分隔线存在的意义就在这里。

### 2. **组内少几行时分隔线照旧；整组不出现时那一道也不要**

多选照片时第一组只剩「在访达中显示」、第三组只剩「移到废纸篓」，分隔线**都留着**：用户在单选与多选
之间来回切换时，组块的位置不跳，「上面那一段是打开」这个印象不随选区变化。分组卡片与相册没有第四组
（面板讲的是**一张**照片），那一组连同它前后该有的分隔线一起不出现 —— 菜单末尾挂一道谁也看不懂的
空档比少一段更糟。**多选照片时第四组也整组不出现**：那一组讲的都是**这一张**照片 —— 面板显示的是
光标那一格，两条命令的取行也都走 `_focus_row()`，选区里另外那十几张并没有理由被指定。早先只藏
「复制元数据」而把「显示元数据信息」留着，那是把**整段**的判据写成了其中一行的。

实现上因此只有四个出口：`_add_look_group` / `_add_copy_group` / `_add_write_group` /
`_add_metadata_group`，每张菜单按「第几组 + 这张缺哪几条」调用。**第四个出口自带它前面那道分隔线**
—— 它是唯一会整个消失的一段，那道线必须与它同生共死；前三组「少几行但段还在」，位置恒定。

### 3. 只有空白处那张不走这四组

**分组卡片的「复制分组条件」就是第四组。** 它同样是一句只读问答，说的正是**这张卡片是什么**（按哪个
字段分的、组叫什么、几张），与「复制元数据」同族 —— 早先判它「不属于四组中的任何一组」站不住：「复制
元数据」也不是「看一眼」，它就在「它是什么」里。改动前后**渲染完全一致**（分组卡片本来就没有那两条，
第四段的位子是空的），变的是概念，不是菜单 —— 从此**五张菜单里没有第五块**。**空白处那张整套不走
这四组**：它的命令全是视图级的（全选、分组、排序、缩略图大小、回到上一层），而最上面另起一块放
「新建相册」与「粘贴」—— 那两条同属「只增不改、绝不覆盖」这一类（ADR 0022 决策 1、
[ADR 0018](0018-paste-into-current-folder.md) 决策 7），与四组都不是一族；**两道都不出现时那一块连同
分隔线一起没有**。相册菜单里「移动到相册」正下方那一行由「粘贴」占着（摆不摆由 ADR 0018 决策 7 定）。

## 后果

- 五张菜单的排列只有一份真相：改一条命令的位置不必记得改五个地方。
- 空白处的菜单结构未变（它本来就不属于这四组）；ADR 0022 的「新建相册」仍在最上面单独一块。
- `menus.py` 的模块文档里写了这张表 —— 拼菜单的人第一眼就该看见分组原则，而不是读五个 `build_*_menu` 拼出结论。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 按落点各排各的（维持现状） | 用户记住的是动作的性质，不是落点；对不齐的排列等于要记五套 |
| 「会动文件」不单独成组，省一道分隔线 | 那两条改的是**既有的那一份**，混在一堆只读命令中间最容易被顺手点到（判据见决策 1 的 ADR 0044 那段：「动哪一份」，不是「动不动文件」） |
| 组内也按子族加细分隔线（访达那样） | 一张十行上下的菜单里塞三四道线，行序要读着「线在哪儿」才看得出来 |
| 空白处那张也套这四组 | 它一条会动文件的都没有，套上去等于凭空多出三道空档 |
| 「复制分组条件」单列第五块（原写法） | 渲染上与放进第四组一模一样，却让「五张菜单共用四个组」凭空多一个例外；它与「复制元数据」是同一种只读问答，没有理由分开 |
