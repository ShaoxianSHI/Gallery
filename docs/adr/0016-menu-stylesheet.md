# ADR 0016：弹出菜单改用样式表，放大圆角与行距

- 状态：已接受
- 日期：2026-10-05
- 相关代码：`src/gallery/ui/menus.py`、`src/gallery/ui/main_window.py`

## 背景

macOS 样式（`QMacStyle`）给弹出菜单画的那圈圆角实测约 **5 像素**、每一行只有 **18 像素**
高。行距明显比访达紧，菜单看起来更像一个通用的下拉列表，而不是 mac 上的菜单。

Qt 没有「菜单圆角」「菜单行高」这样的度量可以改：能改的只有两条路 —— 给控件挂样式表，
或者用 `QProxyStyle` 重画。这条记录说的是选了前者，以及为此放弃了什么。

## 决策

1. **给弹出菜单挂一份样式表**，只写两件事：圆角（`MENU_CORNER_RADIUS = 8`）与菜单项内边距
   （`MENU_ITEM_PADDING`，行高由此从 18 变成 26）。别的什么都不写。
2. **底色必须显式写进样式表**。实测：只要 `QMenu` 上有了样式表，面板就不再由
   `QMacStyle` 画，底色会掉回系统菜单色（浅色 `#ececec`）—— 上一条 ADR 刚统一的
   「菜单与窗口同一块底色」会当场作废。写 `palette(window)` 也不行：它取的是**应用**
   调色板，不是我们逐控件下发的那份，浅色下两者差一档。
3. **子菜单要显式发到**。实测子菜单既不继承父菜单的样式表，也不是它的子控件
   （`QMenu.addMenu(另一个 QMenu)` 不给后者设父对象，`findChildren` 找不到它）。
4. **菜单栏那边不动**。`QAction` 是全局复用的，`some_action.menu()` 可能指向菜单栏里的
   子菜单；递归时必须以「该子菜单的 `menuAction()` 是不是当前这条 action」判所有权，
   否则「视图 → 排序 / 分组 / 缩略图大小」会被右键菜单顺带改掉。

## 后果

- 弹出菜单的**投影与分隔线细节不再由系统画**（圆角是样式表画的）。抓图能验到圆角，
  投影由 cocoa 窗口层给、抓不到，**未查证**。
- 菜单右边的快捷键列要自己留位置：样式表的 padding 是**替换**样式自己的边距而不是叠加，
  给窄了 `⌘R` / `⌘⌫` 会被挤出菜单（现留 25 像素余量）。
- 两个数字都是模块级常量，想换观感改一行即可，不必回到 `QProxyStyle` 那条路。
- 深色模式下底色取的是同一份「窗口底色」角色，因此自动跟随。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| `QProxyStyle` 改 `sizeFromContents` | 只改得动行高，圆角没有对应度量，仍要自己重画 `PE_PanelMenu` —— 等于整块面板自绘，代价比收益大 |
| 全局 `setStyle("Fusion")` 后统一画 | 丢掉全部 mac 观感（`macos` 才是平台样式的 key） |
| 把样式表挂到 `QApplication` | 会波及每一处控件，包括本来画得对的菜单；且与 `setPalette` 的老坑纠缠 |
| 只改行高、不动圆角 | 行距是更刺眼的那一半（18 像素确实挤），两者一起改才看得出是同一件事 |
| 改用 `palette(window)` 写底色 | 实测取到的是应用调色板的 `#ececec`，与窗口那块差一档 |
