# ADR 0032：拍摄时间可写回 —— 时间的本质是时钟读数，不是测量结果

- 状态：已接受
- 日期：2026-11-15
- 相关 ADR：0030（只改位置）、0031（位置的双向编辑）、0023（菜单分组）
- 相关代码：`src/gallery/core/metadata/capture_time.py`、
  `src/gallery/core/metadata/metadata_edit.py`、`src/gallery/core/metadata/writeback.py`、
  `src/gallery/ui/panels/metadata_edit.py`

## 背景

ADR 0030 定了「只改位置」这条规矩，判据是**「这条值是设备的事实记录，还是人的标注」**，
并把「让用户编辑任意元数据（相机、拍摄时间、曝光……）」明确列进了被否决的替代方案：
「那是改写拍摄证据」。

这条判据对**相机、镜头、光圈 / 快门 / ISO / 焦距**是成立的，但把它一并套在**拍摄时间**
上，混淆了两件性质完全不同的事：

- 相机型号、光圈值、焦距是**测量结果**：机身测出来的客观量，替用户改它等于伪造证据；
- 拍摄时间是**机内时钟的一次读数**：它对不对，取决于用户有没有把相机的时区设对、有没有
  换过电池、GPS 有没有对过时 —— 换句话说，它**本来就需要人来校准**。

于是真实世界里有一整类照片，时间是**确定错了**的，而用户手上没有任何工具能改：

- 相机带着一块没电的电池出去，回来时钟归零，全天的照片都成了 1970 年。
- 在日本旅行忘了把时区从 UTC 调成 +09:00，回来每张照片都差九小时；
- 胶卷按张数推断、扫描件导入后补时间、显影老照片只剩年份；
- 某个导出工具把没读出时间的照片一律写成「导出当天」。

这四类里的任何一张，用户在 Gallery 里只能看着一个错的时间 —— 排序错、分组错，还**不能改**。

## 决策

### 1. 拍摄时间可写回，判据从「是不是测量结果」改成「是不是需要人校准的读数」

ADR 0030 的判据本身不推翻，它的**适用范围**被收窄了：它继续挡着相机、镜头、曝光三件套、
像素与色彩空间，挡住它们的理由一个字不改（改那些确实是伪造证据）。这一条把**拍摄时间**
从「事实记录」那一侧挪到了「需要人校准」那一侧。

可写的字段新增两个，**都在 EXIF 的 ExifIFD 里**：

| 标签 | 含义 |
|---|---|
| `EXIF:DateTimeOriginal` | 拍摄时刻的**墙上时间**（钟面时间，`2024:05:16 20:52:02`） |
| `EXIF:OffsetTimeOriginal` | 那个钟面时间属于哪个时区（`+08:00`，**空表示照片不记时区**） |

### 2. 时区偏移单独一栏，可编辑；留空就是不写

EXIF 的 `DateTimeOriginal` **不带时区** —— 它记的是按下快门那一刻相机所在地的钟点，
既不是 UTC 也不是任何换算后的值。时区在**单独的可选字段** `OffsetTimeOriginal` 里
（EXIF 2.31 才有），而相机十有八九不写它。

于是编辑器把两者分成两栏：

| 用户填的 | 写下去的结果 |
|---|---|
| 时间 + 偏移 | 两个字段都写，面板上从此能显示 `+08:00` |
| 时间，留空偏移 | 只写 `DateTimeOriginal`；`OffsetTimeOriginal` **被删掉** |
| 两个都留空 | 两个字段都删掉 |
| 时间不动，只改偏移 | 只写偏移 —— 「相机时区设错了」正是这一栏 |

**留空 = 照片里不记这一项**，而不是「保持原样」。这与位置那一侧的既有语义一致（空框表示
「清掉那一层」，见 ADR 0031），也让编辑器始终是「访达的显示简介」那一种：**打开时看到的
就是最终状态**，不需要另设「改了这一项」的勾。

**绝不替用户猜时区**：照片没写偏移时，那一栏就是空的。凭空填一个 `+08:00` 等于替用户
对时区的猜测做背书，而时区猜错的后果（排序整体偏九小时）比空着严重得多。

### 3. 只写 `DateTimeOriginal`，不碰 `CreateDate` / `DateTimeDigitized` / `ModifyDate`

后三个记的是**文件处理过程**（「什么时候被创建的」「什么时候被扫描仪数字化的」「什么时候被
改写过的」），与「这张照片什么时候拍的」不是一回事。用户改拍摄时间时不动它们 ——
否则一条「2003 年的胶卷扫描件」会被顺手改成「昨天创建」，而那件事根本没发生过。

（用户当场确认过这个取舍：曾考虑连 `CreateDate` 一起写，理由是有些软件只读它。否决 ——
一致性不值得用一个假的时间戳换。）

### 4. 写盘、校验、回滚、撤销、索引作废：全部沿用 ADR 0030，一行机制都没有新写

`writeback.WRITABLE_TAGS` 加两行，回归测试随之加两行。写回仍然：

- 走 exiftool 子进程，`-overwrite_original`（约束 6）；
- **写完回读校验**，对不上就按原值写回去并如实报错（约束 3）；
- 逐字段记 journal，可 ⌘Z 撤销，别人改过的字段不覆盖（约束 4）。

**时间与位置在同一次写回里**（一个 `write_metadata` 调用、一条 journal 记录、一次 ⌘Z），
不是两次。用户在一个对话框里按下保存，得到的是「一次操作」，撤销也只该是一下。

### 5. 「编辑位置」改叫「编辑元数据」

编辑器不再只管位置，命令、菜单项、面板按钮、横幅、⌘Z 的文案一律跟着改。快捷键 ⇧⌘I 不变
（访达的照片「简介」也是 ⌘I）。

「清空」按钮改成**「清空位置」**并只清位置那五栏 —— 拍摄时间不该被一个叫「清空」的按钮
顺手删掉。清掉拍摄时间的方式是把那两个框清空（与位置同一套语义）。

## 后果

- **文件名可能与拍摄时间对不上**：时间栏改了之后，`IMG_20240705_143022.jpg` 这类**文件名
  里编码的时间不会跟着改** —— 改文件名是 ADR 0004 那条独立的、必须用户亲手触发的路，
  约束 1 不许在这里搭便车。
  曾经在这两栏下面放过一行小字专门说这件事，**后来撤掉了**：对话框本来就是访达「显示简介」
  那一类用法，框上写着「拍摄时间」「时区」，用户改自己的照片不需要先被教育一遍。
- **改时间会重排也会重分组**：``captured_at`` 正是分组与排序的键（`facets.extract`），所以
  ADR 0030 那五件界面联动在这里一件都不能少 —— 好在它们与「改位置」走的是同一条
  `_after_metadata_write`。
- `core/metadata/place_edit.py` **原样保留**（它仍然是位置那一侧的翻译层，ADR 0031 不动），
  新增 `core/metadata/metadata_edit.py` 把两个方向合成一次写回。
- 界面层从 `ui/panels/place_edit.py` 改名 `ui/panels/metadata_edit.py`，对话框从
  `PlaceEditDialog` 改名 `MetadataEditDialog` —— 名字不改的话，「place」会变成一个
  与它实际职责不符的说法。
- **约束 1 的回归测试要跟着改**：`WRITE_METHODS_ON_LIBRARY` 里的 `write_place` 换成
  `write_metadata_edit`。换了名字而没改回归测试，那条「界面上改用户文件的地方只有一处」就漏了。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 继续只改位置 | 相机时区设错、时钟归零、扫描件没时间的照片，用户手上没有任何工具能修 —— 这是最常见的一类坏数据 |
| 连相机 / 镜头 / 曝光一起开放 | 那才是伪造证据。这条线由 ADR 0030 的判据挡着，本 ADR 只把**时间**挪到另一侧 |
| 时间统一换算成 UTC 再写 | EXIF 的 `DateTimeOriginal` 存的**就是墙上时间**，写 UTC 会让所有照片在别的软件里显示成凌晨；同时破坏与相机原始语义的一致性 |
| 没写偏移时按本机时区补一个 | 凭空替用户猜时区，猜错的后果（整体偏几小时）比空着严重得多 |
| 连 `CreateDate` / `DateTimeDigitized` 一起写 | 那几个记的是文件处理过程，不是拍摄事实。改它们等于制造一条没发生过的记录 |
| 改完时间顺手改文件名 | 约束 1：改名只能是用户亲手触发的那一次独立操作，不许搭元数据编辑的便车 |
| 时间与位置分两次写回 | 一个对话框里按一次保存却要撤两下、横幅也要说两遍 —— 那不是一次操作 |
