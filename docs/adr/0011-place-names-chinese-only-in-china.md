# ADR 0011：地点一律用当地语言，只把国内（含港澳台）译成中文

- 状态：已接受
- 日期：2026-10-02
- 相关 ADR：0003（离线反查）、0010（打开时解析入库）
- 相关代码：`src/gallery/core/places/countries.py`、`src/gallery/core/places/dataset.py`、
  `src/gallery/core/library/index.py`

## 背景

地点此前是**到处翻译**的，而且翻译得并不到位：

| 层 | 旧行为 | 例子 |
|---|---|---|
| 国家 | 内置一张 190 国的中文表，命中就替换 | `France` → 法国 |
| 省州 | 只有中国有静态表，其余保留原名 | `New Aquitaine`（原样） |
| 城市 | alternate names 里有汉字就用，不管哪个国家 | `Bordeaux` → 波尔多、`New York City` → 纽约 |

拼出来是「法国 · New Aquitaine · 波尔多」：国家被翻成中文、省州没翻、城市又是中文，
**一层一个语种**。更麻烦的是同一条链路上两种写法都在混用：GeoNames 存的国名是
`China`，代码翻成 `中国`；面板若恰好显示的是文件里自带的地点（Lightroom 导出的
`Country-PrimaryLocationName` 写什么就是什么，通常是 `France`），于是同一张照片
在分组里叫「法国」、在面板里叫「France」，差别还来自照片本身有没有写地点。

问题不在于「中文界面就该显示中文」，而在于**翻译是半截的**：`波尔多` 是我们自己挑的
汉字，`New Aquitaine` 却是法文，两者挨在一起谁也不像谁。而且这些译名是**我们自己
造的**，用户在自己的照片上认不出自己拍过的地方。

## 决策

### 1. 规则收敛成一条：国内用中文，其余一律用 GeoNames 原名

判断只看国家代码在不在 `COUNTRY_NAMES_ZH` 里（`core.places.countries.uses_chinese_names`）：

- 境内：`中国 · 浙江省 · 杭州`（省、市的中文名继续由静态表与 alternate names 提供）；
- 境外：`France · New Aquitaine · Bordeaux`、`United States · New York · New York City`。

中文城市名只在解析境内城市时挑选 —— `alternate names` 里当然到处是汉字
（`纽约`、`东京`、`巴黎`），但那些是**当地人写的**名字之外的东西，
用上去等于替用户把他的相册翻译成另一个语种。

### 2. 港澳台也用中文，但层级各按自己的样子

港澳台在 GeoNames 里是三个**独立的国家代码**，大陆的用户却在这三个地方拍过照，
所以它们与大陆一起进中文表。国名统一写作「中国」，差别全在下面两层：

| | 国名 | 省级 | 城市 |
|---|---|---|---|
| 中国大陆 | 中国 | 浙江省 | 杭州 |
| 香港 | 中国 | **无此层** | 香港、沙田、屯門 |
| 澳门 | 中国 | **无此层** | 澳門 |
| 台湾 | 中国 | 台湾 | 台北、高雄 |

两处特殊处理都是**照着 GeoNames 的真实数据定的**，不是想当然：

- **港澳没有省级这一层**。GeoNames 在这两地给的是**区级**名字
  （香港 17 区、澳门 7 堂区），挂上去就是「中国 · 沙田区 · 沙田」——
  在国名与城市之间凭空插一个「省」。于是这一层直接省掉。
- **台湾的省级一律显示「台湾」**。GeoNames 那几个是**历史旧名**
  （`Takao` 是高雄旧称、`Fukien` 是福建旧称），照搬出来是「中国 · Takao · 高雄」。

**不区分简繁**：港澳台在 GeoNames 里的汉字名多为繁体（`荃灣`、`屯門`、`澳門`）。
简繁转换要引入对照表（opencc 之类），不值得为一个显示细节加一条依赖 ——
繁体在简体中文读者那里一样认得出。

### 3. 国家名不再维护整张翻译表

`COUNTRY_NAMES_ZH` 从 190 国缩到 4 项（CN / HK / MO / TW）。这不是为了少写 186 行：
那张表里「刚果（金）」这类译名我们没有权威依据，改一次就得查一次，
而绝大多数条目从来没人用过。**没有权威译名就不硬翻** —— 与省州层早就遵守的规矩一致，
现在只是让国家层也守同一条。

### 4. 旧索引里的旧译名要作废

地点名存在 `.gallery/index.db` 里，`place_ok` 记着「这张已经查过了」。
不处理的话，升级后的用户会看到**新老混排**：新扫的照片是 `Bordeaux`，
上次扫的还是 `波尔多`，且永远不会再变。

因此 `core.library.index.SCHEMA_VERSION` 3 → 4，旧表整表重建
（缓存不值得迁移，见 ADR 0010）。港澳台加进来时补到 5。
代价是一次全量重读，与 0009→0010 那次一样。

### 5. 文件里写的地点仍然原样显示

这一层一个字都不改：`City` / `Country` 是照片自带的内容，我们照抄。
Gallery 从不翻译用户文件里的字段，也不回写（约束 2、3）。所以本 ADR 只管
**我们反查出来的**结论 —— 那才是我们自己造的文字。

## 后果

- 界面上会看到「France · New Aquitaine · Bordeaux」这样的整串外文。
  这正是要的：**用户认得出自己拍过的地方**，而不是认出一份自己没写过的清单。
- 与相机 / Lightroom 写进文件的地点更容易对上号了：两者现在都用同一种语言
  （都在法国就都叫 `Bordeaux`），面板与分组之间也不会再一个中文一个法文。
- **按国家分组时，大陆、香港、澳门、台湾落进同一组「中国」**。它们在 GeoNames 里
  是四个国家代码，在本软件里只算一个国家 —— 想分开只能按省州或城市分。
- 老库第一次打开会重建索引、后台全量重读一次（与 ADR 0010 的那次一样）。
- `COUNTRY_NAMES_ZH` 以后要扩回多国的话，改的是 `uses_chinese_names` 那一条判断，
  但先问一句有没有权威译名来源。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 全部保持英文 / 法文 / 德文原名，包括国内 | 用户看自己的照片，最该看到的是「杭州」而不是 `Hangzhou` |
| 每层各译各的：国家中文、省州原样、城市中文 | 就是旧行为。三层三种语种拼在一起，哪一层都不统一 |
| 港澳台保持外文（`Hong Kong` / `Taiwan`） | 用户确实在这三个地方拍过照，让它们显示成中文是本来就该有的 |
| 港澳台按 GeoNames 逐层照搬：国名中国、保留「沙田区」、保留「Takao」 | 「中国 · 沙田区 · 沙田」凭空多一个省；「中国 · Takao · 高雄」是历史旧名 |
| 港澳台的城市名做简繁转换（引入 opencc） | 为一个显示细节加一条依赖；繁体在简体中文读者那里一样认得出 |
| 保留 190 国译名表，但只在本界面语言为中文时启用 | 界面语言恒为中文，这个开关没有第二个取值，等于没写 |
| 按用户的 Locale 决定（中文界面就全译中文） | 同上，而且这会让地点名随界面语言变化，同一个库两次打开说法不同 |
| 反查结果与索引里不区分语言，读的时候再按界面语言翻译 | 把语言问题塞进每一处消费者；分组、面板、索引三处各写一遍，早晚漂 |
