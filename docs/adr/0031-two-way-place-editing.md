# ADR 0031：位置的双向编辑 —— 坐标推地点，地点推坐标

- 状态：已接受
- 日期：2026-10-06
- 相关 ADR：0003（离线反查）、0010（打开时解析入库）、0011（地点语言规则）、
  0012（自带城市库）、0030（写回原文件）
- 相关代码：`src/gallery/core/places/dataset.py`、`src/gallery/core/places/resolver.py`、
  `src/gallery/core/metadata/place_edit.py`、`src/gallery/ui/panels/metadata_edit.py`
  （原名 `place_edit.py` / `PlaceEditDialog`，ADR 0032 随「编辑元数据」一起改名）

## 背景

Gallery 一直只有「坐标 → 地点」这一路（ADR 0003）：相机原图几乎不写地点，Gallery 按 GPS
离线反查一次，把国家 / 省州 / 城市补齐存进索引（ADR 0010）。

但一旦允许编辑位置（ADR 0030），用户会遇到一个界面上无处可查的缺口：

- 他把坐标改到了别处，照片里的地点名还写着旧的城市，于是**坐标与地名互相矛盾**；
- 他改对了城市名，照片里的 GPS 还固定在别的城市，于是**地图把他带到错的地方**。

两个方向都得补。而「地点 → 坐标」这一路，城市库原本**没有** —— `PlaceIndex` 只有
`nearest()`（坐标 → 最近的城市）。

## 决策

### 1. 两条方向在同一个对话框里合流

`PlaceEdit` 收到的是「用户填完的**那一份**」，不是「改了哪些」。三个输入框加一对坐标框，
**打开时就把照片此刻的值全填上**（访达「简介」的用法）。

| 用户动的地方 | 顺带发生什么 |
|---|---|
| 坐标 | 按新坐标反查地点（`place_for`），查到了就一并写进去 |
| 地名 | 按新名字正查坐标（`place_named`），查到了就一并写进去 |
| 两个都动 | **用户填的说了算**，不去反查覆盖他 |
| 只清空坐标框 | 删坐标、留地名（定位漂了而地名没错） |
| 三层地名与两个坐标框**全清空** | 坐标与三层地名一起删 —— 不需要单独的勾选框 |

### 2. 「地点 → 坐标」用城市库自己的名字，正查就够

`PlaceIndex.by_name(name, region=, country=)`：精确名 → 「市 + 省」→ 「市 + 国家」→ 只看市名；
多候选**按人口降序**返回，让用户在补全里挑一个（与 `nearest` 的消歧同一个理由）。

匹配从最具体到最宽，因为同名的城市在世界上成百上千。三张名字索引（只按市名、市+省、
市+国家）在加载时一次建好，查询是查表而不是遍历两万条 —— 那一路是用户**边打字边问**的。

**不联网、不改数据、不引入新依赖**：名字按 ADR 0011 在生成期就定好了（境内中文、境外当地
写法），运行时只多了一次查表。

### 3. 查不到就是查不到，绝不编一个坐标

库里没有的名字（用户自己写的门牌、景区、小店）**只写地名、坐标原样不动**，并在对话框里
说清「城市库里没有这个名字，坐标保持原样」。

这句话后面还跟了半句：**境外地点按当地写法收录（京都写作 `Kyoto`）**。不说它，用户输「京都」
查不到只会以为这个功能坏了 —— 而整个 Gallery 显示境外地名用的就是当地写法（ADR 0011），
他在这个软件里看到的也一直是 `Kyoto`。

### 4. 坐标 → 地点查不到时，**保留**原来的地名

坐标挪到了海上、附近 300 公里没有城市（ADR 0012 的硬上限），这时照片里原来写着「南京」。

**不清空**：那张照片本来就是「南京」，用户只是把坐标挪到了别处 —— 是地名错了还是坐标错了，
该由用户判断。替他删掉一个字段只会让事情更难查 —— 对话框里那行小字说的是「坐标已按新坐标
更新」还是「附近没有城市记录，原来的地名没有改动」。

### 5. 由地名反推出来的坐标是**市级精度**（这一条现在是**只做不说**）

城市库里那一条坐标是这座城市的位置（多数是市质心或辖区代表点），不是这张照片的拍摄点。
把几十米的精度换成几公里，是一个**看起来精确、实际很粗**的值。

原本这里还有一行随改动实时变的说明（改地名就写「坐标会按这座城市的位置写入 —— 那是市级
精度」）。**那行说明后来被使用者删掉了**：对话框里不要任何预告，横幅也不要，于是「先说
再写」这一半不再成立 —— 风险由下面两处兜着：**坐标系整体只有 13 个标签可写**（改不了别的），
以及**每一次写入都能 `⌘Z` 逐字段撤销**。这是一次「知道后果不如能改回来」的取舍，记在这里
以免日后有人把它当成疏忽又加回来。
**对话框里一个勾都没有**：这个联动本来就是「编辑位置」存在的意义，为它留一个勾等于让
用户每次都要决定一遍「我要不要它联动」。「清除位置」同样不需要 —— 三层地名与两个坐标框
全清空就是那个意思，而勾选框只会多出一种要记的用法。

### 6. 编辑坐标时顺手清掉海拔与定位时间

那两条记的是**另一个位置**上的测量值：坐标在杭州、海拔是珠峰的，一条 GPS 记录内部就自相
矛盾了。清掉比留着好 —— 它随坐标编辑一起发生，同样能被 `⌘Z` 撤销。

### 7. 编辑器里两个方向都是**实时**的

三个地名框按**国家 → 省 / 州 → 城市**由大到小排，而真正用来查的是**城市**（它在库里是唯一
索引，省与国家只是收窄同名城市的条件）。因此：

- **只敲城市就行**：城市一敲定，上面两栏自动补上。查不到时**只按名字再查一遍** ——
  用户换城市时，上面那两栏还留着**上一座城市的**省与国家，按那个过期范围查当然查不到；
- **少于两个字不查、也不给候选**：自带的城市库里有一个真叫「苏」的条目（安徽某个被折叠
  进市里的区）。用户敲下第一个字就恰好命中它的话，屏幕上会立刻跳出「中国 · 安徽省」
  和一串坐标 —— 那是数据里的碎片，不是用户要填的地方；
- **敲地点 → 坐标框立刻更新**；**敲坐标 → 地名框立刻更新**；
- **程序自己填进去的框不再触发下一次回填**（一个 `_programmatic` 标志挡住），
  否则「地名 → 坐标 → 地名」会自己打起来；
- 查不到就**一个字都不填**，说明那一行如实说「城市库里没有这个名字，坐标保持原样」；
- 说明那一行**按「用户刚才动的是哪一侧」说话**：自动回填把两侧都改了，于是「哪一侧变了」
  这句话不再有用，而「我敲了苏州」与「我把坐标挪到波尔多」接下来发生的事完全不同；
- 取消「同时按这个地点更新经纬度」时，刚才自动填进去的坐标**还原成照片原本的** ——
  框里显示的必须是真正会被写下去的那一份。

### 8. 面板上三层地名写成一行

文件里写了地点之后，面板的「位置」组**一行**说清：`中国 · 浙江省 · 杭州`。分三行摆着
（地点 / 省州 / 国家）看着像三件无关的事，而它们说的是同一个地方 —— 与推断出来的地点
同一个说法（「地点（推断）」也是一行）。子地点是另一个字段，仍单列。

顺带修掉一个既有问题：**exiftool 的 `-G` 按一级族回填键**，13.x 给的是 `XMP:City` 而
不是 `XMP-photoshop:City`。只认全名的话，Lightroom 那种只写 XMP 不写 IPTC 的照片，
「地点」永远是空的 —— 面板、分组与索引三处都改成两种族名都认。

### 9. ⌘W 关它，窗口不能拖大拖小

⌘W 挂在对话框自己身上（`StandardKey.Close`）：不挂这一条的话，⌘W 会一路走到主窗口 ——
在一个模态框里按 ⌘W 结果整个窗口没了，那绝不是按键的人想做的事。
窗口尺寸由 `QLayout.SetFixedSize` 锁定，说明与错误各留固定的两行高度，
免得文案在两句之间换来换去时对话框跟着长高再缩回来。

### 10. 横幅只有一句，不重复对话框

保存之后横幅上**只有**「已更新「一张.jpg」的位置。⌘Z 可以撤销。」。

横幅原本还会把「接下来会发生什么」讲一遍（「地名与坐标都是你填的，它们之间的对应关系
Gallery 没有替你调整」），那也是重复：重复的那一遍还是在动作**之后**才到 —— 那时候它
已经不能改变任何决定了。

横幅只回答两件事：**成了吗**、**能不能撤**。后者不是重复：它不是「发生了什么」，而是
「你刚才按 ⌘Z 会发生什么」；撤销时的「只撤了一部分」同理 —— 那是结果，不是解释。

因此 ``PlacePlan`` 上不再带任何「要说的话」：这一层只负责**哪些字段会被改**，
一句话都不生成。

### 11. 冲突由用户填的解决

坐标与地名都被改过时，不去反查、也不警告「它们不一致」。这不是一个错误，是一种合法的
用法（用户知道自己在做什么，例如给一张扫描件补一个大概的位置）。

### 12. 按钮：复制 / 粘贴 / 清空一行，取消 / 保存一行

第一行三个键**占满整行**（各占三分之一），第二行「取消 / 保存」**分别与粘贴、清空对齐** ——
同一套列网格，于是宽度与位置都是布局算出来的，不是两排手工对齐的推算。

「清空」按钮取代了那个被删掉的「清除位置」勾选框：勾选框得先去勾一下才生效，放在五个按钮里
反而更像一个动作；而「全清空」本来就是编辑器里唯一表达得出「全删」的形状。它**只清框**，
仍然要按保存才写盘。

**对话框里不再有任何预告行**（「保存后，XXX」）：使用者要的是把值抄进框里的过程本身，
一句话的预告在旁边反倒像在多问一次。

### 13. 入口摆在页脚，不摆在「位置」那一组里

入口原本是「位置」那一组标题右边的按钮，而**没有位置的照片压根不会渲染出那一组** ——
用户想给一张没位置的照片补一个位置时，界面上什么入口都没有，恰恰是最需要的时候没有。

于是它挪到页脚，与「复制全部」「显示全部字段」一行，**三个组件平分整行**（两个按钮
``Expanding``，那个勾选框按自己的宽度）。不能用时（没装 exiftool）**置灰**并把理由放进
悬浮提示，而「位置」那一组仍然把那句话写出来 —— 看得见，不必去猜（ADR 0014 决策 4）。

## 后果

- 城市库多占一点内存：两张名字索引约两万来个键，几 MB，一次建好全程复用。
- 「地点」这件事从此**只有一套算法**：反查（`nearest`）与正查（`by_name`）读的是同一份
  文件、同一份语言规则；界面上的补全、面板上的显示、分组里的城市名说的是同一种话。
- 编辑器的输入是一份**最终状态**，因此任何调用方都必须像对话框那样把三层地名与坐标都带上 ——
  少带一个就会被解释成「清空那一层」。这条写在了 `PlaceEdit` 的文档里，也有
  `test_place_edit.py` 里那个 `fill()` 帮助函数盯着。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 编辑坐标时把旧地名一并清空 | 那是替用户决定「哪个错了」；保留并说明更诚实 |
| 地名查不到时也配一个坐标 | 库里没有的东西不该由我们编；一个错得离谱的坐标比没有坐标更坏 |
| 地名查不到就干脆不让保存 | 用户完全可以只改文字描述；那是他要的事，不该被工具拦下 |
| 用在线地理编码服务做正查 | 坐标与地名一个字节都不出本机是 ADR 0003 的承诺；而且那需要联网 |
| 编地名时保留原坐标（默认） | 用户明明白白写了「苏州」，界面里那行字还指着南京 —— 两处说两套话 |
| 引入地图控件让用户点选 | 这是唯一会破坏「坐标一个字节都不出本机」的功能。真要做，宁可先做「用地图 App 打开、复制坐标回来」 |
| 编辑地点时一并改同组照片 | 一次动几百张照片的 GPS 是不可想象的操作 |
