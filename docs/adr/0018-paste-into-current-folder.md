# ADR 0018：「粘贴」⌘V 把剪贴板里的文件复制进当前这一层的目录

- 状态：已接受
- 日期：2026-10-07
- 相关代码：`src/gallery/core/metadata/paste.py`、`src/gallery/core/library/facade.py`、`src/gallery/ui/desktop.py`、`src/gallery/ui/window/menus.py`、`src/gallery/ui/main_window.py`、`src/gallery/ui/write_ops.py`
- 相关：[ADR 0013](0013-filesystem-watch.md)（新文件怎么显示）、[ADR 0017](0017-copy-file-to-clipboard.md)（⌘C 往剪贴板里放文件）、[ADR 0004](0004-rename-on-disk.md)（约束 1）

## 背景

Gallery 加了 ⌘C（ADR 0017）之后缺的就是访达那条「粘贴」：用户在别的软件里 ⌘C 了一张照片，切回
Gallery 按 ⌘V 什么也不会发生。这是本项目里**第三个会往用户目录里写东西**的操作（前两个是改名与
移到废纸篓），所以粘到哪去、同名怎么办、能不能撤销这三件事要先定下来 —— 都关系到约束 1。

## 决策

### 1. ⌘V 的目标目录一律**按磁盘上的真实位置**算

> 这一节说的是 **⌘V**。右键菜单那一侧按**落点**另有一套（决策 7），两者刻意分开。

| 当前这一层 | 粘到哪里 |
|---|---|
| 相册模式（在某个相册里） | 当前这一层的文件夹；顶层就是库根 |
| 全部照片 | 整层是平铺的，唯一说得清的目录是**库根** |
| 分组里，且**整组照片本来就在同一个相册** | 那个相册 |
| 分组里，照片散在多个相册 | **没有** —— ⌘V 置灰 |

最后一条的判据是「以实际磁盘上的位置为准」：按相机和按年份各开一张卡片，只要底下都是京都，粘
进去的就是同一个京都；而散在几个相册里的一组不对应任何一个文件夹，与其摆一条永远按不动的，不如
直接置灰（同 ADR 0014 决策 4 的取向）。**源可以来自库外**：在访达里 ⌘C 一个别的文件夹照样能粘进来
—— 剪贴板是系统级的，Gallery 没有理由只认自己库里的路径。

### 2. 已经在目标目录里的**复制一份**

同一个相册里 ⌘C 再 ⌘V **造一份副本**：`一张.jpg` → `一张的副本.jpg`。判据是**源文件的父目录**与
目标目录是不是同一个地方，并且两边都 `resolve()` 过 —— 访达的剪贴板里可能是 `/private/var/…`，界面
拿到的是 `/var/…`，不解析就比不相等。「什么都没发生」不是一种安全的回答：按了键、看见一句话，照片
却一份没多。

> 这一条由 [ADR 0044](0044-duplicate-in-place.md) 决策 3 从「原样跳过」改成复制一份：用户当时要挡的
> 是**编号**那一半（别凭空多出一堆他认不出的 `一张 2.jpg`），那一条现在由 `一张的副本.jpg` 挡住；
> 名字规则与整条实现在 ADR 0044 决策 2，一批里有一部分本来就在那儿，就**每项都造一份**。

### 3. 同名不覆盖，改名 —— 用**系统自己的**规矩

`一张.jpg` → `一张 2.jpg` → `一张 3.jpg`，文件夹同理（`京都` → `京都 2`）。这是量出来的：访达里
对同一个文件连按两次「复制项目」给出的正是这两个名字。**不选「整批停下」**（十张里九张能粘也
粘不成，是把一条能用的命令废掉），**不选「报个错让人自己改名」**（访达不会这么做）。

### 4. **不进撤销栈**，只记账

撤销一次粘贴就是删文件，而约束 1 说删除只允许用户在界面上**亲手触发**；⌘Z 只是一次按键，不是对
某个文件的删除请求。因此每一项都写一条 `action=paste` 的日志（粘了些什么、从哪来、什么时候、
结果如何），`undo._PUSH_ACTIONS` 不收它 —— ⌘Z 那一摞栈**照旧只装改名与移到废纸篓**。想撤掉就在
访达里自己删，或者选中它按 ⌘⌫（那条路有日志、能再撤销）。代价：⌘V 之后按 ⌘Z 撤不掉，这是有意的。

### 5. 复制在后台线程，粘完**不重扫整层**

大照片一个几百兆，挡住界面就是卡住，完成后横幅说清粘了哪些、为什么失败。新粘进来的照片由监听器
（ADR 0013）自己发现并显示 —— 这正是监听器当初要解决的场景。**刻意不重扫当前这一层**：重扫会把
网格清空，选中与滚动位置全丢。

### 6. 粘不了就不出现

「粘贴」出现在**相册**与**空白处**两份菜单里，但只在「剪贴板里真的有文件」时出现；⌘V 另外还要求
「这里有可粘的目录」，剪贴板一变就重算（在访达里 ⌘C 之后切回来直接按 ⌘V，得有反应）。

### 7. **粘到哪里看选区**（2026-10-14 修订两次，2026-10-05 修订一次：左键点空白处已不再留下当前项）

判据（⌘V 与菜单里那一条共用，决策 1 说的就是它）：

| 选区 | 粘到哪里 |
|---|---|
| **恰好选中一个相册** | **那个相册内部**（访达的「粘贴项目」：按在哪个文件夹上就粘进哪个文件夹） |
| 没选中什么 | 当前这一层（决策 1 那张表） |
| 选中的是照片 / 分组卡片 | 当前这一层 |
| 选了不止一个（多个相册，或照片 + 相册混选） | 当前这一层 |

「**恰好**一个」是刻意的：这一层里照片与相册卡片混着摆，所以「多选」未必就是「多选相册」。那种
时候都说不出「粘进哪一个相册」，于是照旧粘进当前这一层 —— 不该被一次多选悄悄改掉这条命令的老习惯。

判据读的是**网格真正选中的那些行**（`MainWindow._selected_album` 直接读
`selectionModel().selectedIndexes()`，**不走 `PhotoGrid.selected_rows`**）：后者在选区为空时会
**退回当前项**，「选区空了、当前项还指着一个格子」这个状态一旦出现，⌘V 就会粘进一个用户已经取消
选择的目录；由 `PhotoGrid.sync_current_to_selection` 收掉那个状态（**当前项必须落在真选区里**），
于是点空白与 ⌘ 点减选之后两者一起空。代价不对称，所以宁可粘错方向也不能反：**把文件粘进用户没选的
地方**用户未必一眼看得出，反过来（没粘到他以为的地方）他看得见。`selected_rows()` 那个回退**没有
动**（那是给别的命令用的，改它会波及删除、拷贝那一摞）。

菜单里摆在哪：

| 落点 | 菜单里 |
|---|---|
| **空白处** | **有**「粘贴」，与「新建相册」同属最上面那一组（ADR 0022 / 0023） |
| **单个相册** | **有**「粘贴」，在「拿进拿出」那一组的末尾（仍在「拷贝路径」正下方），**那一行写着 ⌘V** |
| 照片（单选 / 多选） | **不出现**（那一组里其余几行与分隔线照旧，ADR 0023 决策 2） |
| 分组卡片 / 多个相册 | 不出现（卡片与多选都说不出「粘进哪一个相册」） |
| 大图页 | 不出现（没有「当前这一层」可言） |

- **相册那一行写着 ⌘V，而且那枚键真的按那件事做**：做法是**不另做一份动作** —— 相册菜单里那一行
  **就是菜单栏那个 `_paste_action`**，因此点那一行与按 ⌘V 走的是同一个动作、同一个槽，两处不可能
  分叉。粘到哪里由 `MainWindow._paste_target` 按**选区**算，而右键那一格本来就会被
  `select_for_context` 选中（ADR 0014 决策 2），两边天然落在同一个目录上。问题从来不是「有没有第二枚
  键」，而是**同一个动作会不会在两种地方说两种话**：判据挂在**选区**上（用户能看见、也能改），
  两处就只剩一个真相。
- **照片上不摆**：那一格未必属于当前这一层（全部照片、分组那几屏都是各相册混在一起的），摆出来
  只会让人猜「粘到哪」。⌘V 一直在「编辑」里 —— **菜单里摆不摆与快捷键怎么用是两回事**。
- **空白处要摆**：那里选区是空的，「就粘到我现在看着的这一层里」是最没有歧义的一个落点。
- **大图页不参与**：那一页「选中」的是正在看的那一张（ADR 0021），不是用户选出来的，而 ⌘V 在那里本来就置灰。

## 顺手修掉的一个真 bug

粘完之后**网格里长不出新照片**，文件却确实在磁盘上：监听器报回来的是 watchdog 给的**解析过的真
路径**（macOS 上 `/var` 链到 `/private/var`），而 `MainWindow._current_dir` 存着 `enter_folder` 收到的
**原写法**，于是「这个变化是不是发生在当前这一层」永远说不成，那条变化被静默丢掉 —— 在访达里往
当前相册丢一张照片，网格同样当没看见。修法是 `enter_folder` 存解析过的路径（与 `Library.root`、
扫描出来的条目同一套写法），回归测试 `tests/ui/test_watch_flow.py` 里
`test_a_new_photo_lands_in_the_current_album_behind_a_symlink`。

## 后果

- 网格上「会动用户文件」的入口从两个变成**三个**：重命名、移到废纸篓、粘贴。前两个依然记账且
  `⌘Z` 可撤销，粘贴只记账（决策 4）。README 那一段已改。
- 粘贴**只增不改**：源文件一个字节不动，粘出来的是新文件。唯一会删的是「复制到一半失败时把本
  模块自己刚写的那个半截文件清掉」—— 留着它才是真的把相册弄脏了。除此之外不删用户目录里的任何东西。
- 同一个目录里**不能并发粘贴**：两个任务会争同一个目标名字，后到的会把先到的盖掉。界面上一次只
  跑一个（`MainWindow._paste_job`），core 里写明了这个前提。取消也只在**项与项之间**生效：粘到
  一半停下来会留下半截文件，那比粘完更糟。
- **右键菜单的目标与 ⌘V 的目标是两条路**（决策 7）：⌘V 与空白处走 `_paste_target()`，右键相册走
  的是动作 `data()` 上挂的那个相册。两者共用同一个后台任务前置条件（`_write_job`），所以同一时刻
  只会有一次粘贴在跑。
- 非 macOS 平台：同一段代码照常可用（Qt 在 Windows / X11 上把文件 URL 交给对应的文件管理器），
  **不加平台分支** —— 与「拷贝」一致（ADR 0017）。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 撤销粘贴 = 把粘进来的文件删掉（或移到废纸篓） | 撤销就是删除，而删除只允许用户亲手触发（约束 1） |
| ⌘V 的目标目录**不看选区**，一律按「当前窗口的目录」 | 只认「**恰好**一个相册」那一种情况，其余照旧按当前这一层 —— 跨相册的多选说不清。见决策 7 |
| 目标目录挂在**右键的那一下**上（菜单弹着时有效，菜单一关就作废） | 判据挂错了地方，左键选中一个相册再按 ⌘V 照样粘到当前层级。见决策 7 |
| 分组里一律粘到库根 | 与「以实际磁盘上的位置为准」相反：按年份分组的一组照片散在几十个相册里 |
| 照片菜单里也摆「粘贴」（粘进照片所在的相册） | 一格照片未必属于当前这一层，摆出来只会让人猜「粘到哪」；⌘V 一直在，不必靠菜单（决策 7） |
| 整批停下（有一个同名就不粘） | 十张里九张能粘也粘不成，把一条能用的命令废掉（决策 3） |
| 报个错让用户自己改名 | 访达不会这么做；这个右键菜单是照访达做的（决策 3） |
| 粘完重扫当前这一层 | 会清空网格（选中与滚动位置全丢），而监听器已经把新照片添进来了（决策 5） |
| 置灰而不是不出现 | 与 ADR 0014 决策 4 同一个取向：永远点不动的条目不如不出现 |
| 只让访达支持的图片格式能粘 | 用户在访达里 ⌘C 什么都有；替他拦下来只会让「粘了却没出现」更难懂 |
| 先复制到 `.gallery/` 再搬到目标 | 多一次全量复制，还要管临时文件的生命周期；目标名已经算好不会覆盖，直接落位即可 |
