# ADR 0014：右键菜单：四种落点、各自可做的操作、以及界面层第一次调起系统进程

- 状态：已接受
- 日期：2026-10-03
- 相关代码：`src/gallery/ui/menus.py`、`src/gallery/ui/menu_style.py`、`src/gallery/ui/desktop.py`、`src/gallery/ui/browser/grid.py`、`src/gallery/ui/main_window.py`

## 背景

网格里已经能双击进入、能选中、能行内重命名、能移到废纸篓，但**右键一点什么都不会发生**
（`contextMenuEvent` 全仓零命中）。桌面上没有一个软件缺这条交互：用户右键一张照片，
心里想的是「打开 / 在访达中显示 / 拷贝路径 / 重命名 / 删掉」。

网格这一层有三种东西混在一起（`PhotoRef` / `FolderRef` / `GroupRef`，见 `core.library.photos`），
它们能做的事**不一样**：照片能改名能删，相册能改名能删，分组卡片两样都不能（它不是磁盘上的
东西，ADR 0009）。所以这不是「把 5 个 `QAction` 塞进一个菜单」的机械活，落点不同菜单就不同。

另一个背景：前期调研把「右键菜单 / ⌘A 全选 /
在访达中显示 / 拷贝路径」列为**零 core 改动、不到 300 行**的桌面基本动作。它们确实只动 `ui/`，
但「在访达中显示」做不到 —— 原因见决策 3。

## 决策

### 1. 四种落点，菜单由 `ui/menus.py` 现建、样子由 `ui/menu_style.py` 接管

| 落点 | 判定 | 作用对象 |
|------|------|----------|
| 照片 | `indexAt()` 命中 `PhotoRef` | 该照片；多选时是整个选择 |
| 相册 | 命中 `FolderRef` | 该相册 |
| 分组卡片 | 命中 `GroupRef` | 该分组 |
| 空白处 | `indexAt()` 无效 | 不作用于对象，只给视图级命令 |

**这一版不做大图页的右键菜单**，也不做面包屑的。大图页的写操作另有一笔账要算：删完之后
网格里的选中落到哪、`_current_row` 怎么对账（ADR 0008 已把「大图页不能删」列为边界），
先把网格这一侧做干净。

> **已补上**（见 [ADR 0021](0021-viewer-context-menu.md)）：那笔账已经算清 —— 删完接着看
> 下一张，大图页的作用对象是 `_current_row` 而不是网格选区。大图页的菜单与网格那张逐行相同，
> 只把第一行的「打开」换成「退出」。本 ADR 下面几条仍然成立：菜单现建用完即弃、
> `QAction` 全局复用、「在访达中显示」与「在默认应用中打开」的键位分工。

菜单**每次弹出时现建、用完即弃**，但 `QAction` **本体复用**菜单栏里那一份：这样快捷键文字
（⌘R / ⌘⌫ / ⌘I）白拿，置灰状态也只有一处逻辑（`_update_action_states`）。

### 2. 右键时的选择语义由视图决定，且不挪扩选锚点

`QListView` 默认的 `contextMenuEvent` **不会**选中光标下的项，于是 Qt 原生菜单里
「右键 A、菜单却作用在原来选中的 B 上」是默认行为。规则定死为：

| 落点 | 选择怎么变 |
|------|------------|
| 未选中的项 | 清掉旧选择，只选它，菜单作用于它 |
| 已选中的项 | **不动**（多选保持原样），菜单作用于**整个选择** |
| 空白处 | 清掉选区（与访达一致） |

**「已选中」问的是真选区，不是 `selected_rows()`。** 补记（2026 年复核时发现的实现缺陷）：
`PhotoGrid.selected_rows()` 在选区为空时会**退回当前项**（网格刚打开时 Qt 可能顺手把
第 0 行设成当前项），而 `select_for_context` 判「这一格是不是已经选中了」原本问的正是
它。于是「当前项是第 0 行、但谁也没选中」这个状态被误判成「它已经选中了」而直接返回 ——
一个格子都没选中，右键菜单却照常摆出来。

而菜单里每一条命令读的都是**真选区**（⌘V 粘到哪里就看它，见 ADR 0018 决策 7），
于是用户看到的是「右键了京都」，实际作用的是「什么都没选」：粘到了与相册同级的库根里。
**把文件粘进用户没选的地方是这个功能里最坏的一种错** —— 比反过来严重得多：
粘到他以为的地方用户看得见，粘到没选的地方他看不见。

因此表里「已选中」一栏要读成「**在真选区里**」：另起一个 `genuinely_selected_rows()`
不带回退，`select_for_context` 改问它。「已选中 → 不动」那条（多选保持原样）照旧 ——
对多选来说真选区与非空时的 `selected_rows()` 是同一个东西。

`PhotoGrid.select_for_context(row)` 是这套语义的唯一实现，它**不碰 `_range_anchor`** ——
扩选锚点是「上一次完成的普通左键点选」。挪了它，「右键 A → ⇧ 点 D」就会从 A 铺开，
而访达是从上一次左键那格铺开的。改选区与改锚点必须是两件事。

多选时隐藏「打开」（打开哪一张语义不清）与「复制元数据」（拷谁的？），「重命名」只在单选时出现
（ADR 0004：重命名一次只改一条）。凡是只对「某一个东西」成立的命令，多选时一律不出现。

### 3. 「在访达中显示」用 `open -R`，这是界面层第一次调起系统进程

`QDesktopServices.openUrl` 只能「打开」，没有「在访达里选中并露出它」这个动作。访达的
「显示简介 / 在访达中显示」走的是 `open -R <路径>`。因此：

- 新增 `ui/desktop.py`，封装 `reveal_in_finder()` / `copy_to_clipboard()`；
- 它是**界面层第一个 `QProcess`**，模块文档里写明「Qt 没有对应 API，这是权衡的结果」，
  而不是让它看起来像随手写的；
- 失败（进程起不来、非 macOS）时降级为**打开所在文件夹**，并在横幅里说清楚做了什么；
- **不进 `core/`**：`core/` 不该知道访达是什么，Gallery 也给 core 打过回归测试
  （`tests/test_guards.py`）。

**拷贝文件（⌘C）不做**：访达认可的「文件引用」剪贴板类型 Qt 放不进去，真要做得引
pyobjc / NSFilePromise。为一个拷贝动作引入整套原生绑定不值得。`拷贝路径 ⇧⌘C` 能做，做它。

> **已推翻**（见 [ADR 0017](0017-copy-file-to-clipboard.md)）：上面那个前提经不起复核 ——
> `QMimeData.setUrls()` 写上去的 `public.file-url` 与 `NSFilenamesPboardType` 与访达
> 自己 ⌘C 时写的公开类型完全一致，pyobjc 并不需要。「拷贝 ⌘C」已加回照片与相册菜单，
> 摆在「拷贝路径」上面。

> **已按落点分成两条**（2026-10）：`open -R` 只对**照片**成立。`-R` 的意思是「在它**所在的
> 目录**里把它选出来」—— 对着相册用它，用户看到的是**外面**那一层，而他按下这一下要的
> 是**里面**摆着什么。于是 `ui/desktop.py` 里多了一个 `open_folder_in_finder()`：不带
> `-R` 的那个 `open`，即访达自己的「打开文件夹」，降级也走 `QDesktopServices`（在 macOS 上
> 同样落成「打开这个文件夹」，所以两路文案是同一句）。判据是**整个选区都是相册**：混进一张
> 照片就仍然是「选出来」，因为 `open` 递一个照片进去是交给默认应用打开它。标题条上那个访达
> 按钮（ADR 0034）开的也是它。

### 4. 分组卡片：只留打开与复制分组条件

最初的做法是**置灰 + 菜单末尾一条不可点的说明行**（「分组不是磁盘上的文件夹，改不了名也删不掉。」），
用来兑现 README 早先那句「菜单会置灰、按下去也会说明为什么」。后按用户意见收窄为**干脆不出现**：
菜单里摆两个永远点不动的条目、再加一句解释为什么点不动，等于把同一个事实讲三遍。分组不是磁盘上
的东西，这不需要解释 —— 它本来就不该出现在「对一个文件做什么」的菜单里。

> **已改**（见 [ADR 0020](0020-group-card-operations.md)）：**改名与删掉分组本身**这两条仍然
> 不出现；但菜单里添了六条作用在**组内那批照片**上的命令（在访达中显示、拷贝、拷贝路径、
> 复制到相册、移动到相册、移到废纸篓）。「分组不是磁盘上的东西」挡的是「改这个卡片」，
> 挡不住「拿这个卡片所代表的那批照片去用」—— 那批照片实实在在躺在磁盘上。

### 5. 新增命令同时进菜单栏，右键菜单不是唯一入口

⌘A 全选、⇧⌘C 拷贝路径都注册到新增的「**编辑**」菜单里（⌘Z 撤销一并从「文件」挪过来，
这是 macOS 的标准位置）。只活在右键菜单里的命令是发现不了也记不住的命令。

> **后续（[ADR 0044](0044-duplicate-in-place.md)）**：「复制」⌘D 也挂进了「编辑」菜单，
> 位置在「拷贝路径」与「粘贴」之间 —— 与它在右键菜单「拿进拿出」组里的邻居一致。
> 它同样 `addAction` 到窗口（理由见下一条）。

### 6. 「在访达中显示」挂 ⌘⏎ 这个**真**快捷键，且要 `addAction` 到窗口

用户要的是「菜单里写着这个键，而且按得出来」。`⏎` 归「打开」（网格自己处理，见
`PhotoGrid.keyPressEvent`），`⌘⏎` 正好空着，于是给「在访达中显示」——与访达把
⌘C / ⇧⌘C 让给拷贝是同一个思路。

三条由此而来的约束，都是实测出来的：

- **`QAction` 的快捷键只有在它被 `QWidget.addAction` 加进某个控件之后**才注册进 Qt 的
  快捷键表。光给它一个 `QAction` 父对象，`setShortcut` 照样设上了，按下去却什么都不发生。
  而右键菜单是用完即弃的，靠它注册等于没注册 —— 所以这条动作挂在**窗口**上
  （`self.addAction(self._reveal_action)`）。挂窗口**不会**让它传递到菜单栏里：菜单栏只画
  被塞进某个 `QMenu` 的动作。
- **置灰要与菜单行共用一处判据**（`_update_action_states`）：⌘⏎ 在没选中文件、选中的
  是分组卡片、正在改名字时都要按不动。改名字这一条尤其要紧 —— 窗口级快捷键在按键到达
  控件之前就被 Qt 取走了，不置灰的话「敲完名字顺手 ⌘⏎」不会提交改名，只会弹出一个访达。
- **快捷键只在网格下有效**：大图页没有选区（这一页的写操作另有 ADR 0008 那笔账），
  因此不做大图页的版本，⌘⏎ 在那里仍然只是回车（退回网格）。

> **已改**（见 [ADR 0021](0021-viewer-context-menu.md)）：大图页有了右键菜单，⌘⏎ 与 ⇧⏎
> 在那里同样可用，作用对象是**正在看的那一张**。下面那句「⌘⏎ 在那里仍然只是回车」只对
> 不带修饰符的 `⏎` 成立 —— 退出仍是 `Esc` / `⏎`。

菜单里那一行的显示不用另外写：`ShortcutColumnMenu` 本来就把 `QAction` 的快捷键画在
最右列，而「打开」那枚**只画不生效**的 ↵ 提示（`show_key`）走的是同一个出口，两行因此
共用同一套列宽：⌘ 落在 ⌘C 的 ⌘ 那一列，↵ 落在 ⌘R 的 R 那一列。

### 7. 「在默认应用中打开」`⇧⏎`：**只有照片菜单有**

用户要的是「把这一张交给系统为这类文件设定的默认应用」。`QDesktopServices.openUrl` 就是
这件事，一个 `openUrl` 而已，不必起进程，因此落在 `ui/desktop.py::open_with_default_app`，
与 `reveal_in_finder` 是同一件事的两头（一个交给别的程序看，一个留在访达里）。

四条由此而来的约束：

- **键位是 `⇧⏎`，与 `⏎` / `⌘⏎` 排成一行**：三个「打开」挨着摆，画的又是同一列，
  用户认得出是同一族键。`⇧⏎` 同样要 `addAction` 到窗口才按得出来（决策 6 那条）。
  这一行**逼着快捷键的列改成「按顺序填」**：原先每个修饰符固定一列，`⇧` 落到 `⌘` 的外侧，
  中间空着一格，看着像凭空多出一列（用户原话：shift 应该在第二列，实际是按照顺序的）——
  规则见 ADR 0016 决策 7。
- **只有照片菜单有这一行**：相册是文件夹，让系统用默认应用打开它就是让访达打开它 ——
  与「打开」是同一件事，菜单里摆两行等于把一件事说两遍。分组卡片没有路径，更无从谈起。
  多选时与「打开」一起不出现：多选的那些要交给哪个程序打开，说不清。
- **`ui/desktop.py` 成功时不返回话，失败时才返回**：那个应用自己会弹到前台，横幅再抢
  一句只是噪音；而静默**失败**会被当成程序卡住了。
- **`PhotoGrid.keyPressEvent` 改成只认不带修饰符的回车**：窗口动作不可用时（选中的是分组
  卡片、正在改名字）`⇧⏎` 会落到网格上，而网格原先把**任何**回车都当成「打开」——
  于是「换个地方打开」最后打开的仍是 Gallery。宁可什么都不做。
  这条判据方向写反不得：写成「有修饰符才算打开」会把整个软件最常用的那个键弄没。

不做的：「打开方式…」那种能挑程序的版本。那会改掉系统对这个类型的默认设置，属于改
用户系统设置，不该由 Gallery 的一个菜单项顺手做掉；换关联程序请去访达。

## 后果

- 菜单栏多了一个「编辑」，README 的操作表要跟着改。
- 网格上下文里**没有任何会碰用户文件的代码**：能动的仍然只有重命名与移到废纸篓两条，
  都走既有的 `Library.rename_entry` / `move_to_trash`，都记账、都可 ⌘Z。
- `GroupRef` 没有 `.path`（只有 `facet` / `key` / `label` / `photos`），所有取路径的命令
  必须先挡掉分组，否则「在访达中显示」会 `AttributeError`。
- 「复制元数据」在报告没加载时要经后台读一次再写剪贴板，因此它是**唯一一条可能慢半拍**
  的菜单命令，完成后走横幅报结果。
- 空白处的「分组 / 排序 / 缩略图大小」直接复用已有子菜单里的 action，子菜单自己现建 ——
  把菜单栏的 `QMenu` 直接 `addMenu` 进来会把它从菜单栏里**搬走**。
- 菜单最右那一列现在有三枚键位挨着：「打开」的 ↵（只画不生效）、「在默认应用中打开」的
  ⇧⏎ 与「在访达中显示」的 ⌘⏎（真快捷键）。列宽是整张菜单一起量的，它们不会互相挤歪，
  但**新增一条真快捷键就可能让这张菜单变宽**（`reserve_shortcut_columns`）。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 右键菜单里放「复制文件」⌘C | ~~Qt 的 `QMimeData` 放不进访达认可的文件引用类型，要做就得引 pyobjc~~ —— **已采纳**，前提经不起复核，见 ADR 0017 |
| 新建相册文件夹 | 约束 6：不给用户照片目录写入非 `.gallery/` 的东西。留给访达 |
| 批量改名 | ADR 0004 明确排除：一次改错就是几十张照片找不到 |
| 「添加到相簿」「收藏」 | 需要 Gallery 自己的收藏库，等于变成导入式图库，与项目定位对立 |
| 评分 / 关键词 / 颜色标签 | M5 写回还不存在（`core/` 里没有任何 `-TAG=value`），菜单里出现置灰项不如没有 |
| 在大图页也放 ⌘⌫ | ~~删完之后网格选中怎么落、`_current_row` 怎么对账要另算一笔账；先做网格这一侧~~ —— **已补上**，见 [ADR 0021](0021-viewer-context-menu.md) |
| 右键落在已选中项时也重置为单选 | 与访达相反，会让「右键批量操作」这件事变得无法使用 |
| 把菜单逻辑塞进 `main_window.py` | 它已经 2397 行；菜单构建单独成模块，才测得了项的文本与顺序 |
