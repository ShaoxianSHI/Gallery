# ADR 0030：元数据写回原文件 —— 只改位置，写完必须核对

- 状态：已接受
- 日期：2026-10-06
- 相关 ADR：0004（改名）、0008（废纸篓）、0023（菜单分组）、0031（位置的双向编辑）
- 相关代码：`src/gallery/core/metadata/writeback.py`、`src/gallery/core/metadata/journal.py`、
  `src/gallery/core/metadata/undo.py`、`src/gallery/core/metadata/exif.py`、
  `src/gallery/ui/write_ops.py`

## 背景

Gallery 到此为止对用户照片的写入只有三类：改名（ADR 0004）、移到废纸篓（ADR 0008）、
移动到相册（ADR 0019）。**全部是「让东西换个地方」，没有一个改动过文件的内容**。

路线图上的 M5「元数据编辑：写回原文件，附操作日志与回滚」一直挂着。这里决定它的形状 ——
而第一个要回答的不是「怎么写」，是**「哪些能写」**。

## 决策

### 1. 只改位置：坐标与三层地名

可写的字段恰好十三个，全部与位置有关：

| 组 | 标签 |
|---|---|
| 坐标 | `EXIF:GPSLatitude` / `GPSLatitudeRef` / `GPSLongitude` / `GPSLongitudeRef` |
| 顺带清掉 | `EXIF:GPSAltitude` / `GPSAltitudeRef` / `GPSDateStamp` |
| 地名 | `XMP:City` / `XMP:State` / `XMP:Country` 与 `IPTC:City` / `IPTC:Province-State` / `IPTC:Country-PrimaryLocationName` |

判据是**「这条值是设备的事实记录，还是人的标注」**：

- 相机、镜头、拍摄时间、光圈 / 快门 / ISO / 焦距、像素、色彩空间是**相机机身写下的证据**。
  替用户改它们等于伪造证据，还会悄悄毁掉别的软件据此做的事（同机位去重、时间轴排序）；
- 地点与关键词这类字段在 IPTC / XMP 里的语义**本来就是人的标注**，相机不写，Gallery 也不写；
- 创建者与版权是**权利声明** —— 替用户填作者名，等于替用户主张权利，连空的都不填。

关键词、标题、说明、评级留到后续（同一套机制，`WRITABLE_TAGS` 加几行即可）。

**白名单是代码里的一条事实，不只是界面上的一句承诺**：`write_metadata` 逐条查
`WRITABLE_TAGS`，不在其中直接抛异常；回归测试在 `tests/core/metadata/test_writeback.py`。

### 2. 写回原文件，而不是改索引

`.gallery/index.db` 里那三列地点始终是 EXIF 的投影（`facets.extract` 从原始键值抽出来）。
写回原文件之后，索引里的旧行因为 `(大小, 修改时间)` 对不上而**自动作废**，下一次分组或排序
重读一次就更新了。

于是「面板说杭州、分组说 Bordeaux」这种两套真相在结构上就不可能发生 —— 两处读的是同一份
字节。这也是为什么不做「只改 Gallery 自己的索引」那种看起来更省事的做法。

### 3. 写完必须回读校验，退出码不算数

**exiftool 返回 0 不代表写进去了**：标签不被该格式支持、格式拒绝、原地改失败，都可能
「看起来成功」。所以 `write_metadata` 的判据是回读 —— 写完之后再读一次那几个标签逐个比。

- 对不上 → **按原值写回去** → 抛 `MetadataWriteError`，横幅说「写入没有生效，照片已经恢复原样」；
- 回滚本身也失败时，错误信息里必须带上这件事（那是最坏的情形，不能说得比实际轻）。

**坐标按数值比，不按字符串比**：写进去是 `30.274150`，读回来是 `30 deg 16' 26.94"`。
逐字符比会把每一次成功的写入都判成失败。容差取 1e-5 度（约 1.1 米）—— 那是度分秒量化误差的
三倍余量，又不至于把「差了一条街」当成写成了。

### 4. 撤销按**字段**，别人改过的不覆盖

日志里新增 `ACTION_METADATA` / `ACTION_UNDO_METADATA`，记录带**字段级**的
`FieldChange(tag, before, after)`。这是第一份需要字段级信息的记录：改名与删除靠
`source` / `target` 就能还原，写回动的既不是路径也不是文件集合。

撤销时**逐字段比对**：当前值仍是我们写下的那个才写回原值；不相等说明用户在 Gallery 之外
（或另一个窗口）改过它 —— 那就**跳过并如实报告**。用户按 ⌘Z 想撤的是自己刚才那一下，
不是把别人刚才那一下也抹了。部分冲突时，能撤的照撤。

**撤销的那一次写入记成弹栈动作**，不再压回栈顶，否则「改一下、按一次 ⌘Z」会变成无限循环。

### 5. 不做整份备份

journal 已经逐字段记下了原值，足以精确撤销「我们改过的东西」。而一次写回只改几 KB，
为几万张照片的库各留一份原图是不可接受的膨胀。

代价要说明白：一次写回如果**把文件改坏了**（exiftool 的 bug、磁盘故障），没有整份备份可回。
我们靠的是 exiftool 的成熟度与回读校验回退，而不是自己再实现一遍文件复制。

### 6. argv 上的四件不能省的事

| 参数 | 为什么 |
|---|---|
| `-overwrite_original` | **否则 exiftool 会在照片旁边留一个 `xxx.jpg_original`** —— 违反约束 6 |
| `-charset IPTC=UTF8` | **exiftool 13 起泛指的 `-charset UTF8` 不再覆盖 IPTC**，而 IPTC 缺省是 Latin-1。少了它，中文地名写进去再读出来是乱码 |
| **不加 `-P`** | 让修改时间自然变化，索引的 `(大小, 修改时间)` 判据才会作废。用 `-P` 冻住它的话，长度相同的替换会让索引**静默地继续用旧值** |
| `-overwrite_original_in_place` | 只动对应的那几个字节，大图不必重写整份；不支持该模式的格式自动退回普通覆盖（重试是安全的：所有字段都会再写一遍，值幂等） |

**回读用的是一级族名（`XMP:City`），写回用的是同一个名字**：exiftool 的 `-G` 按一级族回填键，
写 `XMP-photoshop:City` 而读回 `XMP:City` 会让校验永远判成失败。

### 7. 顺带修掉的一个真问题：IPTC 中文是乱码

改这一块时实测发现：**exiftool 13.x 下 `-charset UTF8` 不覆盖 IPTC**，于是 Gallery 一直把
照片里的中文地点读成乱码（分组里的「城市」一栏全是 `æ­£å·ž`）。读取侧统一改成
`EXIFTOOL_CHARSET_ARGS`（同时给读取与写回使用），写进去与读出来的编码从此是同一套。

## 后果

- **约束 1 的范围变了**：从「绝不删除、移动」扩到「除了改名，还可以改照片**里面**的位置」。
  界面上所有这类入口仍然只在 `ui/write_ops.py` 一处（回归测试新增 `write_place`）。
- 写回之后必须做的界面联动有五件：屏蔽监听器回环、丢内存缓存、换网格那一行的引用、重排
  分组排序、重读面板。少任何一件，用户看到的都是「没生效」。
- 缩略图缓存要**换键**（键含 `(路径, mtime, size)`）而不是重新解码 —— 像素一个字节没动。
  不屏蔽监听器回环的话，这次节省会被那一条 MODIFIED 整个抵消掉。
- 只支持位置这一组字段，是一次有意的收窄：关键词、标题、说明的写回随时可以按同一套机制加上，
  但每一次都要重新想清楚「改了 facet 之后索引与分组怎么办」。

## 被否决的替代方案

| 方案 | 否决理由 |
|------|----------|
| 让用户编辑任意元数据（相机、拍摄时间、曝光……） | 那是改写拍摄证据。别的软件拿这些字段做去重与排序，改了等于替用户撒一个自己收不回的谎 |
| 只改索引，不动原文件 | 索引与照片会变成两个真相；别的软件读到的还是旧值，而用户以为自己改成功了 |
| 写前把原文件整份备份到 `.gallery/` | 几万张照片的库放不下；journal 的字段级原值已经足够精确撤销 |
| 相信 exiftool 的退出码 | 退出码 0 不代表标签写进去了 —— 这正是回读校验存在的理由 |
| 撤销时无条件按原值覆盖 | 会毁掉用户在 Gallery 之外的编辑，而那正是他按 ⌘Z 时没打算撤掉的东西 |
| 批量编辑整个相册的位置 | 一次动几百张照片的 GPS 是不可想象的操作；一次只改一张 |
