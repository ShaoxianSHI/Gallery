# ADR 0098：两档背景图（生成 / 照片），图在缓存、清单在应用状态

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0038（东西只放两处）、0096（底色只在窗口上铺一次）、
  0097（两档自定义背景色，只换底不换字）
- 相关代码：`src/gallery/core/backdrops/`、`src/gallery/ui/theme.py`、
  `src/gallery/ui/dialogs/backdrop.py`、`src/gallery/ui/window/settings_flow.py`、
  `src/gallery/ui/browser/transition.py`、`src/gallery/ui/browser/delegate.py`

## 背景

0097 之后底色可以换颜色了，但只能换成一个纯色。用户要的是「几种颜色的墨水在水里晕开」
那种很淡的晕染图，以及拿自己的照片当背景。

难点有四个：

1. **正文色不跟背景走**（0097）。一张深色照片铺在浅色那一档上，浅字压浅图，任何地方都不报错。
2. **0038 说东西只放两个位置**，现在还多了一类「应用级、少量、大」的文件，得说清它算哪一种。
3. **缓存是可以删的**。把用户挑的照片放进缓存，删一次缓存那张背景就没了 —— 除非能重新长回来。
4. **底色只在窗口上铺一次**（0096），但 `paint_background` 有三个调用点，其中两个在网格视口里，
   坐标系与窗口不同。

## 决策

### 1. 图在缓存，清单在应用状态

图片落 `<app cache>/backdrops/`，清单落 `<app data>/Gallery/backdrops.json`。

判据与 0038 里那条一样是**文件数**：一个库只会有几张背景图，几百 KB 到几 MB 一个文件，
不是缩略图那种十万个小文件。而清单**不能进缓存** —— 名字是用户填的，重扫重建不出来；
清单自己丢了，自愈的依据也就没了。

### 2. 图片可丢，靠配方与来源路径长回来

- `kind=ink`：清单里存着完整配方（配色、种子、形状参数、算法版本），丢了就重算。
- `kind=photo`：清单里存 `source`，原图还在就重新导入。
- 都不行的（原图被删、缓存被清），**清单那一条保留**，那一档退回背景色 —— 替用户删掉
  等于替他做了决定。

启动时跑一次 `BackdropStore.repair()`，做过的事进横幅。

### 3. 照片只读，转存一份 JPEG

导入 = 读用户那张原图 → `exif_transpose` → 长边缩到 2560 → JPEG q90 → 写进缓存。
**原文件的字节与 mtime 一个都不变**，这条有测试盯着。

存 JPEG 而不是 PNG：照片原样存 PNG 一张十几 MB，而背景不需要无损。

### 4. 两档仍然是两档，遮罩负责可读性

`Preferences` 多两个键：`light_backdrop` / `dark_backdrop`（背景库里的 id，空串 = 用背景色）。
哪一档生效仍由**系统**决定，与 0097 决策 3 同一条。

图与正文的冲突用一层**遮罩**解：按图片平均亮度解一个 alpha，把合成后的平均亮度压回
这一档该有的位置（浅色 ≥ 0.86、深色 ≤ 0.42），遮罩色就是这一档的 `AppTheme.background`。
生成出来的图本来就很淡（均值 ≈ 0.88），遮罩为 0，等于没加。

于是 `AppTheme.background` **继续是 `QColor`**：日历配色、菜单、对话框、`opaque_over`
全都不必改。

### 5. 三个绘制点都传窗口坐标

`paint_background(painter, rect, *, origin)`，`origin` 是这块矩形左上角在窗口里的位置。
窗口自己传默认值，网格过渡帧与分区标题传 `viewport.mapTo(window, QPoint(0, 0))`。

不传的话，切档动画那一帧与分区标题会露出一条纯色 —— 0096 最怕的那种缝。

预缩放的那一份 pixmap 按窗口尺寸裁好缓存在 `ThemeWatcher` 里，`resizeEvent` 只记新尺寸，
重建发生在下一次绘制时。

### 6. 入口在「外观」子菜单末尾，紧跟背景色

一排三项：生成背景…、用照片做背景…、管理背景…；再加两组子菜单「浅色背景 / 深色背景」，
每组第一项是「用背景色」，其余是背景库里全部的名字。对话框里也能直接选「设为浅色 / 深色」，
两条路落到同一个值上。

生成对话框里点色卡只换配色，**同一个种子**，所以换回来还是同一幅画（浓度场按参数缓存）。

## 后果

- 换一次背景 = 一次 `set_backdrops` 下发（与换背景色同一条 `refresh()`），毫秒级。
- 生成一张约 0.5 秒（浓度场 320×200 × 25 个噪声八度），同步执行 + 等待光标；浓度场有缓存，
  换回用过的配色是瞬时的。
- 新增第三个位置 `<app cache>/backdrops/`，0038 的「只放两处」由此修订为
  「缩略图与背景图都在应用缓存里，各自一个目录」。
- 会话文件多两个键。老版本读不懂它们，那份文件本来就是「读不懂就回默认」。

## 被否决的替代方案

- **背景图放进 `<app data>/Gallery/` 而不是缓存**：备份与迁移更稳，但那是把几百 KB 到
  几 MB 的装饰数据当成用户数据来维护，而它本来就能重建。
- **照片不复制、直接引用原路径**：省一份空间，但用户移动或删掉原图之后背景就空了，
  且每次启动都要去读用户目录里一个可能已经不存在的文件。
- **按 0097 那样拒绝「深色图放进浅色那一档」**：那会让「用这张照片做浅色背景」直接失败，
  而用户想要的往往正是「把它压淡一点」。
- **`AppTheme.background` 换成图片**：日历、菜单、对话框、两处 `opaque_over` 全从它派生，
  改它等于同时改十几个地方的可读性。
