# ADR 0102：自定义配色可以有多个颜色

- 状态：已接受
- 日期：2026-10-25
- 相关 ADR：0035（圆角轮廓）、0098（背景图与遮罩）、0100（文案口径）、
  0101（自定义配色，单色）
- 相关代码：`src/gallery/core/backdrops/recipe.py`、`src/gallery/ui/dialogs/backdrop.py`

## 背景

0101 让用户挑一个颜色，生成一套同色系的晕染 —— 那条路径把一个颜色兑成六档浅深。
想问的是「能不能多色」。

算法本来就是多色的：`colorize` 把浓度 `t` 映到**一条**调色板查找表（`colors` 的 N 个停点，
在 OKLab 里插值）。八套预设里最多的有 7 个停点 —— 多色从来不是限制。限制只在那个入口：
它只收一个颜色。

## 决策

### 1. 一到三个颜色，按挑选次序拼成一条渐变

「+」每点一次**追加**一个颜色（不是替换），最多三个；取消取色器什么都不变。自定义那一格
（「+」左边那颗 34×22 的色块）用它自己的渐变底显示这几个颜色，并当场选中。

上限是三个：再多就不是「一两个色相在墨里化开」，而是一块花布；那颗 34×22 的色块也放不下。
**到上限时「+」按不动**，tooltip 说明原因 —— 不让它悄悄变成「替换第一个颜色」。

重新开始走**右键那颗自定义色块**的菜单（「重新挑选颜色…」）：清掉自定义那套，回到第一套预设。
「+」只有一个意思（追加），删除与重开就放在那颗色块自己身上。

### 2. 每个颜色各占一段浓度，且多色时整体抬高停点

```
颜色  A  A  A/B  B  B  B          ← 两色时各占一段，过渡只在交界
停点 0  .28 .50 .72 .88 1
```

- **不这么做的话，屏幕上只剩最后一个颜色**：它站在最浓的那一头，而前一个颜色只落在最亮的
  那一小片里。实测这套场（同一份配方、同一个种子）的浓度中位数是 **0.45**，25% 分位 **0.32** ——
  6% 的起点几乎就是白色。
- 所以多色时停点整体抬高：`0.18 → 0.26 → 0.34 → 0.44 → 0.52 → 0.60`。单色仍用 0101 那一套
  （`0.06 → … → 0.60`），视觉与已发布的样子一致。
- 最深仍只到 60%：再浓正文压不住（0098 的遮罩管亮度，不管「一整块颜色」）。

### 3. 仍然是「一维的多色」，不是按位置分块

颜色只是浓度的函数，所以几个色相是**交织的丝缕**：同一浓度的地方是同一种颜色，不同的色带
被墨纹切开。真要做到「左边一块红、右边一块蓝」得再加一张低频场当色区选择器、配方新增字段
并升 `VERSION`（已生成的缓存图会重算），这一轮不做。

### 4. 配方与命名

`Recipe.colors` 本来就存着完整停点，**不升 `VERSION`、不加字段**；颜色个数与次序都进哈希，
所以「蓝→橙」与「橙→蓝」是两幅画。默认名字是「自定义 · #336699 → #b06a3b」，三个颜色也在
40 字的名称上限内。

渐变色块的边框仍按 0101 的办法预先合成成不透明（0035），渐变时按这几个颜色的平均色合成 ——
一圈 1 点宽的边框跨不出那么大的色差。

## 后果

- 「+」的 tooltip 随状态变：没有颜色时「选一个颜色…」，有颜色时「追加为渐变色」，
  到上限时「最多三个颜色（右键自定义色块可重新挑选）」。
- 自定义色块的外观从纯色变成渐变；常态/选中两圈边框的深点问题按 0035 处理（有像素测试）。
- 单色那条路径的产物一个字节都没变（同一套停点、同一个函数）。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 第二次挑颜色时替换第一个 | 用户想的是「再加一个色相」，替换会让第一个颜色凭空消失 |
| 只有两个端点颜色 | 0101 的那条否决现在反过来：追加式入口不必解释「哪一端更浓」，而三个颜色恰好覆盖「青 / 藕 / 蜜」这类常见搭配 |
| 不设上限，挑几次算几次 | 色块越来越花，名称越来越长；超过三个颜色在 16:10 的淡背景上基本分不开 |
| 按位置分块的多色（左红右蓝） | 要第二张场 + 配方升版 + 新的交互；先看这一版够不够用 |
| 给色块画一个小「×」来清空 | 34×22 里放不下第三个可点的东西；右键菜单是这一族控件在别处也用的方式 |
