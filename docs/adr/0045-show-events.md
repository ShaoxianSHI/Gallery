# ADR 0045：第二类事件「演出」—— 复用什么公共字段、重名字段怎么消歧

- 状态：已接受
- 日期：2026-10-07
- 相关 ADR：0043（事件体系）
- 相关代码：`src/gallery/core/events/{kinds,prefill}.py`、`src/gallery/core/library/search.py`、`src/gallery/ui/dialogs/event_edit.py`

## 背景

ADR 0043 定了「公共脊柱 + 每类一张扩展表」，并说好「将来加演出就多一组它自己的字段」。演出的字段有 15 个
（演出名称 / 艺人 / 嘉宾 / 剧目 / 日期时间 / 城市 / 场馆 / 票价 / 实付 / 座位 / 评分 / 演出类型 / 购买渠道 /
感想 / 备注），三件是 ADR 0043 没有回答的：哪些进公共 `events` 表、哪些进扩展表；「日期/时间」里的**时间**
没有地方放（公共日期只到天）；演出的「评分」与旅行重名、「城市」与 EXIF 的「城市」重名，而搜索候选按名字
匹配。

## 决策

### 1. 公共脊柱只复用三个字段，其余 13 个进 `event_show`

公共：`title`（演出名称）、`started_on`（日期 / 结束日期）、`note`（备注）。独有：`artist` / `guests` /
`program` / `start_time` / `city` / `venue` / `ticket_price` / `paid` / `seat` / `rating` / `show_type` /
`channel` / `thoughts`。**评分、花费这类「看起来每类都能问」的字段不提升为公共**：那要给 `events` 表加列，
而 `store.attach` 的版本升级路径是 `DROP` 所有事件表重建（会清空用户已填的事件与绑定）。新开一类只多一张
`event_show`（`CREATE TABLE IF NOT EXISTS`），**不升 `SCHEMA_VERSION`、不丢任何数据**。

### 2. 时间另开 `start_time`（开场时间），公共日期仍只到天

`started_on` 是 `DAY`，`parse_calendar_day` 只认 `YYYY-MM-DD`，按日期范围的比较建立在「纯日期可比较」上，
让它接受时间会波及旅行、解析与区间比较；于是日期复用公共列，时间进 `start_time`（如 `19:30`），代价是
`#开始日期` 只按日期筛，时间不参与。

### 3. 自动标题与预填由类型声明，不再硬编码「目的地」

`EventKind` 多两个声明：`title_parts`（自动标题在日期之后接哪几栏，**取第一个非空** —— 旅行是目的地，演出
先剧目再艺人）与 `place_field`（预填地点进哪一栏）。`suggested_title` 因此收整个 `values`。

### 4. 搜索里重名的字段自动加类型前缀；字段 id 一律带类型

> **本节已被 [ADR 0046](0046-event-search-field-prefixes.md) 取代**：现在每类独有的字段一律带类型前缀，
> 不再只在重名时加。字段 id 一律带类型那半条仍然成立。

候选列表按名字匹配，同名只能选中一个：一个事件字段的标签**已被照片那族或先声明的那一类占用**时，改叫
「演出·城市」「演出·评分」，照片那一族的「城市」不动。字段 id 一律写成 `event_{kind}_{field}`（如
`event_trip_destination`），因为条件的身份是 `(id, 原文)`，两个类型同名的列不带类型就会让两条不同的条件
撞成一条。

## 后果

- 菜单（记录为 / 新增事件 / 编辑事件）、建表、读写、journal、⌘Z、分组、绑定搬迁全部按 `EVENT_KINDS` 迭代。
- 面板对金额栏的校验从硬编码的 `cost` 改成「所有 `REAL` 字段」，错误文案带上字段名。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 评分 / 花费提升为公共字段 | 要给 `events` 加列 = 升版本 = 现有重建逻辑清空用户事件（决策 1） |
| 把时间并进 `started_on` | 波及旅行与日期解析、区间比较，而收益只是少一栏 |
| 演出类型做成固定下拉 | 现有 `choices` 只会渲染成一排按钮，剧种一多就挤；自由填写零新控件 |
| 两种「城市」「评分」在面板与搜索里都改名 | 面板按类型打开没有歧义，只在全局搜索那一层消歧 |
