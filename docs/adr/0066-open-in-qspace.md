# ADR 0066：第二个外部应用：在 QSpace 里打开这一层（或这一张）

- 状态：已接受
- 日期：2026-10-17
- 相关 ADR：0034（用外部应用打开的入口）、0014（`open -R` 那条右键命令）、0021（大图页的当前项）、
  0038（东西只放两个位置）
- 相关代码：`src/gallery/core/external/qspace.py`、`src/gallery/ui/desktop.py`、
  `src/gallery/ui/main_window.py`、`src/gallery/ui/window/widgets/external_button.py`

## 背景

标题条上那个「用外部应用打开」的入口在全部照片 / 相册视图下给的是一列应用，目前只有「访达」：
点一下用访达打开**当前这一层文件夹**。用户用 QSpace 当文件管理器，要的是同一件事换个软件做。

QSpace（含 Pro）在 `Info.plist` 里注册了 `file` URL 方案，因此**递一条 `file://` 地址**就能让它
打开那个文件夹 —— 这也是它在 Raycast 里能被 quicklink 调起来的原因。

## 决策

1. **加在这一列里，不加进右键菜单。** 它做的是「打开**当前这一层**文件夹」（大图页那一支是把
   **正在看的那一张**选出来，见决策 8），与「访达」那一项是同一件事的两个软件，而这一列本来就是
   「同一个动作换个软件」的地方；右键菜单那几组回答的是「选中的这一格怎么处理」，作用对象不同。
2. **访达仍是第一个可用的那项**：下拉框左半那一下打开的默认项不变，QSpace 排在它后面。
3. **装没装按 bundle id 问 Launch Services**（`com.jinghaoshe.qspace.pro`，其次
   `com.jinghaoshe.qspace`），**没装就不摆这一项** —— 与「访达」同一套判据，灰着点不动的条目
   只会让人以为软件坏了。不按 `.app` 的名字认，理由与 ADR 0034 决策 2 同：名字随发行版与
   系统语言变。查询走 `NSWorkspace`（pyobjc 已经是依赖，见 ADR 0062），非 macOS 上取不到就是
   「没装」，静默。
4. **递的是 `file://` 地址，不是路径文字**：命令是 `open -a <应用包> <file://…>`。这是 QSpace
   自己公开声明的输入；路径文字是否被认没有保证。
5. **网格页那一支不模仿「在访达中显示」那条 `-R`**：`-R` 是访达自己的语义（在**上一级**里把
   东西选出来），而这一页要的是**打开进去** —— 与 `open_folder_in_finder` 同族，不是与
   `reveal_in_finder` 同族。QSpace 这边也没有 `-R` 可借：把它连着 `-a QSpace` 一起递过去，
   弹出来的仍然是访达（实测），所以两种效果在它这里靠**递文件还是递文件夹**区分。
6. **图标从应用包里读**（`CFBundleIconFile` → `Contents/Resources/…icns`），读不到才退回自画的
   轮廓：别人的商标不随包分发（ADR 0034 决策 6）。
7. **降级不是沉默**：`open` 起不来就改用访达做同一件事（打开文件夹 / 把文件选出来），横幅里
   说清实际换了哪一个 —— 用户以为东西开在 QSpace 里、看到的却是访达，比明说换过更难查。
8. **大图页给的是「正在看的那一张」**，与右键那条「在访达中显示」是同一个对象（ADR 0021 决策 3）：
   访达走既有的 `open -R`，QSpace 递那个**文件**的地址，由它打开所在的那一层并把这个文件选出来。
   两页要的本来就不是同一样东西 —— 网格页问「这一层里摆着什么」，大图页问「我看的这一张在磁盘上
   哪儿」；递文件夹过去只会落进里面，与要看的那一个文件对不上。判据只有一处
   （`MainWindow._external_targets`），两项共用，免得有一边忘了大图页那一条。

## 后果

- 全部照片 / 相册视图的下拉框里多一项「QSpace」，**只在装了它的机器上**；大图页上点它（以及点
  「访达」）露出**正在看的那一张**，与右键那条一致。
- 这一层**不碰用户的照片**：只读应用包的 `Info.plist`、只起一个 `open` 进程（约束 1 不涉及）。
- 首次点击可能弹「Gallery 想控制 …」之类的系统询问，属于「用户可修复」。
- 装没装**只在启动时问一次并缓存**（与 PWA 那条同一个做法）：会话中途去装了 QSpace，要重开
  Gallery 才看得到这一项。

## 被否决的方案

- **把 QSpace 设成 `file://` 的系统默认处理程序**：那是用户的系统设置，不该由我们替他们改
  —— ADR 0014 拒绝「打开方式…」是同一条理由。
- **用 QSpace 自己的 `qsapi://` 方案**：那是它内部回跳用的，参数要猜、换个版本就可能变；
  `file://` 是它写进 `Info.plist` 的公开接口。
- **按名字找应用包**（`/Applications/QSpace Pro.app`）：换发行版或换系统语言就落空，
  而且是**静默**落空（下拉框里少一项，没有别的症状）——「按名字认」在 ADR 0034 里已经吃过一次。
- **右键菜单里也加一条**：那里的两条命令作用在**选中的东西**上（照片是选出来、相册是打开进去），
  与「打开当前这一层」不是同一个对象；混在一张菜单里，用户说不清按下去开的是哪一个。
- **大图页上也打开那个文件夹**：用户在大图页看的就是一张照片，「它所在的目录」只有把这个文件
  一并选出来才答得清 —— 只打开目录等于把问题又丢回去（这一条与决策 8 是同一件事的两半）。
